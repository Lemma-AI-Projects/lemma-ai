## 2 · 它要解决什么问题

> **同类行为在不同目标下意义不同，而今天的系统只看行为本身。**

用户花了整个晚上把一道题的三种解法都试了一遍：

| 他的目标 | 同一件事的意义 |
|---|---|
| 两周后考试 | 值得提醒：探索的深度在挤占覆盖率 |
| 因为喜欢数学才来 | 这正是值得留住的过程 |
| 两者都有 | 要看**当前阶段**和**他明确说过的优先级** |

⇒ 启示必须**结合目标**，不能只按效率或正确率判断一个行为有没有价值。

**三个否定（这一版守住的边界）**
1. 不是一个**总在纠正用户**的系统。
2. 不把**观察到的习惯**上升成**永久的用户特征**。
3. 不把**效率 / 正确率**当成所有学习目标的优化标准。

## 3 · 明确不采用（写在这里，免得换名字回来）

| 不采用 | 为什么 |
|---|---|
| ❌ 四层认知结构（L1–L4）或任何**等价的固定层级** | 未经证明；而且"层次"会诱导我们把"缺数据的能力"包装成"高一层" |
| ❌ 用**概率 / 评分 / 掌握度百分比**表达确定性 | 仓库既有红线（`architecture/learner-state.md` §1「不外流任何数值」） |
| ❌ 把用户**永久划分为**"考试型 / 兴趣型"等人格 | 同一个人可以同时有多个目标，优先级还会变 |
| ❌ 把**单次行为**当成稳定特征 | §8 的验收项之一就是"不许这样" |
| ❌ 让模型**自行推断**掌握程度或"认知成熟度" | 状态层已经定过：状态只从证据算 |
| ❌ 为它新建 **Agent / Coordinator / 长期记忆系统** | §6 说清了它挂在哪儿 |

**"干预对象"这个轴保留**（§4.1），但它是**一个分类轴，不是层级** —— 它回答"这次谈的是哪一类事"，
不回答"谁比谁高"。现有那一版写的是：知识 / 推理过程 / 表达 / 策略 / 元认知 / 情绪与坚持。

## 4 · 决策模型（本轮的核心）

### 4.1 输入：只读五样，每一样都有表

| # | 读什么 | 从哪 | 今天的实际状态 |
|---|---|---|---|
| 1 | **当前目标** | `space_goals` 里 `status='active'` 的（**可能 0 条**） | 有表、有接口；目标不是必填 |
| 2 | **学习者状态** | 从证据**现算**（`ai/knowledge/state.py`），不落库 | 已具备 / 接下来可学 / 还没轮到 / 没测过 |
| 3 | **相关证据** | `knowledge_evidence`，**只取最近窗口内、且与候选知识点相关的行** | `verdict` · `tier(A/B/C)` · `independent` · `hint_used` · `created_at` · `item_id` |
| 4 | **认知历史（V1 的极小版）** | ① 同一知识点上的历史行 ② **用户此前对同类启示的否决** | ① 现成 ② 新表，只有一张 |
| 5 | **空间与当前情境** | 空间 id + 当前打开的页 / 资料 | 现成 |

⚠️ **不把全部用户数据无条件塞进模型。** 规则是：**先按知识点收窄，再按时间收窄，最后才交出去**。
今天的量级小，但接口形状必须一开始就是"收窄过的"。

⚠️ **认知历史里"尚无数据基础"的部分推迟**（用户如何调整策略、不同策略在各场景的结果、
用户对 Agent 判断的修正史…）—— 这些今天**没有表**，不在 V1，也不为它提前建库。

### 4.2 判断：三步，其中两步是纯函数

**S1 · 候选生成（纯函数、确定性、可单测）**
在收窄后的证据行上跑几条计数规则，产出候选。**V1 只有一条规则**：

> **`help_dependence`（帮助依赖）**
> 条件：同一个 `item_id` 上，`verdict='correct'` 且（`hint_used` **或** 非 `independent`）的**行数 ≥ 2**，
> 并且该知识点上**没有**一条"独立做对"的行（`correct and independent and not hint_used`）。

**为什么这一条**：
- 它只用**今天已经在库里的字段**（`hint_used` / `independent`）—— 不新增任何写入面；
- 它正落在现有状态层**刻意留空**的那个缝里：`state.py:282-291` 只在独立做对时采纳 ⇒
  **"带着帮助做对"在状态里是一条 INERT，用户从任何界面都看不到它**；
- 它**可被反驳**："我知道，那次我故意看的" —— 这正是我们要的（用户能修正）。

**S2 · 门槛（纯函数、可单测）**
候选必须同时满足，否则**降级为不生成**：
1. 证据行数 ≥ 2；
2. 这些行**跨至少 2 个不同日期**（防"一次会话里连点两次"被当成模式）；
3. 该知识点**不在**"用户已否决"的名单里（§4.4）。
⚠️ **缺目标不阻止生成**，只把确定性降到 `low` 且**换措辞**（不说"为了你的目标"）——
用户没设目标不该被当成"没资格得到启示"。

**S3 · 组织成话（唯一一次模型调用）**
把 S1 选出的**那几行** + 目标交给模型，让它写 ≤3 句。**硬约束**：
- **只许引用给它的行**，不许引入行里没有的因果、时间、次数；
- **不许出现数字、百分比、评分**；
- 输出里必须带 `evidenceRefs`，且**只能是输入 id 的子集**（探针逐条核）。

⇒ 一句话概括这个分工：**事实由规则选，话由模型说，模型不许引入新事实。**

### 4.3 输出契约

```
InsightDecision {
  kind: 'help_dependence' | 'none'
  itemId: uuid | null                 // 谈的是哪个知识点
  claim: string                       // ≤3 句，模型写的，只能引用给它的行
  evidenceRefs: uuid[]                // **必须非空**；界面上点得回原处
  certainty: 'low' | 'medium'         // 只有两档（不造概率）
  intervention: 'statement' | 'question'
  nextAction: string | null           // 只是建议；用户可以不做
  declinedBy: 'no_evidence' | 'not_repeated' | 'user_dismissed' | null   // kind='none' 时说明为什么
}
```

`declinedBy` 不是内部日志 —— **它是"不生成"要能说出的那句话**。

### 4.4 反馈

用户可以**接受 / 质疑 / 否决 / 不管**。V1 只记录**明确的动作**：

```
user_action: 'accepted' | 'questioned' | 'dismissed' | null   （null = 没有回应）
```
⚠️ **`null` 不等于接受，也不等于否决。** 只在用户真的点了 / 说了的时候才写。
`dismissed` 会进 S2 的第 3 条门槛 —— **这是"用户不必重复拒绝同一条建议"的唯一机制**。

### 4.5 「不生成」是一等结果

没有候选、或没过门槛、或被否决过 ⇒ `kind='none'`，并带上 `declinedBy`。
理由：一个"每次都要说点什么"的系统，最终会变成噪音，而且**没有数据支撑时它只能编**。

## 5 · 三个问题必须分开（别再混在一起）

| | 问题 | 本轮的处置 |
|---|---|---|
| **A · Insight Selection** | 什么值得揭示、要不要生成 | **本轮最重要** —— §4.2 的 S1 + S2。它**不依赖**界面，也不依赖表达方式 |
| **B · Insight Intervention** | 以什么方式介入 | 只定 **两个**：`statement`（直接说出观察）/ `question`（提一个开放问题）。**不是四级能力阶梯**，是两种表达 |
| **C · Insight Representation** | 界面上怎么摆 | **本轮只记约束**（见下），**不锁视觉形态** |

**C 的约束（只有这些）**
1. 一条启示必须能**展开看见它引用的那几行证据**（`evidenceRefs` 点得回原处 —— 与轨迹同一条纪律）。
2. 必须有**质疑/否决**的入口，并且这个动作**会写进反馈**。
3. **没有证据就不许摆一条** —— 空态是"这次没什么要说的"，不是一条占位卡。
4. ⚠️ **不许因为卡片需要一个结构，就反过来发明认知理论层级。** C 是布局问题，不是理论问题。

## 6 · 落在现有架构哪里

| 问题 | 答案 |
|---|---|
| 谁提供 Goal / Learner State / Evidence | **全是现成的**：`space_goals` · `ai/knowledge/state.py`（派生，不落库）· `knowledge_evidence` |
| 谁判断要不要生成 | **新增一个 service 的纯规则部分**（`services/insight_service.py`）—— **不是新 Agent、不是新 Coordinator** |
| 谁生成具体内容 | **同一个 AI runtime**（`init_ai_runtime()` 那一套），**不是新 Agent**。V1 先用**一次独立的、schema 约束的调用** —— 这样才能数清"有候选时才调、没候选一次都不调"，也才能逐条核 `evidenceRefs` 是不是输入的子集。要不要并进 Global Agent 的同一轮回答，见计划 **I7** |
| 反馈归属哪个上下文 | **空间**（`project_id`）—— 和 Goal 同一个理由：它讲的是"这个空间里发生的事" |
| 怎么保证不绕过 Evidence 与状态的更新规则 | Insight **只读**：它不写证据、不写状态、不写记忆。它唯一写的是**自己的反馈行** |
| 需要 Coordinator 参与吗 | **V1 不需要。** Coordinator 管的是"接下来做什么"；Insight 管的是"有什么值得你注意"，两者不重叠 |
| 能不能复用 Space Context / 历史 | 能 —— 就是 §4.1 的第 4、5 条 |

### 6.1 真正缺的最小接口（不是"重新设计 Learn Space"）
**只有一张表**（V1）：

```
space_insights
  id · project_id · user_id · item_id
  kind · claim · evidence_refs(jsonb) · certainty · intervention · next_action
  created_at
  user_action(null|accepted|questioned|dismissed) · user_action_at · user_note
```
⚠️ 它是一张**记录表，不是一个"学习者模型"** —— 它不承载掌握度，也不进 Space Memory。
（边界照旧：**记忆 = 这个空间过去发生了什么；状态 = 根据证据认为用户掌握了什么；这张表 = 系统说过什么、用户怎么回应的。**）

### 6.2 不改的东西（写在这里是纪律）
不改 `ai/knowledge/state.py` 的算法 · 不新增证据写入面 · 不把 Insight 写进 Space Memory ·
不把 Insight 塞进 Coordinator 的候选 · 不动 Focus / 轨迹 / 网格。

### 6.3 未定：界面上放哪儿
候选位置：① 工作台「学习简报」面板里（**和状态挨着**，最省事，但可能被当成状态的一部分）；
② 对话里由 Agent 自然说出（最自然，但**反馈没法定位到一句话**）；③ 独立一处（最清楚，但要新控件）。
⇒ **V1 先不选**：给一个免登录评审页看形状，真实位置等这一条真的有人用起来再定。

## 7 · V1 范围

### 做
1. `space_insights` 一张表（反馈用）。
2. `insight_service` 的**规则部分**：收窄输入 → S1 → S2 → 输出 `InsightDecision`（含 `declinedBy`）。
3. 一次模型调用（只在**有候选**时发生），schema 约束 + 探针核 `evidenceRefs` 子集关系。

**推迟不等于否定它的价值**，只是现在不为它提前建基础设施。

## 8 · 验收方式

| # | 判据 | 怎么算过 |
|---|---|---|
| 1 | 用的是**与当前目标相关**的真实证据 | 每条 `evidenceRefs` 都能在库里按 id 查到，且都属于同一个知识点 |
| 2 | 同一行为在**不同目标**下可能得到不同、且都合理的启示 | 同一批证据 + 两种目标，跑两次，话不一样（或确定性档不一样），两次都不越界 |
| 3 | **不把单次行为当稳定特征** | 只有一条证据时，`kind='none'`、`declinedBy='no_evidence'` |
| 4 | 证据不足时**降强度或不生成** | 同一天连点两条 ⇒ `declinedBy='not_repeated'`；缺目标 ⇒ `certainty='low'` |
| 5 | 用户质疑后系统**保留反馈** | 问题记录能查出 `user_action` 与 `user_note` |
| 6 | **允许用户不采纳** | `nextAction` 非空时，界面与措辞都不把它写成"必须" |
| 7 | 能证明 V1 有实际价值，**而不是生成更长的总结** | 用同一条证据跑一次"没有 Insight 的普通回答"，两次的**信息量差异能被指出来** |

### ⚠️ 这个门证明不了什么
- 1–7 全绿**证明不了"启示对用户有用"** —— 只证明"它说的是库里真有的事、且不会越界"。
- 证明不了**用户会不会觉得这是说教** —— 那是 §9 的第 1 条假设，只能用人试。
- 证明不了**它能改善学习结果**（今天没有能测这个的数据）。
- ⚠️ **不要用虚构的量化评分或进度指标假装验收通过。** 每条判据要么有命令输出，要么如实写"未验"。

## 9 · 待验证的假设（都还没有依据）

1. **用户在乎"靠提示做对"这件事吗？** 可能被读成"你在批评我偷看答案"。
2. **`statement` 与 `question` 哪个更不容易被当成纠正？** 今天只能猜。
3. **阈值（2 条 / 2 个日期）对不对？** 拍脑袋定的，需要用真实空间回看。
4. **反馈真的会改变下一次判断吗？** V1 只在"否决"这一条上用（不做学习/自适应）。
5. **`help_dependence` 之外的下一条规则是什么？** 候选是"同一知识点反复没做对"，但它和状态栏说的是同一件事 ——
   在第一条真的有人用起来之前**不加**。
