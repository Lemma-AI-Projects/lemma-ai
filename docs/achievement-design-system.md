## 1. 核心视觉方向

```
Retro-futurism × Pure Color × Geometric Shadow Lines
```

三条支柱各自负责一件事：

| 支柱 | 负责 | 具体表现 |
|---|---|---|
| **Retro-futurism** | 气质 | 1960–70 年代的"未来"想象：几何、克制、乐观、有秩序。不是赛博朋克 |
| **Pure Color** | 颜色 | 平涂、纯色、低饱和、无复杂渐变。颜色表达**类别**，不表达**稀有度** |
| **Geometric Shadow Lines** | 结构 | 细结构线 + 长投影。靠**线**建立体积，不靠光影与材质 |

必须同时保持的七条调性：**极简 · 克制 · 精密 · 收藏感 · 学术/科研感 · AI-native · 非传统游戏化**。

**参考方向**（只借气质，不借素材）：

- Monument Valley —— **只借空间构成与几何错觉**（等距空间、阶梯、错位通路）。
  ⚠️ **禁止**复制其角色、建筑造型、配色方案、品牌视觉。
- Scientific Illustration —— 借**理性气质**：结构清晰、标注克制、比例可信。
- Retro-futurist interface —— 借**界面秩序**：网格、模块、等宽字体元数据。
- Editorial / Archive design —— 借**档案感**：编号、日期、留白、目录式排版。

## 2. 设计哲学

### 2.1 它不是传统游戏 Badge

Lemma 的 Achievement **不是**：

金银铜奖牌 · 皇冠 · 奖杯 · 五角星 · RPG 徽章 · XP reward · 任务完成标记。

它是：

> **A visual record of human capability development.**
> 成就不是奖励，而是系统对"人的能力变化"留下的视觉证据。

### 2.2 与证据层红线的关系（硬约束，不可违反）

证据层已经定死了三件事（`docs/evidence/02-contract.md` §2、§4）：

1. **不外流任何数值** —— 没有百分比、没有掌握度分数、没有权重。
2. **状态是算出来的，不是存起来的。**
3. **模型产生证据，永远不产生状态。**

这三条直接约束视觉：

| 红线 | 对设计的约束 |
|---|---|
| 没有数值 | **禁止**进度百分比、XP 数字、等级数字、稀有度星级、进度条上的百分数 |
| 状态是派生的 | 成就卡上**不写**"你已掌握 73%"，只写**发生了什么** |
| 模型不产生状态 | 成就**不可以**由模型"颁发"；视觉上必须能指向具体证据条目 |

> 推论：**成就的可信度来自它引用的证据，不来自它的视觉重量。**
> 一个没有 evidence 列表的漂亮徽章，在这个系统里是**无效**的。

### 2.3 四条设计原则

```
Evidence → Signal → Capability → Identity
```

而不是：

```
Task → XP → Badge
```

1. **证据优先**：任何 Capability 级以上的图形，都必须能展开到它引用的 Trace。
2. **过程可见**：能力是"逐渐长出来"的，视觉上要能表达**未完成**（见 §8.3）。
3. **环境表达能力，人物不表达**：用建筑、路径、地形说话，不用表情、姿势、角色（§11）。
4. **安静**：不抢页面主任务的注意力。成就出现在它该出现的地方，不弹窗、不发光、不震动。

## 3. 视觉关键词

### 3.1 Positive Keywords（要的）

| 关键词 | 它意味着什么（可执行的解释） |
|---|---|
| **Retro-futurist** | 1960–70 年代的未来主义：几何、乐观、有秩序。参考的是"当年的未来"，不是"现在的科幻" |
| **Geometric** | 一切形状由圆、弧、正多边形、等距网格构成。没有手绘感、没有有机曲线 |
| **Monumental** | 图形像建筑：有基座、有体量、有台阶。哪怕只有 24px 也要有"立着"的感觉 |
| **Minimal** | 96px 下笔画 ≤ 6 条、视觉层 ≤ 4 层。删到不能再删为止 |
| **Scientific** | 像标本图、剖面图：结构清楚、比例可信、有标注位。不装饰 |
| **Archival** | 像档案卡：编号、日期、来源、目录式排版。是"记录"，不是"奖品" |
| **Cognitive** | 符号指向**认知动作**（提问、连接、迁移），不指向**成就本身**（赢、第一、最强） |
| **Precise** | 线宽、角度、间距都来自 token，不是目测。同一系统内不允许"差不多" |
| **Quiet** | 低对比、低饱和、大面积留白。放在页面上不喊 |
| **Collected** | 有收藏感：成套、可编号、可排列、可对比。单看一个成立，摆一排更好看 |
| **Human-centered** | 指向"这个人长出了什么能力"，不是"这个系统发了几颗星" |
| **Evidence-based** | 每个图形都能指回具体证据（§2.2） |

### 3.2 Negative Keywords（明确不要的）

| 不要 | 为什么 |
|---|---|
| **childish** | 学习者不是小孩；系统不哄人 |
| **gamified** | 一旦有分数/等级/连击，就退化成游戏 |
| **cartoonish** | 破坏精密感 |
| **fantasy RPG** | 魔法、纹章、宝石、符文，全部不属于认知能力 |
| **trophy-like** | 奖杯是"比赛赢了"，不是"能力长了" |
| **excessive gradients** | 大面积复杂渐变会带来材质感与廉价感；只允许 ≤12% 的单向色块 |
| **neon cyberpunk** | 霓虹与暗底发光属于"科技产品"，不属于"档案" |
| **glossy 3D** | 高光、反射、景深是渲染，不是几何 |
| **cute mascot** | 吉祥物会让人格化"能力"本身 |
| **reward-store aesthetic** | 兑换、商店、积分墙的视觉语言 |
| **excessive decoration** | 任何不能说明"这是什么能力"的装饰都要删 |

### 3.3 判定方法（三个问题，任一条不过就重做）

1. **去掉文字**，只看图形 —— 它像"一个认知动作的标本"，还是像"一个奖章"？
2. **和另一个成就并排** —— 它们是**同一套系统**里的两个，还是两个设计师各画一个？
3. **它指向证据吗** —— 能不能说出"它记录的是哪种行为"？

## 4. 色彩系统

### 4.1 原则

> **Pure / Flat / Restrained Color** —— 平涂、纯色、克制。
> 颜色表达 **能力类别**，不表达 **稀有度**。

三条硬规则：

1. **一图一色**：一个徽章只用**一个**类别色，其余全是中性色。
2. **禁止渐变**：唯一例外是"单向 8–12% 的色块填充"（不是渐变，是平涂的浅色面）。
3. **类别色 ≠ 稀有度**：Trace / Capability / Signature 三层的差别靠**结构与层数**（§8.2），不靠换色。
   同一个能力，永远是同一个颜色，无论它长到多大。

### 4.2 中性 / 结构色（骨架）

| Token | HEX | 用途 |
|---|---|---|
| `--ach-bg-parchment` | `#F4F1EA` | 米白底（页面/展柜底） |
| `--ach-bg-paper` | `#FBFAF7` | 卡片纸面 |
| `--ach-ink` | `#1C1B19` | 主墨色：描边、标题、主结构线 |
| `--ach-ink-muted` | `#55524C` | 次级文字、说明 |
| `--ach-ink-faint` | `#8E8A80` | 元数据、未激活文字 |
| `--ach-rule` | `#C9C4B8` | 结构灰：细分割线、栅格线、次要描边 |
| `--ach-rule-soft` | `#E2DED3` | 最浅的线（表格线、极弱分割） |

> 结构灰是这套系统的**主力**。一屏成就里，中性色应占视觉面积的 **85% 以上**。

### 4.3 能力类别色（8 类）

颜色是**能力的分类器**。八类之间保持可分辨的色相距离，但全部压在中低饱和区，避免彩虹感。

| 能力类别 | Token | HEX | 色相说明 | 一句话 |
|---|---|---|---|---|
| **Exploration** 探索 | `--ach-cap-exploration` | `#2F6F6B` | muted teal | 走出已知边界 |
| **Reasoning** 推理 | `--ach-cap-reasoning` | `#4C6694` | slate blue | 从前提走到结论 |
| **Creation** 创造 | `--ach-cap-creation` | `#A8492F` | terracotta | 造出原本没有的东西 |
| **Reflection** 反思 | `--ach-cap-reflection` | `#C08268` | dusty coral | 回头看自己的过程 |
| **Synthesis** 综合 | `--ach-cap-synthesis` | `#6E5A8C` | muted violet | 把多块拼成新结构 |
| **Transfer** 迁移 | `--ach-cap-transfer` | `#B98A2E` | warm ochre | 把会的东西搬到新情境 |
| **Persistence** 坚持 | `--ach-cap-persistence` | `#7A5C42` | umber | 在没有反馈时继续 |
| **Collaboration** 协作 | `--ach-cap-collaboration` | `#6B7F5E` | sage | 和别人一起长出来 |

每个类别色配三个派生值（**由实现计算，不手填**）：

| 派生 | 规则 | 用途 |
|---|---|---|
| `-wash` | 类别色 12% 混 `--ach-bg-paper` | 主形体的浅色面 |
| `-line` | 类别色本身 | 该能力的主结构线（当类别色用于描边时） |
| `-ink` | 类别色 85% 混 `--ach-ink` | 需要更强对比时的小面积文字/实心点 |

> **`Reasoning` 的 `#4C6694` 不是随手定的**：它就是 free-course 现有成就卡在用的蓝
> （`frontend/src/features/free-course/session/TeachingSessionView.tsx:551-564`，`#4c6694` / `#edf4ff` / `#ceddec`）。
> 沿用它是为了**零成本迁移**（§13），不是巧合。

### 4.4 状态色

| 状态 | 处理 | Token |
|---|---|---|
| **未获得 / 未开始** | 只保留结构灰描边，**完全去色** | `--ach-inactive` = `#B8B4AC` |
| **进行中** | 结构完整，类别色只用于 **1 条**结构线 | 类别色 `-line` |
| **已获得** | 结构完整 + 类别色 `-wash` 填充 | 类别色 |
| **不可用 / 停用** | `--ach-inactive` + 40% 不透明度 | — |

> **禁止**用灰度表达"等级高低"。灰 = 还没长出来，不是"低等级"。

### 4.5 与现有 token 的映射（必读，别另起一套）

现状（**事实**，`frontend/src/index.css`）：

- Tailwind v4，`@theme inline` 里是 shadcn 风格 token：`--background` / `--foreground` / `--primary`(220 13% 14%) / `--muted` / `--border` / `--radius: 0.875rem`。
- 颜色以 **HSL 变量**存放，`@theme inline` 里用 `hsl(var(--x))` 暴露成 `--color-x`。
- 已有 `.dark` 主题。

**落地方式（约定）**：新增一组 `--ach-*` 变量，**不覆盖**任何既有 token：

```css
/* frontend/src/index.css —— 追加，不改既有的 */
@theme inline {
  /* 成就系统：与主题无关的部分直接给 HEX（Tailwind v4 接受任意 CSS 颜色） */
  --color-ach-ink: #1C1B19;
  --color-ach-ink-muted: #55524C;
  --color-ach-ink-faint: #8E8A80;
  --color-ach-rule: #C9C4B8;
  --color-ach-rule-soft: #E2DED3;
  --color-ach-inactive: #B8B4AC;

  --color-ach-cap-exploration: #2F6F6B;
  --color-ach-cap-reasoning: #4C6694;
  --color-ach-cap-creation: #A8492F;
  --color-ach-cap-reflection: #C08268;
  --color-ach-cap-synthesis: #6E5A8C;
  --color-ach-cap-transfer: #B98A2E;
  --color-ach-cap-persistence: #7A5C42;
  --color-ach-cap-collaboration: #6B7F5E;

  /* 随主题变化的两枚底色 */
  --color-ach-bg-parchment: var(--ach-bg-parchment);
  --color-ach-bg-paper: var(--ach-bg-paper);
}

:root {
  --ach-bg-parchment: #F4F1EA;
  --ach-bg-paper: #FBFAF7;
}

.dark {
  /* 未定：见 §16-1。这里给的是"如果做深色"的默认方向，尚未拍板 */
  --ach-bg-parchment: #17161A;
  --ach-bg-paper: #1F1E23;
}
```

**只有两枚底色随主题走，八枚类别色与全部中性墨色不随主题变** —— 因为类别色是**语义**，
在深色下换一套颜色会让"同一个能力"看起来像两个能力。

### 4.6 使用规则

| 规则 | 值 |
|---|---|
| 单图类别色面积 | ≤ 全图 **20%** |
| 中性色面积 | ≥ **85%**（含留白） |
| 同屏类别色数量 | 一屏 ≤ **4 种**；超过就说明该分组了 |
| 纯黑 | **禁用** `#000000`，最重只用 `--ach-ink` |
| 纯白 | 只在 `--ach-bg-paper` 之上做高光细线时使用 |
| 渐变 | 仅允许单向 8–12% 平涂色面；**禁止**多色渐变、径向渐变、光晕 |

## 5. 几何语言

### 5.1 基本母题

Lemma Achievement 的几何由这些母题构成：

| 母题 | 用法 |
|---|---|
| **circular geometry** | 最外层容器、刻度、轨道。代表"被观测的范围" |
| **arch** | 外框的上半：像门、像桥洞、像展柜。代表"入口 / 可进入" |
| **hexagon** | 稳定结构、蜂巢式排列。代表"已成体系" |
| **shield-like frame** | 只用**轮廓**，不用纹章内容。代表"被保存下来的" |
| **isometric structures** | 主体量：塔、基座、台阶、平台。代表"建成的东西" |
| **stepped geometry** | 阶梯：进度、层级、爬升。代表"过程" |
| **bridges** | 连接两块分离的结构。代表"迁移 / 连接" |
| **pathways** | 折线路径 + 节点。代表"走过的路线" |
| **nodes** | 路径上的点。代表"一次行为 / 一条证据" |
| **concentric rings** | 同心环。代表"层级 / 深度 / 回看" |
| **symmetry / controlled asymmetry** | 主体对称，**一处**打破对称（缺角、开口、错位） |
| **long cast shadows** | 单向长投影（§6）。代表"光来自系统之外" |
| **thin outline** | 细描边是**唯一的轮廓手段**（§6） |

### 5.2 为什么是建筑 / 空间 / 路径 / 节点（隐喻映射）

这不是审美选择，是**语义选择**：能力和建筑共享同一组结构关系。

| 视觉隐喻 | 对应的学习概念 | 展开 |
|---|---|---|
| **地基 / 基座** | 先修知识 | 看不见但承重；地基越宽，上面能盖的越多 |
| **阶梯** | 学习进程 | 一次一级，不可跳；**未完成的台阶要画出来**（§8.3） |
| **塔 / 体量** | 已形成的能力 | 由多个证据逐层堆出来，不是一次点亮 |
| **桥** | Transfer | 把已有的东西搬到另一块地上 |
| **路径 + 节点** | Trace / Evidence | 每一个节点 = 一条可观察行为；路径 = 这些行为的连线 |
| **河 / 地形** | 知识领域 | 环境决定路径形状；不是背景装饰 |
| **同心环** | Reflection | 回看：从外圈回望内圈 |
| **拱门** | 入口 / 资格 | 穿过去才算进入某个领域 |

> 一句话：**徽章本身应该像一个"认知建筑"或"能力标本"，而不是一枚奖章。**

### 5.3 对称与受控不对称

- 主体结构**必须**有一条明确的对称轴（竖轴，或 30° 等距轴）。
- **每张图恰好一处**不对称 —— 缺角、开口、错位、未完成的台阶。
  这一处不对称就是"仍在生长"的信号。
- 禁止：完全对称（会像徽章/纹章）、多处不对称（会像涂鸦）。

### 5.4 几何禁止项

❌ 五角星 / 勋章绶带 / 皇冠 / 奖杯剪影
❌ 人物、脸、手、动物、吉祥物
❌ 手绘抖动线、有机曲线、水滴、火焰
❌ 超过 6 条笔画的主形（96px 下）
❌ 立体渲染（透视消失点、材质、高光）

## 6. Shadow Line System

这是本系统最重要的辨识特征：**用线建立体积，不用光影**。
规范单独成章，因为它是"看起来像不像 Lemma"的第一决定因素。

### 6.1 光源约定（全系统统一，永不翻转）

| 项 | 值 |
|---|---|
| 光源方向 | **左上**（方位角 315°） |
| 投影方向 | **右下** |
| 等距构造网格 | **30°**（标准等距） |
| 长投影角度 | **35°** |
| 为什么差 5° | 让投影读起来是"光"，而不是"几何本身"。两者完全同角会让画面糊成一片 |

### 6.2 参数表（design token，不是"建议值"）

以 **96px** 画布为基准（缩放规则见 §6.3）：

| Token | 值 @96 | 说明 |
|---|---|---|
| `--ach-stroke-primary` | **1.5px** | 主轮廓：外框、主体量、主路径 |
| `--ach-stroke-secondary` | **1px** | 次级细节：内部结构、刻度、地平线 |
| `--ach-stroke-hairline` | **0.75px** | 极弱线：栅格、标注引线（≥48px 才允许出现） |
| `--ach-highlight` | **1px** | 高光：只画在**左上受光边**，纯白 60% |
| `--ach-shadow-angle` | **35°** | 长投影方向 |
| `--ach-shadow-length` | **0.6–1.2 ×** 形体高度 | 按层级取值：Trace 0.6×，Capability 0.8×，Signature 1.2× |
| `--ach-shadow-opacity` | **8–14%** | 用 `--ach-ink` 的透明度，不另设灰色 |
| `--ach-shadow-thickness` | **= 形体线宽 × 1.5** | 投影是"挤出来的面"，不是模糊阴影 |
| `--ach-max-layers` | **4 + 1** | 4 个结构层 + 1 层投影 |

**投影的画法**：把主形体的轮廓沿 35° 平移，用 `--ach-shadow-opacity` 的 `--ach-ink` 填充，
**不加模糊**。它是平的、硬的、有边界的 —— 这就是"Geometric Shadow Lines"。

### 6.3 缩放规则（24 / 48 / 96）

笔画不随画布等比缩放，而是**分级降级**：

| 画布 | 主轮廓 | 次级 | 极弱线 | 投影 | 层数上限 | 笔画上限 |
|---|---|---|---|---|---|---|
| **24px** | 1px | **去掉** | 去掉 | **去掉** | 2 | 3 |
| **48px** | 1px | 1px | 去掉 | 0.8× @10%，2px | 3 | 4 |
| **96px** | 1.5px | 1px | 0.75px | 按层级（§6.2） | 4 | 6 |

> 24px 是**图标档**：只保留"能认出是哪个能力"的最小笔画。认不出的细节一律删，不是缩小。

### 6.4 重叠与密度

| 项 | 规则 |
|---|---|
| 描边重叠 | 允许 ≤ 1px 交叠；交叠处**后画的前景轮廓压在背景填充之上**，不合并 |
| 填充重叠 | 禁止；等距交叉处只允许"前景覆盖背景"的视觉关系 |
| 墨色覆盖率 | 目标 **≤ 22%** 的徽章包围盒面积（含投影，不含留白） |
| 负空间 | 是特征，不是浪费。留白率 < 60% 视为过密 |
| 视觉层数 | 硬上限 4 结构层 + 1 投影层；超了就说明该拆成两个成就 |

### 6.5 禁止项

❌ realistic 3D / 透视消失点
❌ photorealistic lighting / 环境光遮蔽
❌ glossy object rendering / 高光反射
❌ heavy drop shadow / 模糊投影 / 多层柔化阴影
❌ 投影角度在同一张图里变化
❌ 投影带渐变淡出（投影必须**边界清晰**）

## 7. Glyph System

### 7.1 为什么要系统化

> **glyph 必须具有系统性，而不是每个 badge 单独画一个漂亮图案。**

单个好看的图形是**插画**；能组成一套的图形才是**语言**。
判据：把任意两个 glyph 并排，它们必须像"同一套字体里的两个字"，而不是"两幅画"。

**不使用**常见 emoji 或游戏图标作为主要视觉语言（emoji 不能控制线宽、角度、层数，且平台间不一致）。

这里的核心符号叫 **Capability Glyph**：一个能力 = 一个 glyph，跨所有成就复用。

### 7.2 构造规则

| 规则 | 值 |
|---|---|
| 构造网格 | 96px 画布上的 **12 单位** 等距网格（8×8 格） |
| 安全边距 | 四周 **12px**（即 1 格），glyph 不越界 |
| 笔画上限 | 96px ≤ **6** 条 / 48px ≤ **4** 条 / 24px ≤ **3** 条 |
| 允许的角 | 只有 **30° / 60° / 90° / 45°**（45° 仅用于非等距的平面符号） |
| 允许的形 | 正圆、弧（≤180°）、正多边形、矩形、折线 |
| 对称 | 每图**恰好一处**受控不对称（§5.3） |
| 描边 | 全部来自 §6.2 的 stroke token |
| 命名 | `glyph-<capability>`，如 `glyph-synthesis` |

### 7.3 十二个 Capability Glyph

> 每个 glyph 的四栏是**实现约束**，不是描述：几何来源决定它怎么画，
> 简化规则决定它怎么删，三档决定它在什么尺寸下保留什么。

#### 1. Curiosity · 好奇
- **几何来源**：一个**未闭合的圆环**（缺口 45°，缺口朝右上）+ 一条从圆心向外伸出的短半径线。
- **认知含义**：已知的边界上开了一个口 —— 好奇心就是那个缺口。
- **简化**：先删半径线 → 再缩短弧（保留 ≥ 270°）→ 缺口必须保留。
- **24px**：只有开口圆环（缺口即识别点）。**48px**：加半径线。**96px**：加一段极弱的同心弧（表示"更大的未知"）。

#### 2. Exploration · 探索
- **几何来源**：一条 30° 折线路径 + 3 个节点，**最后一个节点被画布裁掉一半**。
- **认知含义**：路径没有终点；已经走出的部分可数，前面那截不可见。
- **简化**：先删中间节点 → 再减少一段折线 → 末端被裁的节点必须保留。
- **24px**：两段折线 + 2 个实心点。**48px**：三段 + 3 点。**96px**：加极弱地平线。

#### 3. Reasoning · 推理
- **几何来源**：两个三角形**顶点对顶点**（沙漏形），中轴一条竖线。
- **认知含义**：前提 → 结论的转换；中轴是那条不可跳过的推演线。
- **简化**：先删中轴 → 再弱化下三角 → 沙漏轮廓必须完整。
- **24px**：沙漏轮廓（2 条折线）。**48px**：加中轴。**96px**：上三角加一个节点（前提），下三角加一个节点（结论）。

#### 4. Memory · 记忆
- **几何来源**：三层**同心方框**（回字形），右下角一处缺口贯穿三层。
- **认知含义**：可回溯的层；缺口是"记不住的那一块"。
- **简化**：先删最内层 → 保留两层 + 缺口。
- **24px**：两层方框。**48px**：三层。**96px**：三层 + 沿缺口的一条极弱引线。

#### 5. Focus · 专注
- **几何来源**：一个正圆 + 圆心实心点 + 左右两条**向内的弧**（括号状，各 ≤90°）。
- **认知含义**：注意力向中心收束。
- **简化**：先删两条弧 → 保留圆 + 点。
- **24px**：圆 + 实心点。**48px**：加两条弧。**96px**：弧上各加一枚刻度点。

#### 6. Persistence · 坚持
- **几何来源**：**五级阶梯**，最高一级**缺一角**（未完成）。
- **认知含义**：仍在往上；最上面那级还没封顶。
- **简化**：先减到三级 → 再删最低级 → 缺角必须保留。
- **24px**：三级阶梯 + 缺角。**48px**：五级。**96px**：五级 + 沿台阶的长投影（0.8×）。

#### 7. Reflection · 反思
- **几何来源**：一个形状 + 它的**镜像**，中间一条竖轴；**镜像侧只描边不填充**。
- **认知含义**：回看自己的过程；镜像之所以是空心的，因为那是"看到的"不是"发生的"。
- **简化**：先删竖轴 → 再简化原形 → "一实一虚"的对比必须保留。
- **24px**：两个三角（一实一虚）。**48px**：加竖轴。**96px**：镜像侧加一条极弱水平引线。

#### 8. Synthesis · 综合
- **几何来源**：**圆 + 方**在中线处合并成一个**六边形**（合并处用一条极弱缝合线标出）。
- **认知含义**：两块不同的东西合成一个更大的新结构。
- **简化**：先删缝合线 → 保留六边形轮廓。
- **24px**：六边形（2 条折线）+ 一条中线。**48px**：加圆/方的残留弧。**96px**：加缝合线 + 两侧各一个节点。

#### 9. Transfer · 迁移
- **几何来源**：左侧一块平面 → **拱桥** → 右侧一块平面，桥面中部有第三个更小的平面。
- **认知含义**：把会的东西搬到另一块地上，并在途中被改写。
- **简化**：先删中间小平面 → 再降拱为直线 → "两块地 + 一条跨过去的线"必须保留。
- **24px**：两块矩形 + 一条斜连线。**48px**：斜线变拱。**96px**：加中间小平面 + 两端节点。

#### 10. Independence · 独立
- **几何来源**：**一根立柱** + 它自己的长投影，**没有基座、没有支撑**。
- **认知含义**：自持；不需要外部结构也能立住。
- **简化**：只删投影（柱体不可简化）。
- **24px**：单柱（一个窄矩形）。**48px**：加投影。**96px**：柱顶加一条 30° 斜面 + 投影 1.2×。

#### 11. Connection · 连接
- **几何来源**：两个节点之间一条**最短折线**，中间**绕开一个障碍矩形**。
- **认知含义**：连接不是直线 —— 真实的概念连接要绕过已知的障碍。
- **简化**：先删障碍 → 折线变直线（此时必须保留"绕行"的一次转折，否则退化成 Transfer）。
- **24px**：两点 + 两段折线。**48px**：加障碍矩形。**96px**：障碍加极弱阴影。

#### 12. Precision · 精确
- **几何来源**：十字准线 + 一个正圆，**交点处一个小方点**（不是圆点）。
- **认知含义**：把模糊的东西定到一个点上；方点表示"这是被定义的，不是被感觉的"。
- **简化**：先缩短准线（保留 ≥ 圆的半径）→ 圆与方点必须保留。
- **24px**：圆 + 方点。**48px**：加十字线。**96px**：准线两端加刻度。

### 7.4 缩放降级总则

1. **先删装饰性细节**（极弱线、刻度、引线）。
2. **再删次级结构**（弧、缝合线、中间平面）。
3. **最后保"识别点"** —— 每个 glyph 都有一个不可删的识别点（缺口 / 裁切 / 缺角 / 一实一虚 / 方点）。识别点没了，这个 glyph 就不成立。
4. **不为小尺寸重画**：降级是删，不是重新设计。

## 8. Achievement 三层结构

### 8.1 定义

| 层 | 中文 | 是什么 | 例子 | 数量级 |
|---|---|---|---|---|
| **1. Trace / Evidence** | 痕迹 | **可观察行为**（最底层，可无限多） | asked a meaningful question · corrected an error · connected concepts · independently solved a difficult problem | 每天都有 |
| **2. Capability** | 能力 | 系统**长期**从 evidence 中观察到的能力 | Synthesis · Reasoning · Transfer · Reflection | 十余个 |
| **3. Signature / Identity** | 签名 | 长期形成的**能力组合** | The Investigator · The Synthesist · The Builder · The Explorer | 少数几个 |

**归属关系**：多个 Trace → 支撑一个 Capability；多个 Capability → 组合成一个 Signature。

> ⚠️ **Trace 不是"小成就"。** 它是证据本身的可视化。
> Trace 不出现在成就墙上被"收藏"，它出现在能力卡**展开之后**。

### 8.2 视觉权重阶梯（**不是铜 → 银 → 金**）

三层的差别靠**结构深度**，不靠金属色、不靠稀有度：

| | **Trace** | **Capability** | **Signature** |
|---|---|---|---|
| 视觉隐喻 | 页边的一个记号 | 一座建筑 | 一片地形 |
| 结构层数 | 1（只有线） | 3（线 + 面 + 内构） | 4 + 投影 |
| 投影 | **无** | 0.8× @10% | 1.2× @12% |
| 外框 | **无** | 拱 / 盾形轮廓 | 拱 + 双层基座 |
| 类别色 | **不用**（纯结构灰） | 单色（§4.3） | 主色 + 最多 1 个副色的极弱面 |
| 尺寸 | 16–20px | 48 / 96px | 96px+ |
| 字形 | 单行，等宽 | 标题 + 说明 | 标题 + 说明 + 编号 + 组合说明 |
| 出现位置 | 能力卡展开后 | 成就墙 / 个人资料 | 个人资料顶部 |
| 能否丢失 | 可被修订（证据可被顶破） | 可退化 | 长期稳定 |

**关键规则**：

1. **禁止金属色**（金/银/铜）与"稀有度"用词。
2. **禁止星级、等级数字、百分比**（§2.2）。
3. 视觉权重的提升 = **盖了更多的东西**，而不是**换了更贵的材质**。
4. Signature 不是一个"更高级的 Capability"，而是**多个 Capability 的一次组合**：
   画面上必须能看到构成它的那几个能力结构（§8.3）。

### 8.3 组合规则（怎么画"还在长"和"已组合"）

| 情形 | 画法 |
|---|---|
| Capability 正在形成 | 结构完整，但**最高一级台阶缺角** / 路径最后一个节点为空心 |
| Capability 已形成 | 结构闭合，投影完整，类别色 wash 填满 |
| Signature | 一片地形：把 2–4 个 Capability 的建筑放在同一块地上，**共用一条路径**把它们串起来 |
| Signature 中某个 Capability 退化 | 对应建筑**退回线稿**（去色、去投影），其余保持 —— 不隐藏、不删除 |

> 最后一条很重要：**能力会退化，而档案要如实记录**。这正好呼应证据层的 `revise`（被反例顶破的边会退役，`docs/evidence/02-contract.md` §9）。

## 9. Badge Anatomy

### 9.1 层序（从外到内，从上到下）

```text
LEMMA                          ← ① 系统标记（永远是第一行，最小、最静）
↓
CAPABILITY / ACHIEVEMENT       ← ② 层级标签（说明这是哪一层，等宽、大写）
↓
PRIMARY GLYPH / VISUAL SCENE   ← ③ 主图形（唯一的视觉重心，占卡片面积 40–55%）
↓
TITLE                          ← ④ 标题（人话，如 "Midwest Explorer"）
↓
SHORT DESCRIPTION              ← ⑤ 一句话说明（记录了什么能力）
↓
DOMAIN                         ← ⑥ 领域（Geography & History）
↓
EVIDENCE                       ← ⑦ 证据（可展开；Capability 以上必须有）
↓
COMPLETED                      ← ⑧ 达成时间（ISO 日期，等宽）
```

### 9.2 信息层级（四档）

| 档 | 内容 | 视觉强度 | 规则 |
|---|---|---|---|
| **T1 重心** | 主图形 | 最强 | 唯一可以使用类别色 `-wash` 的地方 |
| **T2 名称** | TITLE | 次强 | 卡片里最大的文字，但**不超过**图形的视觉重量 |
| **T3 含义** | DESCRIPTION + DOMAIN | 中 | 灰色，可读但不抢 |
| **T4 出处** | LEMMA + 层级标签 + EVIDENCE + COMPLETED | 最弱 | 等宽、小号、大写/数字，像档案页脚 |

> **一句话判据**：把文字全部去掉，图形要仍然像 Lemma（§3.3 第一问）。

### 9.3 排版层级

| 元素 | 字号 @96 卡片 | 字重 | 字距 | 大小写 |
|---|---|---|---|---|
| LEMMA | 9px | 500 | `0.18em` | **全大写** |
| 层级标签 | 10px | 600 | `0.12em` | **全大写** |
| TITLE | 17px | 600 | `-0.01em` | 句首大写（专名照原样） |
| DESCRIPTION | 13px | 400 | `0` | 句子 |
| DOMAIN | 10px | 500 | `0.08em` | **全大写**（等宽） |
| EVIDENCE 条目 | 12px | 400 | `0` | 句子（等宽日期前缀） |
| COMPLETED | 10px | 500 | `0.06em` | 等宽数字 |

### 9.4 间距与栅格

- 基础栅格 **4px**，所有间距取 4 的倍数。
- 卡片内边距：`24px`（96 档）/ `16px`（48 档）。
- 图形与 TITLE 之间：`16px`；TITLE 与 DESCRIPTION：`8px`；说明块与元数据块之间：`20px`（且加一条 `--ach-rule-soft` 分割线）。
- 元数据行间距：`6px`，采用 **label 左对齐 + value 右对齐** 的两列结构。
- **文字一律左对齐**（除 Trace 档的纯符号）。图形水平居中。

### 9.5 元数据布局

```text
DOMAIN        GEOGRAPHY & HISTORY
EVIDENCE      4 条 · 展开
COMPLETED     2026-09-14
```

- 左列 label：等宽、10px、`--ach-ink-faint`、全大写、字距 `0.08em`。
- 右列 value：等宽、10px、`--ach-ink-muted`。
- EVIDENCE 展开后是 Trace 列表（§8.1），每条一行，带日期。

### 9.6 图标使用

| 规则 | 说明 |
|---|---|
| 徽章内**只有** Capability Glyph | 不混入 UI 图标 |
| UI 图标用现有 Lucide（项目既有） | 16px、`stroke-width 1.5`、`--ach-ink-muted` |
| **禁止 emoji** | 平台间不一致，且无法控制线宽与角度 |
| 禁止在插画内放图标 | 图标是界面语言，不是插画语言 |

### 9.7 边框 / 外框

| 层 | 外框 |
|---|---|
| Trace | **无框**。它只是一个记号 |
| Capability | 拱形或盾形轮廓，**单线**（`--ach-stroke-primary`），**不闭合底部**（底部留给投影） |
| Signature | 拱 + 双层基座；基座是结构，不是装饰 |

- **禁止**圆角矩形外框当"徽章框"（那是卡片，不是徽章）。
- 卡片圆角沿用现有 `--radius`（`0.875rem`）；**徽章图形本身圆角为 0**（几何不圆角化）。

### 9.8 尺寸档位

| 档 | 尺寸 | 用途 | 包含 |
|---|---|---|---|
| Icon | 24px | 列表、时间线、聊天内联 | 只有 glyph |
| Chip | 48px | 成就墙网格 | glyph + 外框 |
| Card | 96px+ | 详情、展开 | 完整八段结构 |

## 10. Typography

### 10.1 总原则：**不引入新字体**

现状（**事实**）：`frontend/src/index.css:142-148` 只定义了一套字体栈 ——
`Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`。
仓库里**没有**第二套字体，也**没有**等宽字体 token。

所以本规范的字体策略是 **映射，不是替换**：

| 用途 | 方向 | 落地（映射到现有系统） |
|---|---|---|
| **Display / TITLE** | editorial、克制 | **沿用 Inter**，`600`，`letter-spacing: -0.01em`。靠字重与字距做出编辑感，**不引入衬线体** |
| **Body / DESCRIPTION** | 安静、可读 | 沿用 Inter，`400`，`13–15px`，`line-height 1.5` |
| **Mono / Metadata** | technical、archival | **新增一个系统等宽栈**（不是新字体文件）：`ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas, "Liberation Mono", monospace` |

> 等宽栈只用于**元数据**（日期、编号、DOMAIN、层级标签、证据计数）。
> 它是"档案感"的主要来源，也是唯一新增的字体相关约定。

**明确不要**：gaming font · futuristic sci-fi font · 过度圆润的字体。

### 10.2 细则

| 项 | 规则 |
|---|---|
| **letter spacing** | 全大写标签 `0.08–0.18em`（随字号减小而增大）；标题 `-0.01em`；正文 `0` |
| **uppercase 使用** | **只**用于：`LEMMA` 字标、层级标签、DOMAIN。**TITLE 与 DESCRIPTION 永不全大写** |
| **title casing** | TITLE 用句首大写（`Midwest Explorer` 是专名，保持原样）。中文标题不加空格、不用书名号 |
| **numeric formatting** | 日期一律 `YYYY-MM-DD`（如 `2026-09-14`）；计数用半角逗号（`1,284`）；时长用 `3d 4h`；**禁止序数词**（"第 3 名""Level 5"） |
| **行高** | 标题 `1.3`；正文 `1.5`；元数据 `1.4` |
| **中文** | 中文与数字/西文之间由字体栈自然处理，**不手动插空格**；不使用斜体 |

## 11. Illustration Style

### 11.1 定位

**Isometric architectural world** —— 每个成就是一小片**等距建筑世界**。
它不是"贴图"，是**用环境表达能力**。

### 11.2 元素库

| 类别 | 元素 |
|---|---|
| 建筑 | monumental architecture · 塔 · 基座 · 平台 · 门廊 |
| 垂直 | stairs · 阶梯 · 竖井 · 柱列 |
| 连接 | bridges · 拱 · 坡道 · 索 |
| 地形 | pathways · rivers / landscapes · abstract geography · 等高线 |
| 工业/农业 | railroads · 仓塔 · 水渠 · 田垄 |
| 符号物 | symbolic objects（罗盘、标尺、透镜 —— 只作几何体，不作写实道具） |

### 11.3 设计原则

> **用环境和空间表达能力，而不是用人物表情表达成就。**

**例**：成就"完成美国中西部历史与地理"

- ❌ 不要画：一个拿着美国地图的人 · 一面国旗 · 一只鹰 · 真实地图轮廓 · 带渐变天空的风光照
- ✅ 应该画：Mississippi River（阶梯化河道）· Great Lakes（同心盆地）· prairie landscape（重复水平带）· railroads（细长线 + 节点）· industrial / agricultural geometry（仓塔、田垄）· monumental architecture · historical routes（路径 + 节点）

这些元素经过**高度几何化**之后，组成一个**独立世界**。

### 11.4 构图规则

| 项 | 规则 |
|---|---|
| 投影 | 统一 30° 等距构造 + 35° 长投影（§6.1） |
| 地平线 | 位于画面高度 **60%** 处；可省略，但不可上下浮动 |
| 结构数量 | **≤ 5 个**主要结构；超过就拆成两个成就 |
| 人物 | **零**。不出现人、脸、手、动物、吉祥物 |
| 文字 | 插画内**零文字**（标题/说明在卡片层，不在图里） |
| 配色 | 1 个类别色 + 3 个中性色，**没有第二个色相** |
| 背景 | 平涂 `--ach-bg-parchment`，**无渐变、无天空、无光晕** |
| 尺度感 | 用**重复单元的密度**表达尺度（田垄越密，平原越大），不用远近透视 |

## 12. Example Case：Midwest Explorer

一个完整的 Capability 级案例，把所有规则串起来。

### 12.1 卡片内容

```text
LEMMA
CAPABILITY
[ 主图形：等距世界 ]
Midwest Explorer
把一条河、一片湖和一条铁路读成同一段历史 —— 地理与历史不是两门课。
DOMAIN        GEOGRAPHY & HISTORY
EVIDENCE      4 条 · 展开
COMPLETED     2026-09-14
```

| 字段 | 值 |
|---|---|
| id | `midwest-explorer` |
| 层级 | **Capability**（不是 Signature） |
| 主能力 | **Exploration**（`--ach-cap-exploration` `#2F6F6B`） |
| 副能力 | **Synthesis**（只在证据说明里提及，**不额外上色**） |
| DOMAIN | `GEOGRAPHY & HISTORY` |

### 12.2 证据（Trace）列表 —— 展开后

```text
2026-08-21  asked a meaningful question    「五大湖为什么决定了芝加哥的位置？」
2026-08-28  connected concepts             把「运河—铁路—粮价」连成一条因果链
2026-09-05  corrected an error             修正了自己对「中西部=农业」的单一判断
2026-09-14  independently solved           自己推出河道走向与城市分布的关系
```

> 注意：**没有分数、没有百分比、没有"掌握度"**（§2.2）。
> 这四条就是这张卡片的全部说服力。

### 12.3 主图形：等距世界（结构分解）

画布 96×96，等距构造 30°，长投影 35°。

| # | 结构 | 几何 | 颜色 | 层 |
|---|---|---|---|---|
| 1 | **河道**（Mississippi） | 从左下折向右上的**三级阶梯状水渠**，每级 12 单位宽 | `--ach-cap-exploration` 12% wash | 背景层 |
| 2 | **湖盆**（Great Lakes） | 右上**三个同心盆地**，最内一层略下沉 | wash + `--ach-rule` 描边 | 背景层 |
| 3 | **草原**（prairie） | 底部 **5 条等距水平细线**，向上渐弱至消失 | `--ach-rule-soft` | 背景层 |
| 4 | **铁路** | 一条 **1px 长斜线**贯穿画面，线上 **2 个节点** | `--ach-ink`（1px） | 中景层 |
| 5 | **仓塔** | 右侧一根**竖向矩形**，顶部一个 **30° 斜面** | `--ach-ink` 描边 + 空白填充 | 前景层 |

- **层数**：3 背景 + 1 中景 + 1 前景 = **4 结构层**（未超上限），**投影**为第 5 层。
- **投影**：仓塔与河道的轮廓沿 **35°** 平移 **0.8×** 高度，`--ach-ink` @ **10%**，**无模糊**，边界清晰。
- **高光**：只在仓塔与湖盆的**左上受光边**各一条 1px 纯白 60%。
- **受控不对称**：**铁路末端超出画布被裁切** —— 这是全图唯一的不对称，表示"这条线还在往前修"。
- **墨色覆盖率**：约 **19%**（≤ 22% ✅）。
- **留白**：约 **68%**（≥ 60% ✅）。

### 12.4 三档降级

| 档 | 保留 | 删除 |
|---|---|---|
| **24px** | 三级阶梯河道 + 2 个节点 | 湖盆、草原、仓塔、投影、高光、全部次级线 |
| **48px** | 河道 + 湖盆 + 铁路（去掉草原与仓塔） | 草原、仓塔、高光、极弱线 |
| **96px** | 全部 | — |

### 12.5 这个案例的反例（明确不要）

❌ 一个拿着地图的人 · ❌ 美国国旗配色（红白蓝）· ❌ 写实的密西西比河轮廓
❌ 带渐变天空的风光照 · ❌ 一只鹰或任何动物 · ❌ 图里写 "Midwest" 字样
❌ 五角星"已解锁"角标 · ❌ 进度条显示 "80%" · ❌ 金色描边表示"高级"

### 12.6 自检（§3.3 三问）

1. 去掉文字后 —— 它像"一段被几何化的地理与历史"，不像奖章。✅
2. 与 `glyph-synthesis` 并排 —— 同一个 30° 网格、同一套线宽、同一个投影角。✅
3. 指向证据 —— 河道对应第 1、4 条证据；铁路对应第 2 条；被裁的末端对应第 3 条。✅

## 15. 验收清单

一个新成就（或一次改动）上线前，逐条打勾：

**语义**

- [ ] 它能指向具体 evidence 条目，且 evidence 里**没有**分数/百分比
- [ ] 它的层级（Trace / Capability / Signature）明确，且视觉权重与 §8.2 一致
- [ ] 它没有用稀有度语言（金/银/铜/星/等级/XP）

**图形**

- [ ] 全部形状落在 30°/60°/90°（或 45° 平面符号）上
- [ ] 96px 下笔画 ≤ 6，结构层 ≤ 4 + 1 投影
- [ ] 有且仅有**一处**受控不对称
- [ ] 投影角度 35°、无模糊、透明度在 8–14%
- [ ] 墨色覆盖率 ≤ 22%，留白 ≥ 60%

**颜色**

- [ ] 只用 1 个类别色，面积 ≤ 20%
- [ ] 无渐变（除单向 8–12% 平涂面）、无纯黑
- [ ] 类别色来自 §4.3 的八类，没有新造颜色

**字形**

- [ ] 用的是 Capability Glyph，不是一次性画的图案
- [ ] 24/48/96 三档都试过，24px 下识别点仍在
- [ ] 没有 emoji

**文字**

- [ ] 八段结构齐全（§9.1），元数据用等宽栈
- [ ] 全大写只出现在 LEMMA / 层级标签 / DOMAIN
- [ ] 日期格式 `YYYY-MM-DD`，无序数词

**整体**

- [ ] 去掉文字后仍然像 Lemma（§3.3 第一问）
- [ ] 与另一个成就并排，像同一套系统
- [ ] 在 `--ach-bg-parchment` 与 `--ach-bg-paper` 上都看过

## 16. 未定与缺口

以下**还没有答案**，不要当结论用：

1. **深色模式**：`index.css` 有 `.dark`，但成就系统在深色下的表现未定。
   §4.5 给的是一个**未拍板**的默认方向（只换两枚底色，类别色不动）。
   风险：`#F4F1EA` 系中性色在深色底上会失去"纸感"。
2. **Signature 是固定集合还是每人组合生成**：若为后者，需要一个"组合构图算法"（目前只有 §8.3 的原则，没有实现方案）。
3. **Trace 是否对用户可见**：本文假设"可见（展开后）"，但产品未确认。若不可见，§9.5 的 EVIDENCE 行需要重设计。
4. **哪些能力先做**：八类中先落哪几类未定（§13.3 建议先做 4 个 glyph，具体哪 4 个待定）。
5. **24px 真实可读性未验证**：§7.3 的三档规则是推演的，需要在真实字体渲染下逐个体检（尤其 Curiosity 的缺口、Precision 的方点）。
6. **等宽字体栈的最终取值**：§10.1 给的是系统栈；若设计要求跨平台一致，可能需要自托管字体（与"不引入新字体"的原则冲突，需拍板）。
7. **`AwardCard` 的最终处理**：§13.1 给了两个选项，未拍板。
8. **本文件是否入库**：`docs/` 在 `.gitignore` 里（`.gitignore:3` `/docs/`），本文件**默认不进仓库**。若要入库，需要加例外规则（见 §16-9）。
9. **与 Connect 原型的关系**：`connecting-page` 分支上的「成就」栏目前是 mock，等本规范定稿后需要回填（那是另一个分支，本文不追）。
