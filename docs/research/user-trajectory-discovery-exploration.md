# User Trajectory · Discovery 交互探索

> 分支 `user-trajectory` · 2026-11-03 · 状态：**未定（探索中，不选方案）** ·
> 上游：`design/user-trajectory-positioning.md` §2/§6 · `design/trajectory.md` §3 · `design/adaptive-insight.md` §4.5

**这份文档不选方案。** 它把三个候选概念摊开，比较它们各自解决什么问题、在哪里重叠、
今天能不能做出来，以及**该用哪种低保真去证伪它们**。

⚠️ 谁在这里读出"结论是 B"，谁就误读了。三个概念的主次、是否共存、具体交互，**全部未定**。

---

## 1 · 三个候选

### A · Discovery Cards

**定义**：把"一处值得注意的发现"做成一张可以直接进入的卡片。
一张卡 = 一句可以被证伪的话 + 一个可点开的依据 + 一个"去看看"的落点。

| | |
|---|---|
| 它解决什么 | **入口问题**：用户不知道从哪开始，卡片替他做了第一次筛选 |
| 它不解决什么 | 探索本身。卡片点进去之后往哪走，它不管 |
| 它的失败模式 | 变成 feed：一条接一条，用户滑完什么也没记住（`positioning.md` §6.5 四条就是防这个） |
| 今天能不能做 | **半能做**：卡片的容器可以做，但卡里的内容没有供给源（§5） |

### B · Living Map

**定义**：一个会随数据变化的关系空间——对象、事件、线索在其中占据稳定位置，连线表示它们的关系。

| | |
|---|---|
| 它解决什么 | **空间感**：一眼看见"我走了多远""哪几件事其实挨着" |
| 它不解决什么 | 从哪开始。一张完整的图对新人是最不友好的首屏 |
| 它的失败模式 | 变成装饰：好看、能拖、但没人从里面读出任何东西 |
| 今天能不能做 | **概念上已经在做**：`design/trajectory.md` §3 定的"纵向时间 × 横向 focus"就是一张 Living Map 的雏形 |

⚠️ **这是最重要的一条**：三个候选里，B 不是新东西，它**可能就是已经计划好的那张画布**。
如果成立，真正的问题不是"三选一"，而是"一张画布上挂几个叠加层"（§4）。

### C · Exploration Trails

**定义**：把一串相关对象、事件、材料、想法、证据连成一条可以顺着走的路径。

| | |
|---|---|
| 它解决什么 | **过程问题**：用户在探索中会走丢，路径把"我刚才怎么走到这儿的"留住 |
| 它不解决什么 | 首发发现。没有起点就没有路径 |
| 它的失败模式 | 变成面包屑的加长版（那就是导航，不是探索） |
| 今天能不能做 | **能做**：它是对既有关系的查询（`engages_with` / `derived_from` / `supports`），不需要新数据 |

## 2 · 对照

| 维度 | A Cards | B Map | C Trails |
|---|---|---|---|
| 回答的问题 | 从哪开始 | 整体长什么样 | 怎么走过来的 |
| 主要消费者 | 新用户 / 回访用户 | 已有一定数据量的用户 | 已经在探索中的用户 |
| 依赖的数据 | 一条可断言的发现 | 对象 + 关系 + 稳定位置 | 关系的可达性 |
| 对数据量的敏感度 | 低（1 条也能用） | **高**（少了就是空白画布） | 中 |
| 时间成本（实现） | 低 | **高** | 中 |
| 今天有没有供给 | ❌ 没有（§5.1） | ⚠️ 部分（画布已有） | ✅ 有（关系已在） |
| 失败后的样子 | 一个 feed | 一个装饰 | 一条面包屑 |

## 3 · 重叠分析

三处真实重叠，不是措辞问题：

**3.1 Cards ↔ Trails：在"串起来"上重叠。**
一张卡片如果要回答"为什么这两件事有关"，它必须给出路径——那就是 Trail 的最小形态。
⇒ **卡片可以是 Trail 的头**，而不是独立机制。这条如果成立，A 与 C 可以合并成一个东西的两种长度。

**3.2 Map ↔ Timeline：在"时间 × 结构"上重叠。**
`design/trajectory.md` §3 的布局（纵向时间、横向 focus）已经同时表达了"何时"与"哪条线"。
一张 Living Map 如果再加一条时间轴，它就是同一张图。
⇒ **B 与 Timeline 视角可能是同一个 surface 的两种相机位置**，不是两个产品。

**3.3 Cards ↔ Insights：在"一条判断"上重叠。**
`positioning.md` §7 说 Insight 应当能在探索过程中出现。一张 Discovery Card 如果内容就是一条 Insight，
那它只是 Insight 的另一种排版。
⇒ **Cards 不是新的信息类型，是 Insight / Connection / Possibility 的入口形态。**

### 小结

| 如果…… | 那么三个概念实际是 |
|---|---|
| 上述三条重叠都成立 | **一张画布（B）+ 两种叠加（A 作入口、C 作路径）**，而不是三个并列机制 |
| 只有 3.1 成立 | A 与 C 合一，B 独立 |
| 三条都不成立 | 三个确实独立，需要分别验证 |

⚠️ 本文倾向第一种，但**没有验证**。这正是 §6 第 5 个问题的来源。

## 4 · 三种组合（都不选）

| 组合 | 形态 | 代价 | 什么时候它是对的 |
|---|---|---|---|
| **K1 · 画布为主** | Map 是唯一 surface；Cards 是画布上的高亮标记；Trails 是选中后的路径高亮 | 新用户没有入口，首屏是空的 | 用户已经有 ≥3 个月数据 |
| **K2 · 卡片为主** | 首页 Cards；点开进 Map；路径在 Map 上高亮 | 卡片供给不足时首页空洞；且很容易变成 feed | 发现供给稳定之后 |
| **K3 · 路径为主** | 每次进入都从一条"你可能想看的路径"开始 | 需要先知道用户想看什么；冷启动最难 | 有明确任务时（如"回顾这个项目"） |

三者不互斥，但**同时全做一定失败**——不是因为工程量大，是因为用户分不清三个入口的区别。

## 5 · 今天能做出什么

### 5.1 供给：Discovery 的内容从哪来

| 内容类型 | 今天有没有 | 依据 |
|---|---|---|
| Unexpected Connection | **没有**。没有任何机制产出"两个对象之间的连接" | `adaptive-insight.md` §7 明确不做"全面的跨学科认知模式识别" |
| Emerging Pattern | **没有**。V1 只生成一种观察（help_dependence），且门槛是 ≥2 行跨 ≥2 日期 | 同上，§4.2 |
| Unexplored Possibility | **没有**。今天没有任何"提议"类对象 | — |

⇒ **这是整个 Discovery 方向最大的风险**：体验目标已确认，供给源未建。
一个没有供给的 Discovery Surface，最后一定会用模型现编——那正好违反 `adaptive-insight.md` §4.5。

**可以立刻做的替代供给（不生成，只查询）**：

| 类型 | 怎么来 | 是否算"发现" |
|---|---|---|
| 同一材料出现在两段经历里 | 查询 `material → experience` 的多重归属 | 算，弱 |
| 一条线索跨了 ≥2 个项目 | 查询 `focus → project` | 算，弱 |
| 某条解释被后续证据削弱 | 查询 `evidence_relations` 的负向边 | 算，强，但需要关系表 |
| 用户自己写过但从未再提的问题 | 查询"只有一条解释、无后续活动"的 topic | 算，强 |

⚠️ 这四条都是**结构查询**，不是模型生成。它们能把首页填起来，但填的是"连接"和"模式"的最浅一层。

## 6 · 低保真先验证的五个问题

每条都写了"什么算失败"。**失败不是坏事**——五个里能证伪三个，这一轮就值。

### V1 · 用户真的会在四个视角之间来回走吗？

- **怎么测**：给一份真实感的历史（`user-trajectory-lab` 的合成数据即可），只做一个可点击的视角切换，
  记录用户是否在 5 分钟内跨视角 ≥2 次，以及跨过去之后第一件事做什么。
- **失败长什么样**：所有被试都停在第一个视角；或跨过去后立刻退回。
- **失败意味着**：`positioning.md` §5 的共享上下文是一套为不存在的路径做的工程，应砍到最小。

### V2 · 首页能不能产生"我没注意到"的瞬间？

- **怎么测**：首页给 1–3 条发现，每条带依据。看完问一个问题：**"这里面有哪一条是你之前没意识到的？"**
  以及"你怎么知道它说的是真的？"
- **失败长什么样**：被试说"挺对的"但说不出具体哪条 → 那是配文，不是发现；
  或者被试问"这数据哪来的"却点不开 → P2 失效。
- **关键区分**：能复述出"连接的两端是什么"= 成功；只能复述语气 = 失败。

### V3 · 三种发现内容，用户分得清吗？

- **怎么测**：同一屏放一条 connection、一条 pattern、一条 possibility，让用户各用一句话说它是什么。
- **失败长什么样**：三条被描述成同一类（"系统觉得我……"）。
- **失败意味着**：`positioning.md` §6.3 的三种候选不该同时出现，应只留一种。

### V4 · 一张图在 8 条线索、密集时段下还成立吗？

- **怎么测**：用合成数据里最坏的一段（6-04 → 6-08，五天 30 条活动，单日峰值 8）。
  这是 `design/trajectory.md` §6.4 自己承认没验证过的数字。
- **失败长什么样**：用户说不出"这几天发生了什么"；或者必须先点开 5 次才能看懂。
- **失败意味着**：需要折叠规则或 focus 过滤开关，而这是布局的**前置条件**，不是优化项。

### V5 · 用户能不能说清"这条是怎么来的"？

- **怎么测**：给一条系统判断（最好用会错的那种：`ins-13`"你四个月零投入"），
  观察用户能否在 30 秒内找到反驳它的证据（`ev-17`）。
- **失败长什么样**：用户相信了它，或找不到反驳入口，或找到了但不知道那算不算反驳。
- **失败意味着**：Insights 视角的 §7.2 六项关联里，第 4 项（Contradicting Evidence）不是加分项，是必需项。

## 7 · 明确不做

| 不做 | 为什么 |
|---|---|
| 在这一轮选出最终方案 | 供给源都还没有，选出来的方案是在纸上选 |
| 为三个概念各做一版高保真 | 高保真会让讨论变成审美争论 |
| 用模型现编"发现"来填满首页 | 违反 `adaptive-insight.md` §4.5；且第一次被用户发现是编的，整个产品的可信度就没了 |
| 把 Living Map 做成通用图组件库 | 那是工程决策，不是产品决策 |
| 用合成数据得出"用户喜欢哪种" | 合成数据只能测**界面撑不撑得住**，不能测**人喜不喜欢** |
