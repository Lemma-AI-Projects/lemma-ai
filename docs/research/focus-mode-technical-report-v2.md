## 一页摘要（V2）

**一句话**：Focus Mode 的核心人机交互机制，是 **Agent 把学习操作留给用户、把自己限制在"准备与提议"上**；技术路线以 **Path C′（活动壳 + 块层 + 最小关系层）** 为工作假设——但 V2 把它从"推荐"降级为**待检验假设**，并给出了能推翻它的实验（E9）。

V2 相对 V1 的四个最重要变化：

1. **Agent Interaction 不再是"插入提示或卡片"**。V2 给出五级行动类别
   （Observe / Prepare / Propose / Act / Interrupt），并指出它们**成本与风险严重不对称**：
   准备（Prepare）近零成本且不可见，提议（Propose）占注意力但可逆，行动与打断（Act /
   Interrupt）改变用户的内容或注意力。由此得出的设计原则 V1 没有：**默认多备少动**——
   Agent 应持续准备（预取材料、预计算引用、预渲染可视化）但只在信号足够时呈现。
   当前系统只实现了 Propose 一种。
2. **干预强度的分界线不是"打扰多少"，而是"卸载了什么操作"**。V1 把 L1 当成零成本、
   把 L4 当成必然卸载风险——两者都被新证据修正。真正的问题（有实验支持）是：
   **被 Agent 接管的操作是不是学习者自己需要发展的能力**。这条判据同时修正了
   "Socratic 一定比直接解释好"（不，先验知识决定，expertise reversal）——
   这给 Method System 的动态切换找到了第一个有文献支撑的选择变量。
3. **Learning Move 必须是持续对象，不是一次性插入**。误读恢复（撤回）、重复抑制
   （记住被拒绝过什么）、用户直接操作 Agent 产物（不经过 Chat）——三个 V1 案例回答
   不了的问题，都需要 Move 有身份与生命周期。Case C 专门挑战了这一点，并推翻了
   V1 的状态分类（"Agent 建议 = 会话内存态"）。
4. **"Activity = Blocks 的组合"不完整**。V1 的 Hybrid 缺了第三层：**关系层**。
   对比两个材料是学习的核心动作（Case A 的全部要点），而单列块流**无法并置**。
   V2 的内容模型是块层 + 活动层 + **最小关系层（并置 + 引用）**，E1 的实验范围
   因此扩大（跨文档引用锚定）。

保留不变的：五类意图、L1–L4 干预分级（作为设计框架）、三段式锚定方案、
E1–E4 实验骨架、仓库事实层。**全部修订的逐条对照见 §1.3 与 §12。**

### 1.2 V1 的四个结构性问题

1. **过早收敛**。一页摘要就宣布 Hybrid 推荐，其后四章主要在为它找理由。
   四条路线从未被放在同一组场景下竞争——"Document-Centric 失败"这类断言
   没有经过判别场景检验。§7 重做。
2. **Agent Interaction 被简化为单循环**。"用户行为 → 判断 → 插入卡片 → 回应"
   能描述一个 Learning Move，描述不了连续学习：上下文如何在对象间移动、Agent 错了
   怎么恢复、被拒绝的建议如何影响后续行为、多日活动如何演化。§4/§5 重做。
3. **理论用单向**。V1 用理论支持设计（epistemic action 支持可操作性、AIRIS 支持
   可逆性），没有让理论产生反例。最明显的两处：把 L1 写成"近零成本"（注意捕获与
   监控成本被忽略）；把 Socratic 写成守则级正确（expertise reversal 直接反驳）。
   §3 逐条对抗。
4. **案例过于线性**。V1 三场景各自成立，但没有任何一个能挑战推荐架构——
   全部场景里 Agent 的判断都恰好正确、用户都恰好配合。§5 用四个案例修正，
   其中 Case C（误读）与 Case D（长程）被刻意设计为暴露架构缺口。

## 2 · 产品基础与证据等级

### 2.1 已批准的产品决策（不变）

与 V1 §2.1 完全一致：Learn Space 是 Learning Environment；Canvas 空间化、元素类不冻结；
双击文件进 Focus、上下文连续；**L1–L4 已批准**（作为设计框架而非状态机）；粒度正交；
Agent Initiative 三分（打断非默认）；Every Method is a Plugin（方向已定、架构未冻结）。

### 2.2 工程事实（2026-10-27 时点）

在 V1 §2.2/§2.3 基础上，V2 增补/强调四条：

1. **Agent 只有 Propose 一种行动形态**。九个工具里没有"预取""预备"类；AgentMoveCard
   是一次性 DOM 元素，无身份、无生命周期、无跨表面存在。
2. **证据层无"假设"位**。`knowledge_evidence` 只记已发生判定；Agent 对用户的假设
   （"他可能在对比两文"）无处落盘——被拒绝的建议同样无处记录（重复抑制因此不可能）。
3. **无"读到哪/正在做什么"信号**（VISION_GAPS C2）。一切主动性研究的前置缺口，
   两次评审均确认。
4. **块内容与交互对象分属两个渲染体系**（MaterialView vs BlockEditor 按文件类型分流），
   且 Agent 插入物走活动层、用户内容走块层——两层的对象没有共同的引用机制。

## 3 · 认知科学与 HCI 证据（批判性修订）

> 本章的写法与 V1 相反：每节先陈述一个 V1 依赖的结论，再找它的**边界与反例**，
> 最后给出修订后的表述。新引用全部经检索核实，来源等级在 §13 标注。

### 3.1 直接操作的边界：epistemic action 有时窄化思考

V1 引用 Kirsh & Maglio（1994）：操作外部表征本身就是思考，Agent 替用户做掉
epistemic action = 抹掉学习机会。这个方向成立，但它只讲了一半。

**反例（教学窄化效应）**[RF]：Bonawitz et al.（2011）的玩具实验——成人示范一种玩法后，
幼儿探索玩具其它功能的时间与发现数**显著下降**；对照组（无示范）探索得更多。
直接教学（包括 Agent 演示"正确用法"）是**高效的，同时也是窄化的**。

**修订后的表述**[EJ]：操作促进思考的前提是**用户保有操作的选择权**。因此：

- Agent 呈现的可视化/示例**不应自带"正确用法"的完整演示**——Proposal B 的滑杆
  实验符合（它给的是一个可操作的参数空间，不是一个演示动画）；
- Agent 主动演示"你应该这样操作"属于窄化行为，默认降档为 Prepare（备好但不出示）；
- 但对**目标明确的例行操作**，代劳无害（见 §3.3 的外围/核心区分）——
  "Agent 永不代劳"和"Agent 总是代劳"同样是错的。

### 3.2 引导与发现：干预强度没有无条件答案

V1 的隐含立场是"引导式 > 直接给答案"（Khanmigo 式守则）。学习科学对这个问题的
证据远比这精细：

- **纯发现 < 直接教学**（对新手）[RF]：Mayer（2004）综述三个十年的纯发现教学实验，
  提出"三振出局"；Kirschner, Sweller & Clark（2006）从工作记忆限制给出机制解释——
  无引导搜索填满工作记忆，新手没有剩余资源用于学习。
- **增强发现 > 直接教学** [RF]：Alfieri et al.（2011）元分析 164 项研究——
  **无辅助发现显著差于直接教学**（580 个比较，d = −0.38）；而**带脚手架、反馈、
  工作样例或自我解释引发的发现，显著优于直接教学**（360 个比较，d = 0.30）。
- **先验知识反转** [RF]：Kalyuga 的 expertise reversal effect——对同一内容，
  对新手有益的引导，对高先验知识者变成冗余负担；最优引导量随先验知识**递减**。

**对 Focus Mode 的含义**（这是给 Method System 的第一个硬结论）：

1. "Agent 不给答案"不是普适定律——它对**低先验知识的学习者**成立；
   对已具备大量先验知识的学习者，同样的问题追问是冗余打扰。
2. Agent 干预的最优强度是**先验知识的函数**——这意味着 Socratic 与
   direct_explanation 之间的选择**不应由用户偏好或固定规则决定，而应由可观察的
   先验知识证据决定**。这直接支撑 Method 重构计划（`method-system-refactor-v0.md`）
   里 SWITCH 缺口的必要性，并给出了第一个可操作的选择变量。
3. 设计推论 [DH]：L2/L3 的干预在**无先验知识证据**时默认取"指向动作"形态
   （"把方向转到 0° 看看"），在有证据显示用户已熟练时默认静默。

### 3.3 认知卸载：何时有害取决于卸载了什么

V1 引用 AIRIS（Kuhn et al. 2026）作出二分：外围外包无害、认知卸载有害。
2024–2026 的实验文献把这个二分精确化了：

- **卸载水平实验** [RF]：130 人四组对照（无 AI / 高卸载=直接给答案 / 中=分析支持 /
  低=评价反馈）。**高卸载组当场表现最好、决策最快，但技能增长比对照组低 7.1%**；
  中低卸载组技能增长 +5.5%。机制分析：损害来自**元认知误校准**（自评能力与真实
  能力的差扩大），不是行为参与减少。存在一个**卸载阈值**：低于它 AI 助手同时提升
  表现与技能。
- **无限制使用的保留测试** [RF]：Bastani et al.（2024，NBER，土耳其高中数学现场实验）——
  无限制 GPT 组练习成绩 +48%，**撤掉 AI 后比从未用过的对照组差 17%**；结构化 tutor 组
  撤除后无此惩罚。同类：ChatGPT 学习 RCT（n=120）45 天后知识保留 57.5% vs 对照 68.5%
  （d = 0.68）；AI 撤除后坚持性下降、跳题率上升（COLM 2026，n=1222 三组实验）。
- **AIRIS 的位置**：作为理论框架与上述实验兼容；但"有害"的机制现在有了更细的
  指认——元认知误校准（觉得自己会了）。

**修订后的表述**[EJ]：**判据不是"Agent 做了多少"，而是"被接管的操作是不是学习者
自己需要发展的能力"**。把公式计算交给 Agent，对要学代数的人是替代练习；
对已经会代数、在分析财务报表的人是外围外包。同一条 L3 建议卡，既可能是
"增强"也可能是"侵蚀"，取决于内容与学习者状态。

**对 Focus Mode 的含义**：

1. L1–L4 重新解释（修正 V1 的两处过度确定，见 §3.4）；
2. **Agent 建议卡的内容类型要区分"产物型"（Agent 给出答案/解释/摘要）与
   "操作型"（Agent 给出可由用户执行的动作或工具）**——产物型在用户尚未尝试时
   呈现 = 高卸载风险；操作型（L2 指向动作、L3 可操作模拟器）保持练习在用户手里。
   Proposal B 的 EigenExplorer 是操作型的正确实例。
3. **Method 的 directive 里应声明本方法的目标能力**（这个方法在练什么），
   干预器据此判断"这个 move 是否在替代目标能力"——这是 Method→Move 指导的
   第一个实质性用途。

### 3.4 对 L1 与 L4 的两处修正

**L1 不是零成本**。V1 写"近零"。修正：持续可见的信息有两类持续成本——
(a) 自下而上的注意捕获（显著度越高越不可避免）；(b) **监控邀请**：一个持续存在的
Agent 输出会持续邀请用户评估"要不要看它"，这是元认知负荷——而 §3.3 刚说明
元认知误校准是卸载损害的机制。因此 [DH]：L1 区应有**更新节流**（不是有新发现就刷新）
与**衰减**（陈旧条目自动下沉），把"持续在场"变成"有变化才在"。

**L4 不必然意味着卸载风险**。V1 写"几乎必然"。修正：L4 卸载的是**活动组织**——
而活动组织是不是"待发展能力"，取决于学习阶段：目标已经明确、在执行成熟路径的
学习者，被建议换活动可能正中需求；在探索期的学习者，被重定向会窄化探索
（§3.1 的 Bonawitz 效应在活动层面的对应）。[EJ] L4 的确认协议应携带**理由与依据**，
让用户判断"它是不是在替我做我不该外包的决定"——确认的对象是理由，不是按钮。

### 3.5 打断时机：subgoal 边界假设

V1 只说了"打断有 resumption lag"。对干预时机更有用的是**何时打断伤害最小**：
Adamczyk & Bailey（2004）发现打断出现在**子目标边界**时，负面影响显著小于任务
执行中途。Mark et al.（2008）确认被打断工作有真实的恢复成本与压力成本。

**修订后的表述**[DH]：Agent 的干预时机应瞄准**子目标边界**——刚完成一段推导、
刚读完一节、刚关闭一个模拟器、刚保存一次笔记。这把"何时介入"从不可计算（Horvitz
的期望效用在学习场景算不出来，V1 已承认）变成**可检测的事件模式**：边界 = 任务段
的终结事件。这也解释了为什么"用户连续阅读时绝不打断"（无边界可借）与
"读完一节提示下一步"（有边界）是同一条原则的两面。**前提缺口不变**：检测边界
需要"读到哪"信号（C2 埋点）。

### 3.6 Chat 的真实边界：问题在 agency，不在语言

V1 依据 Keyhole Effect 把 Chat 判为不合格的工作面。修订：

- Keyhole 的**量化部分仍是模型估算**（作者自己标注），只可取方向；
- **"Learning by Chatting?"**（2026，纵向日记式现场实验）给出了更准的机制：
  ChatGPT 组学习结果更差，归因是**探索知识空间缩小、信息选择代理权丧失、
  控制感下降**——并记录了用户对**主动跟进提示的明确反感**（"follow-up prompts
  were interruptive"）。这与本项目 U4（主动性≠频繁发言）和 D4 独立汇合。
- 但 Chat 对 **Ask/Redirect 意图**仍是对的画面：提出新问题、改变方向、表达不满——
  这些本来就是对话性动作。

**修订后的表述**[EJ]：Chat 的问题不是"聊天形式有害学习"，而是**当它成为唯一表面时，
用户失去了对信息选择与操作的控制点**。Focus Mode 的正确姿态不变（Chat 是五意图之一），
但理由修正为 agency 而非效率——这也意味着：**只要工作区对象可以被直接操作与回应
（不经 Chat），Chat 频率自然下降；靠限制 Chat 来保 agency 是治标**。

### 3.7 理论 → 设计约束（修订版映射）

| 理论/证据 | V1 推论 | V2 修订后的约束 |
|---|---|---|
| Epistemic action + Bonawitz 窄化 | Agent 内容必须可操作 | 可操作 + **不自带完整演示**；代劳按外围/核心区分 |
| Alfieri/KSC/Mayer 引导-发现谱系 | "不给答案"守则 | 最优强度是**先验知识的函数**；Method 切换有了第一个变量 |
| Offloading 阈值实验 | L4 几乎必然卸载 | 判据 = 被卸载的操作是否待发展能力；**产物型/操作型**区分 |
| 元认知误校准机制 | L1 零成本 | L1 需**更新节流与衰减**；持续在场本身是监控负担 |
| Adamczyk & Bailey 边界效应 | L2 就近呈现 | 时机瞄准**子目标边界**；无边界时不打断 |
| Learning by Chatting（agency） | Chat 不合格 | Chat 限为 Ask/Redirect；**让对象可操作**才是 agency 的来源 |

## 4 · Agent–Human–Workspace 交互（本轮核心）

> V1 的交互模型是单循环："观察 → 判断 → 插入 → 回应"。本章把它替换为一个能承载
> 连续、非线性学习的模型，分四个问题：共享注意、主动性的行动类别、Move 的本体地位、
> 连续性。每一节标注"仓库现状"，防止把设计当实现。

### 4.1 Shared Attention：从事件流到可行动情境

**Agent 如何知道用户正在做什么？** 四层信息模型（V1 §5.4 提出，这里给出机制化）：

| 层 | 内容 | 机制 | 仓库现状 |
|---|---|---|---|
| Observed Events | 选中、滚动、滑杆、停顿、保存、笔迹 | 埋点事件流，**不解释** | **无**（C2 缺口） |
| Contextual Interpretation | "他在对比两文""他卡在第二步" | Agent 会话内的当下解读，随轮次可弃 | prompt 措辞约束已有 |
| Hypotheses | 带时效的判断："重复回看 §2 = 可能在做系统性探索" | **需要可写的假设存储**：内容、依据事件、置信、状态（活跃/被拒/证实） | **无处存放**（D5） |
| Supported Conclusions | 有充分依据的判定 | 唯一可进 Learner State | 已有（判定类） |

三个机制问题（V1 未回答，本轮给出立场）：

1. **"当前注意对象"如何判定**：多对象并存时（两个材料 + 一个模拟器 + 一张便签），
   候选信号有显式选择（最新点击/编辑）、时间衰减、任务边界事件。[DH] 判定取
   **显式选择 > 新鲜度 > 任务结构**的优先序，且**任何基于此的干预必须携带它依据的
   对象**（溯源徽章），让用户能发现"它以为我在看 B"并当场纠正——判定错误是常态，
   可纠正性是设计要求，不是异常处理。
2. **对象间切换时上下文如何保持**：[DH] 上下文不挂在"当前页面"上，而挂在
   **活动上下文对象**（activity context）上——一组可引用的元素（材料块、便签、
   打开的模拟器、活跃假设）。切换对象改变的是 context 的**焦点成员**，不是清空重建。
   这解释了 Path B 的实测（跨路由状态保留）为什么感觉"自然"：状态本来就属于活动，
   不属于视图。仓库现状：sessionStorage 原型是它的最低配版本。
3. **什么值得记录**：记录本身有成本（存储、噪声、以及 §3.4 的监控邀请——用户知道
   被记录时的行为改变）。[EJ] 记录取**事件计数与段落级锚**（"回了三次 §2"），
   不取细粒度行为流回放；不记录不解释的原始键鼠流。**宁可少记，不可误读**——
   误读的代价在 Case C 展开。

### 4.2 Agent Initiative：五级行动类别与成本不对称

产品上下文的三分（判断/行动/打断）是设计语言。落到系统行为上，区分五类：

| 类别 | 定义 | 用户可见性 | 成本 | 风险 | 仓库对应物 |
|---|---|---|---|---|---|
| **Observe** | 记录事件、维护上下文与假设 | 无 | 低 | 误读（记录了错的） | **缺**（C2） |
| **Prepare** | 预取材料、预计算引用、预渲染可视化、排好对比——**不呈现** | 无 | 低 | 无（浪费算力） | **缺（本轮新识别的最大缺口）** |
| **Propose** | 呈现建议卡/提示，等用户处理 | 中（占注意力，可忽略） | 中 | 打扰、误读呈现 | AgentMoveCard / L2 |
| **Act** | 直接改变内容（写块、改设置） | 高 | 高 | 覆盖用户内容 | 工具存在但 prompt 约束走 propose |
| **Interrupt** | 转移注意力（L4、横幅、声音） | 最高 | 最高 | 打断成本、窄化 | **无（正确）** |

**核心设计原则（V2 新增）：成本不对称 ⇒ 默认多备少动。** Prepare 的成本与风险
近零（用户根本看不见），Propose 起才消耗注意力，Act/Interrupt 起才可能造成损害。
因此：

- Agent 应该**持续 Observe + Prepare**（预取 B 中论证相似段、预生成一个反例、
  把对比布局排好），**只在信号足够时才 Propose**，Act 走建议-采纳通道，Interrupt
  保留给显式批准的场景；
- 这直接回应了 V1 没有回答的问题——"主动性不等于频繁发言"的具体机制不是
  克制发言，而是**把主动性放在用户看不见的层**。用户感觉到的是"每次需要时
  它都已经准备好了"，而不是"它总在说话"。
- 判断"干预是否有帮助"只有四条信号 [EJ]：采纳/展开（正）、显式拒绝或撤回（负）、
  忽略后该对象被继续正常使用（弱负）、忽略后行为改变（中性）。**没有第五条
  "推断它有帮助"**。

**忽略与恢复（回答 V1 未答的生命周期问题）**：

- 被忽略的 Propose：进入**冷却期**（同类 move 在同一对象上暂停一段时间），
  换**变体**再试一次（同一假设、不同形态：L2 文字 → L3 卡片），仍被忽略则假设
  降级为静默；**连续两次被忽略 = 假设可能错了**，回 Observe。
- 判断错误的恢复（Case C 的机制基础）：Propose 可撤回（撤回 = 对象标记 superseded，
  不删除——历史可见）；被拒绝的**假设**进入拒绝记录，抑制同源建议；撤回与拒绝
  都要**可解释**（用户能看到"它为什么不再提这个了"）。
- 避免反复打断的机制不是道德约束，是**计数与冷却**：每会话 Interrupt 预算、
  每对象 Propose 上限。数值待 E3′ 实验，本轮不定（拒绝拍脑袋上限）。

交互（Case A 引用、Case C 撤回、Case D 多日回访）都需要 Move 有身份。

从生命周期推出的四条机制结论：

1. **用户直接操作 Agent 对象是非 Chat 回应通道**：移动建议卡（挪到自己排的对比位）、
   在卡片上批注、把卡片引用进自己的笔记、点掉——这些动作都应更新生命周期状态。
   **用户不应需要"用回复 Agent 的方式"来回应 Agent 的产物。**（这也是 §3.6 agency
   结论的落地：让对象可操作，Chat 自然退到 Ask/Redirect。）
2. **重复抑制**：dismissed + 理由 → 同假设冷却；adopted → 同源 move 不再提
   （已解决）；superseded → 撤回理由可见。
3. **Move 的关系性**：Move 可以引用其它对象（材料块、另一个 Move、画布元素）——
   Case A 的"连接两文"就是 reference move 创建了一条**持续存在的引用边**，
   用户关掉 Focus 后边还在画布上。这使 Move 不是"插入一段 UI"，而是**在工作区
   对象图上加节点/边**。
4. **Method→Move 弱耦合**：Method 在 directive 里声明目标能力（§3.3）与
   偏好 move 形态（数据），**翻译成具体卡片/提示的是工作区**（GenUI Static 模式，
   V1 §4.3 的结论维持）——Method 不 import 任何 UI 组件，UI 不知道 Method 存在。

**仓库现状**[EF]：以上全部为设计。AgentMoveCard 无状态机、无身份、无持久化；
C5 线（Agent–Workspace 边界）的实验范围因此扩大（§9.2）。

### 4.4 Interaction Continuity：连续交互需要的状态支持

V1 §6.4 的四类状态（持久内容 / 界面态 / Agent 建议 / 证据）保留，两处修订：

1. **"Agent 建议 = 会话内存态"被 Case C 推翻**。最小持久性要求 [DH]：
   (a) **拒绝记录**（哪些假设被拒过、何时、什么对象上）必须跨会话——否则每次打开
   都重新犯错；(b) 建议对象本身可以会话内存在，但其**生命周期事件**
   （engaged/dismissed/…）必须进事件流，成为证据层输入。
2. **跨表面身份**：Case C 里用户在画布上遇到聚焦模式里收到的建议（卡片跟着活动走），
   需要建议对象有跨视图身份。这与 Path B 已验证的"状态属于活动不属于视图"是
   同一条原则，应用到 Agent 产物上。

**方向改变的语义** [EJ]：用户改变学习方向时——跟随，不劝回（U 系列不变）；
系统侧动作 = 活跃假设批量降级（旧方向的假设不再触发建议）+ 方法可能 SWITCH
（证据足够时，Method 计划 Stage 3）+ 已有引用边**保留不删**（改方向不等于
否定之前的连接）。

**撤销语义**（细化 V1 §6.3）：Agent 的已采纳内容 = 一个独立事务，整体可撤销，
用户后续编辑不被回滚（E2 验证）；Agent 的建议卡 = 可撤回、可整体消失；
**Agent 永不修改用户正在编辑的块**（V1 约束不变，追加：也不修改用户尚未保存的
note——Agent 写入只走追加式通道）。

## 5 · 连续交互案例（四案例）

> 案例设计原则：不再要求每个案例里 Agent 都判断正确。Case C 刻意让 Agent 犯错，
> Case D 刻意让状态跨天失效——**每个案例都要暴露一类架构缺口**；Case C 直接挑战
> V1 的推荐架构。案例是推演产物 [DH]，技术展开处的"需要的能力"是本轮的真实产出。

### Case A · Laptop / Research：对抗性材料与被拒绝的解释

**叙事。** 小周在读两份结论相反的实证研究（A 认为效应存在，B 认为是伪相关），
学习目标写在空间目标里："判断 B 的反驳是否成立"。他从 A 的 §3.2 选了核心回归表
所在段，写了边注："样本量只有 41？"；又打开 B，读它的 §4（方法学批评），在
"控制变量不足"下面划了线；然后回到 A，把两处选区先后点亮，来回切换了四次。

**Agent 看见什么**：四次对象切换（A↔B）、两个选区、一条边注、目标文本。
**Agent 不知道什么**：他切换是在对比，还是在 B 里找一个他记得的句子；他对 B 的
态度（被说服 / 正在反驳）；他划线是同意还是标记靶子。

候选 move 与取舍：

| 候选 | 级别 | 取舍 |
|---|---|---|
| 在 B 的"控制变量不足"旁提示"检查 A 是否回应了这一点" | L2 | **被选**——指向动作，不代作判断；依据可展开（两次选区 + 来回切换） |
| 直接生成"两文分歧的三点对比表" | L3 产物型 | **不选**——§3.3 判据：对比正是他在练的能力，Agent 产表 = 替代练习 |
| 提示"A §3.2 的样本量问题 B §4.2 有回应"（预计算好的引用边） | L1 | 备用——若他 10 分钟内没自己建立连接，从 Prepare 升 Propose |

他接受了 L2（照着去查了 A 的 §5），但**拒绝了 Agent 后来补的一句解释**
（"这说明 B 的批评可能不成立"——这是产物型判断，他想要的正是自己下这个结论）。
他点掉了它。

**技术展开**：这个案例需要四样东西，其中三样仓库没有——(1) **跨材料语义检索**
（找到"A 回应 B"需要内容理解，`read_page` 只能读本页）；(2) **Prepare 层**（引用边
预先算好，10 分钟后才升级呈现——多备少动）；(3) **拒绝记录**（"产物型解释"这个
形态被拒过，下次同源 move 换操作型或闭嘴）；(4) 引用边是**持续对象**（他后来把
这条边拖进了自己的比较笔记）。工作区缺口：单列块流无法并置 A/B 两段——
对比动作要求关系层（§6.2）。

### Case B · Tablet / Mathematics：手写、模拟器与"不说话的回应"

**叙事。** 小陈在平板上做特征向量。她拖滑杆试了几个方向，停在一个非特征方向上，
然后在手写区写"为什么 Av 不沿着 v？"——写完继续拖滑杆，没发任何消息。Agent
不知道她写了什么（不做 OCR 前提，笔迹是不可读的 ink）。她把滑杆拖到 0°，看到
对齐高亮，又拖到 315°，再次对齐；然后关掉模拟器，在手写区补了几行推导。

**Agent 的选择**：她在操作时**绝不出现**（无边界可借，§3.5）；她**关闭模拟器的
瞬间**是子目标边界——L2 出现："两个方向让 |Av| 变了 2 倍和 1 倍。你的推导里
λ 出现在哪一步？"——指向动作 + 连到她的手写（她刚写的推导），不替她推导。
她没理这个提示，直接继续写。**冷却**：同类 L2 在此对象上暂停；她写完保存，
假设（"在找特征值与推导的连接"）保持活跃但不升级——她在正常推进，
不需要帮助的证据与需要帮助的证据一样多。

**技术展开**：需要 (1) ink 块（原样保存，不 OCR）——V1 已列；(2) **边界检测**
（模拟器关闭 = 子目标边界事件——这是 C2 埋点的第一批事件之一）；(3) **冷却与
变体逻辑**（§4.2）；(4) L2 文案**连接到她的对象**（她的手写块、她刚操作的滑杆
状态）而不是通用文案——这要求 Propose 的 payload 携带锚，即三段锚定（§6.4）。
失败模式：如果边界检测不到（她不关模拟器、直接切走），Agent 的正确行为是
**什么都不发生**——这个案例的"成功版本"里 Agent 只说了一次话，或者零次。

1. **锚的寿命**：D4 材料改版后，D1 建立的引用边指向旧 quote——三段锚的复核
   发现 quote 不匹配，**显式降级**（边还在，从句级降为块级并标注"内容已变"）。
   锚定不是 E1 的"20 次随机编辑"问题，是**多日、多版本、跨对象**问题（E1 范围修正，
   §9.2）。
2. **建议的寿命**：D1 的对比卡在 D5 还该出现吗？adopted 状态 + 引用它的用户笔记

   adopted 是终态，这意味着卡片必须知道"我已被采纳、并入了哪里"。
3. **上下文的寿命**：D5 他先看总结块——activity context 的焦点成员与 D1 不同，

4. **证据的积累方式**：五天里系统攒下的是**事件与假设的生命史**（哪个假设被

   真实素材，不是 Learner State 的**。

> V1 的顺序是"内容模型 → 场景验证"；V2 反过来：先从四个案例导出工作区必须
> 支持的需求，再检验候选模型。

### 6.1 四案例导出的工作区需求

|---|---|---|---|

### 6.2 "Activity = Blocks 的组合"假设的正面检验

V1 的公式是：活动 = 块的有序组合 + 交互对象。拿 R1–R10 检验：

- **能承载**：R1（块锚）、R8（ink 作为块类型）、B/C 案例的单活动流、
  "读文档"型活动（全块序列）——这条假设对**线性活动**成立。
- **不能承载**：**R2/R3/R10 全部失败**。对比、引用、互引是**对象间关系**，
  而"块的有序组合"是单列序列——序列没有并排，没有边，没有跨文档成员。
  Case A 的核心动作（把 A 的一段和 B 的一段放在一起看）在这个模型里
  **没有自然的表示**。
- **结论**[DH]：内容模型需要第三层——**关系层**，且最小实现不是图数据库式的
  通用图，而是两种边：**并置**（两个对象同屏对比的组合）与**引用**
  （带锚的指向）。画布原型已经隐式验证了并置（元素可拖到一起）——
  关系层把它从"视觉摆放"升级为"有语义的对象"。

这不是推翻 Hybrid，是给它补上 V1 缺的第三块；但**关系层落在块层还是画布层**
是 E9 要回答的问题之一（§7.5）。

### 6.3 锚定与编辑冲突（收窄后的声明）

V1 的锚定方案（三段锚）与编辑冲突表维持不变，两处收窄/扩大：

- **收窄**：E1 原来隐含"锚定问题由引入编辑器框架解决"——V2 明确这是待检假设；
  Path D（现状增强）也可以通过"只对 Agent 引用做快照锚"缓解，成本不同，
  E9 要比。
- **扩大**：锚的测试范围从单文档多轮编辑，扩到**跨文档引用边 + 材料改版 +
  多日存续**（Case D）。quote 失配的降级路径（句级→块级→"内容已变"标注）
  是 R1 的一部分，不只是错误处理。

## 7 · 竞争性架构分析（重做）

### 7.1 四条候选路线

- **Path A · Document-Centric**：富文本文档树为主载体，活动与 Agent 内容嵌入文档。
- **Path B · Activity-Centric（纯）**：活动/对象构成工作区，无持久文档层（Proposal B 原型即形态）。
- **Path C · Hybrid**：块层（内容）+ 活动层（组织）+ 关系层（最小：并置+引用）——V2 修订版（C′）。
- **Path D · 现状增强**：不引编辑器框架，继续自研 BlockEditor + 整页保存，
  加埋点、建议卡持久化、快照式锚。

### 7.2 三个判别场景（不打星）

同一组需求放到每条路线下问三个问题：**天然支持？需要自定义（多大）？不支持？**

**S1 · 长文精读 + 段落边注 + Agent 就近提示**（Case B 的桌面版）
**S2 · 双材料对抗性对比 + 引用边**（Case A）
**S3 · 混合活动：文档 + 模拟器 + 手写 + 建议卡，跨天回访**（Case B+D 合并）

| 需求 | Path A 文档中心 | Path B 纯活动 | Path C′ Hybrid | Path D 现状增强 |
|---|---|---|---|---|
| S1 精读+边注+就近提示 | **天然**（文档是本命） | 自定义（要造文档块流） | 天然（块层） | 天然（已有 BlockEditor） |
| S2 并置对比 | 自定义（分屏/引用扩展，PM 生态有先例） | **天然**（对象自由摆放，已验） | 天然（关系层并置） | **弱**（单列流 + 画布两套，无语义引用边） |
| S2 跨材料引用边 | 自定义（文档内锚成熟，跨文档需自建） | 天然（对象即锚） | 天然（块锚+边） | **弱**（快照锚可做但脆） |
| S3 块内精细编辑 | 天然 | 自定义（编辑器终要引入） | 天然（Tiptap 待检） | 天然（已有，但整页保存约束在） |
| S3 跨天状态 | 天然（文档即持久） | 自定义（活动持久化未做） | 自定义（活动+块两层持久化） | 天然 |
| Agent 锚定建议 | 自定义（文档内锚 + 外部对象割裂） | 天然（对象即锚） | 天然（块锚统一） | 弱（快照锚） |
| **Agent 交互约束** | Agent 产物是文档附件——**降级回"文档里的卡片"，与已批准的活动为中心相悖** | Agent 产物=一等对象，但长文阅读无家 | 两层统一锚，产物可进块也可留活动层 | 产物走活动层，与块层割裂（R10 失败） |
| **工程成本** | 高（重写 BlockEditor，两条仓库线废弃一条） | 低（已有原型） | 中（编辑器 PoC + 关系层） | **最低**，但锚定/undo 地基持续自研 |

### 7.3 判读

1. **V1 的"Path A 失败"说得太满**：S1 上它是最强的，PM 的 step/mapping 模型
   对锚定甚至比 Tiptap 更成熟。A 的真问题是**与已批准决策的方向冲突**
   （Agent 产物降级为附件）与工程成本（重写），不是能力不可能。
2. **Path B 的真缺口被 V1 低估**：不是"长文档"三个字，而是 S3 的**跨天持久化
   与块内精细编辑**两件具体的事。
3. **Path D 升格为严肃候选**：它是唯一"零迁移"路线，且 R1/R5/R6/R7 全部
   可以独立于内容模型先做。它输在 R2/R10（引用边与互引）——而这两条恰恰是
   Case A/C/D 的核心。**如果 E9 显示引用边可以在活动层独立实现，D 的地位会上升。**
4. **Path C′ 的领先理由变了**：V1 说"它两个都能接"；V2 的理由是**关系层
   （引用边+并置）需要一个统一的锚定体系**，而只有 C′ 把用户内容与 Agent 产物
   放进同一套块锚。这是可被 E9 检验的具体主张，不是偏好。

### 7.4 一个更简单的模型？[ORQ]

brief 问"是否存在更简单、低耦合的模型"。V2 的回答：**存在一个更简单的分解**——
把"内容模型"与"关系模型"解耦：内容层可以是 Path D 的现状（不迁移编辑器），
关系层独立为引用边服务（画布层已有摆放，补语义）。这个"**D + 关系边**"混合
是真实的竞争者：它推迟编辑器迁移，先验证交互价值。代价是锚定两套（快照+未来块锚），
且若 E1 证明必须换保存协议，迁移债仍在。**E9 的判别结果将直接决定 C′ 还是 D+边。**

## 8 · 工程约束（2026-10-27 时点）

V1 §2.3 的五条约束全部维持，V2 追加三条（均已在 §4 案例中暴露）：

1. **建议对象无身份**（AgentMoveCard = 一次性 DOM）——R4 的全部成本；
2. **两层对象无共同引用机制**（用户块 vs Agent 活动层产物）——R10 失败的根源；
3. **Propose 是唯一实现的行动类别**——Prepare/Act-通道/Interrupt 的缺位是
   交互模型（§4.2）与实现之间的最大落差。

## 9 · 实验研究计划（重组）

### 9.1 证据四分（先于实验清单）

每条实验只声称验证四类证据之一，**不得越界引用**：
Technical Feasibility（工程可行）/ Usability（可用）/ Interaction Quality（交互质量）/
Learning Effectiveness（学习效果）。**本轮计划中没有任何实验能验证第四类**——
那需要长期对照研究（§3.3 的文献已给出该类实验的形态，但不是本阶段能做的）。
一次原型走查的成功 ≠ 交互质量已验，更 ≠ 学习效果已验。

### 9.2 工程正确性实验

- **E1 · 锚定存续性（范围修正）**：原"10 块文档 5 锚 20 次编辑"；扩为
  **三组**：(a) 单文档 20 次随机编辑（原样）；(b) **跨文档引用边**在两端各自编辑后
  的存续；(c) **材料改版**（模拟 Case D：整节重写）后 quote 失配降级路径的正确性。
  成功/失败标准沿用（≥90% 精确恢复或显式降级）。Informs：编辑器选型 + 保存协议。
- **E2 · 双方编辑冲突与撤销**（不变，挂 C1）。
- **E5 · 结构化内容与交互对象共存**（新增，从 brief 提取）：同一活动流内
  块内容 + 可交互对象（模拟器/建议卡）+ 引用边共存渲染；50 块文档 + 5 个交互对象
  的帧率与内存基线。Informs：性能风险（V1 零证据）+ R3 并置的渲染可行性。

### 9.3 交互机制实验（新增类别）

- **E3′ · 干预可理解性与生命周期**（取代 V1 E3 的走查）：L1–L4 同屏 +
  **忽略后的行为**（冷却/变体/静默是否被理解为"它学会了"）+ L1 更新节流的
  可感知性。走查 n≥5，think-aloud。Informs：§4.2 的参数与 L2/L3 默认权重。
- **E7 · 纠正流**（Case C 的可测版）：注入一次故意误读，观察用户是否
  (a) 发现溯源徽章指出错误对象，(b) 能用对象操作（拖开/批注/点掉）完成纠正，
  (c) 系统撤回与抑制是否被注意到。Informs：R4/R5 的最低可用形态。
- **E8 · Move 对象可操作性**：用户能否移动/引用/批注 Agent 卡片而不破坏
  其生命周期状态。Informs：R4/R10 的组件设计。

### 9.4 竞争性实验（本轮最重要的新增）

- **E9 · 三路线判别**：S2（双材料对比+引用边）同一任务在三个 mock 上走查——
  Path D+边（现状+独立引用边）、Path C′（块层 PoC）、Path A mock（文档+分屏）。
  相同功能需求清单（R1–R3/R10 子集），评价维度：完成时间、**建立引用边的操作步数**、
  并排阅读的主观负担、以及**实现各自的代码量**（工程成本是评价维度，不是 tie-breaker
  的遮羞布——brief 明确：表现接近时按成本与复杂度取舍）。Informs：§10 的推荐。

### 9.5 优先级与 C1–C5 挂接（更新）

| 顺序 | 实验 | 挂接线 | 理由 |
|---|---|---|---|
| 1（并行 a） | **E1** | C1 | 一切块路线的前提；范围已扩 |
| 1（并行 b） | **E9** | C1/C5 | 竞争判别是本轮批评的核心；mock 成本低，不必等 E1 |
| 3 | E2 + E5 | C1 | 依赖 E1 的 PoC |
| 4 | E3′ + E7 + E8 | C2/C5 | 需要一个可用的路线 mock |
| — | E4（平板消歧） | C3 | R5 阶段前置，维持 |

C 线状态更新：C1 增加关系层与跨文档锚定；C2 增加边界事件依赖（C2 埋点）；
C5 吸收 Move 生命周期与身份问题；C4（公式）不变。

## 10 · 暂定技术建议（working hypothesis）

### 10.1 推荐

**Path C′（块层 + 活动层 + 最小关系层）仍是最优假设**，但 V2 的推荐强度是
条件化的：**前提是 E9 证明引用边在块层体系内比在现状+独立边服务更省、且 E1
证明块锚可存续**。两步走不变（活动壳已验证 → 块层实验）。

### 10.2 会推翻本推荐的结果

- E1(b)/(c) 失败且 Path D 的快照锚达标 ⇒ 转 **Path D + 关系边**（§7.4）；
- E9 显示引用边操作步数/成本在 D+边上不劣于 C′ ⇒ 推迟编辑器迁移，先 D+边；
- E5 显示两层渲染性能不可接受 ⇒ 关系层并入画布层（活动壳扩展），块层缩回
  纯文档范围。

### 10.3 最小 Agent–Workspace 边界（四原语 → 五原语）

V1 四原语修订：`read / propose / annotate / reference` 保留，**新增
`track(move)`**——读取与更新 Move 的生命周期状态（含拒绝记录）。理由（Case C）：
没有 track，Agent 无法知道自己的建议的命运，重复抑制与撤回恢复都不可能。
仍然没有 DSL、Runtime、Scheduler；五原语的全部实现面在 workspace 一侧。
