## 5. 明确没有的东西（会被误读成"这个人的情况"）

| 缺什么 | 为什么没做 | 对 UI 探索的影响 |
|---|---|---|
| **第二个用户** | 任务只要一个人 | 多用户对比、同龄人参照、社区这类界面无法测 |
| **声音 / 视频材料** | 这个人不录也不看自己的录像 | 音频时间轴、转写检索一类界面无法测 |
| **连续的测评序列** | 只有 3 次零散小测 | "能力随时间上升"的曲线在数据上不成立，任何画曲线的原型都是编的 |
| **一次活动产多条证据** | 编起来容易失真，故意没编 | 证据 → 活动的反查只能是一对一；如果 UI 需要"这条证据还支持了什么"，测不出来 |
| **他人的协作痕迹** | 他从没和别人一起做东西（除了答辩） | 协作、评论、共编类界面无法测 |
| **生活事件** | 只有 35 天空档，没有原因记录 | "为什么停了"这个问题，数据里没有答案。UI 若强行解释就是编造 |
| **花费 / 时间投入** | 没有任何时长记录 | "投入了多少小时"这类统计无法测；也正好对应产品今天没有的字段 |
| **证书 / 学分 / 成绩** | 他没有考任何证 | 凭证类展示无法测 |
| **失败的应用 / 被拒** | 邮件都没发出去 | "挫折"只能从活动和反思里读，没有外部事件支撑 |
| **同一个人的多平台身份** | 只有一个 GitHub 账号 | 身份归并（`trajectory-inputs.md` §2.F）无法测 |
| **长期目标的量化指标** | 目标全是定性的 | 进度条这类组件在这份数据上无处可挂——这是刻意的 |

## 6. 三个最容易踩的统计陷阱

1. **"读完 12 件"不等于学到 12 件。** `mat-08` 读完了，零笔记零证据；`mat-23` 看了 9 讲，只留一页笔记。
   任何"完成率"都会把这两件事算成一样。
2. **"104 条活动"里有 77 条系统看不见。** 直接用全量做时间轴，密度感是对的；
   用可见量做，3 月会突然变稀——两个都对，但**不能混在同一个视图里不标注**。
3. **兴趣条数不等于兴趣强度。** `int-08`（机器人）跨度 157 天只有 5 条活动，全是被要求的；
   `int-04`（因果）只 54 天但有 6 条活动加一条迁移证据。按"持续时长"排序会把假的排前面。
