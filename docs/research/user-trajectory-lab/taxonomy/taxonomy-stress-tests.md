# 分类压力测试 · 16 个边界案例

> 每条都要回答五个问题：主类是什么 / 还有哪些有效角色 / 需要哪些关系 / 必须保留什么信息 / 能不能不新增类目地表示。
> 判断标准不是"能不能放进某个格子"，而是**放进去之后有没有丢东西**。
> 记录 id 全部指向 `synthetic-trajectory-data.json` v0.2。

---

## A · 对象边界

### ST-01 · 一本书，同时属于一门课、一个问题、和六个月后的重读

**场景**：`mat-19`（Bengio《The Consciousness Prior》）3-17 在 `lx-01`（认知科学导论）里读到，3-19 写下一条 pending 判断，
9-25 又自己重读一遍并做了笔记（`act-091`）。

- **主类**：I-a Material。作者不是他，书本身不因他而存在。
- **其他有效角色**：`lx-01` 的读物 · `lx-04` 的读物 · `foc-02` 的起点材料 · `ev-15` 的落点 · `int-02` 的早期信号
- **需要的关系**：`engages_with`（两次活动 → 同一本书）· `belongs_to`（活动 → 两段经历）
- **必须保留的信息**：**两次接触是两个事件，一本书是一个对象**。若合并成"读过"，3-19 与 9-25 之间的六个月就没了，
  而那六个月正是他从"读到"变成"重读"的全部意义。
- **能否不新增类目**：能。一个 Material + 多条 `engages_with`。**不需要"每门课一份副本"。**

### ST-02 · 一门没有指定教材的课

**场景**：数据集里 6 段经历**全部**有材料（`lx-01` 有 3 份、`lx-04` 有 6 份）。
假设 `lx-01` 只靠课堂和讨论，没有任何读物。

- **主类**：I-b Learning Experience。
- **其他有效角色**：无。它可能连一件 Artifact 都不产。
- **需要的关系**：0 条。`engages_with` 允许为空。
- **必须保留的信息**：**"没有材料"不是"数据缺失"**。`lx-01` 的价值在板书和讨论里，这些在系统里没有对象。
- **能否不新增类目**：能，但有个代价——**这类经历在轨迹上会显得很空**。
  一个只显示"关联材料"的界面会把它渲染成"什么都没学"，而它可能是最有效的一段。
  ⚠️ 数据集这里有一个**覆盖缺口**：没有任何"零材料的经历"，所以这个风险今天测不出来。

### ST-03 · 一个中途改方向的工程

**场景**：`prj-02` 开题是纯视觉方案，4 月在日光灯下不稳，5 月加了红外补光，成功率 62%→78%。
6-02 把项目描述从"纯视觉方案"改成"单目 + 红外补光"。

- **主类**：I-c Project（有开发史、有状态）。
- **其他有效角色**：3 件产出（`out-04` 论文、`out-11` slides）的来源 · `foc-07` 的主体 · `ms-04`/`ms-05` 的容器
- **需要的关系**：`produces`（项目 → 产出）· `transitions_to`（方案变更）· `supersedes`（新描述 ⊃ 旧描述）
- **必须保留的信息**：**旧描述**。今天它存在 `description_revisions[0].from` 里，而不是被覆盖。
  如果只剩新描述，"他改过方向"这件事就消失了，而这个改动恰好是 `act-035`（师兄建议）到 `act-048`（被迫接受）之间的全部内容。
- **能否不新增类目**：能。**前提是 Project 允许有 `revisions[]`**——这是原提案没提、但数据里已经存在的东西。

## B · 证据边界

### ST-04 · 一件产出同时支撑三个判断，还反驳一个

**场景**：`out-10`（repr-view v1，412 行 + 说明文档，附 3 个自测用例）。
它产出 `ev-17`（能交付）、`ev-24`（这次补了验证）；`ev-24` 削弱 `ins-12`、反驳 `ins-13`。

- **主类**：I-d Artifact。
- **其他有效角色**：2 条证据的载体 · `prj-07` 的产出 · **`ins-13` 的反证**
- **需要的关系**：`produces`（活动 → 产出）· `supports`（证据 → 解释）×1 · `contradicts` ×1
- **必须保留的信息**：**产出本身不是证据**（`trajectory-inputs.md` §4.4）。中间必须隔着一条 Evidence。
  若让 Artifact 直接 `contradicts` 一条解释，就变成"东西存在所以他对/他错"，这正是要防的。
- **能否不新增类目**：能，但要求关系不能挂在 Artifact 上，只能挂在 Evidence 上。

### ST-05 · 一条证据反驳一条高置信的系统判断

**场景**：`ins-13`（10-30，confidence: high）："5-22 之后你在神经渲染这条线上零投入。"
`ev-17`（10-29）：repr-view 画的就是 3D 数据的特征向量。`ev-24`：它还有自测。两条 `contradicts`。

- **主类**：III Evidence（证据）。
- **其他有效角色**：`ins-13` 的反证 · `prj-07` 的证据
- **需要的关系**：`contradicts`（Evidence → Interpretation）**必须允许方向是负的**
- **必须保留的信息**：**矛盾不能被裁决**。系统没有撤回 `ins-13`，用户也没看过它。
  一个"自动取高置信"的实现会让错误的那条赢——这就是这道题要抓的东西。
- **能否不新增类目**：能。但需要一条规则：**`contradicts` 不会自动降低 `confidence`**。
  置信度是生成时的判断，不是事后投票。

### ST-06 · 一条证据只加条件，不推翻

**场景**：`ev-23`（10-31）第 3 节写了 800 字全删、改成重写开头 → `qualifies` `ins-07`（"9 月后写作量上升"）。

- **主类**：III Evidence。
- **其他有效角色**：`ins-07` 的限定条件
- **需要的关系**：`qualifies`（比 `contradicts` 弱，比 `supports` 复杂）
- **必须保留的信息**：**"削弱"与"反驳"与"加条件"是三件事**。
  `weakens` 降置信，`contradicts` 说不能同时成立，`qualifies` 说"成立但只在某种情况下"。
  数据集里三个都有（rel-04 / rel-09 / rel-05），压成两档就会把它们混为一谈。
- **能否不新增类目**：能，但要**四种极性**（supports / weakens / contradicts / qualifies）。
  原提案只有三种，缺 `weakens`。

### ST-07 · 用户说"我能读懂了"，但没人测过

**场景**：`ev-18`（10-31）："我现在能读懂 NeRF 那类论文了，基本不用查。" 唯一一次检验是 `ev-21`（10-24），结果不确定。

- **主类**：**IV Interpretation**（不是 Evidence）。作者是他，`subject: self`，`about: 知识`。
- **其他有效角色**：一个待验证的主张 · `ev-21` 的检验对象
- **需要的关系**：`derived_from` 不成立（没有推的来源）；`supports` 不成立（没有证据撑它）。
  它是一条**悬空解释**——这在数据里是合法的：解释可以先存在，证据可以永远不到。
- **必须保留的信息**：**"他说的"与"系统测到的"必须长得不一样。**
  若把它当 Evidence，`ev-21` 的 inconclusive 就会被读成"部分证实"，于是这句话变成事实。
- **能否不新增类目**：能，**但要把自述从 Evidence 移到 Interpretation**。
  这是本规范与原提案分歧最大的一处（spec §2.3.3）。

## C · 兴趣、线索、目标

### ST-08 · 系统推断出一个兴趣，用户否定的不是它，是它的说法

**场景**：`int-07`（系统编程/Rust）从 2 月活跃到 4 月，9-02 用户写下 `ins-06`：
"我不是想成为 Rust 工程师。我是想成为'能写系统代码的人'，这两个不一样。"

- **主类**：I-f Interest（`int-07`）+ II-b Transition（退役）。
- **其他有效角色**：`ins-06` 是**对这个兴趣命名的否定**，不是对"他学过 Rust"的否定
- **需要的关系**：`transitions_to`（active → retired）· `derived_from`（ins-06 依据 ev-11、ev-16）
- **必须保留的信息**：**兴趣的名字与被否定的对象是两件事**。被否的是"Rust 工程师"这个身份框，
  不是"他学了 Rust"。退役之后 `lx-02` 那段经历仍然成立，`ev-11` 那条证据仍然成立。
- **数据集的一个缺口**：真正意义上的"用户拒绝一条推断"在这里并不干净——`int-06`（数学基础）才是那条推断错的兴趣，但它从未被摆到用户面前，所以谈不上拒绝。
  这道题今天是靠 `int-07` 的退役来回答的，属于"近似"而不是"正中"。
- **能否不新增类目**：能。**但 `retired` 必须是一个独立生命周期值**，不能和 `abandoned` 合并——
  放弃是他决定的，退役是这个说法不再成立。

### ST-09 · 一个没人声明过的兴趣

**场景**：`int-04`（因果推断）：8 条活动、3 份材料、54 天，`confirmed_by_user: false`，`confidence: moderate`。
他从没说过"我对因果感兴趣"，他只说过"我就是顺着往下看"。

- **主类**：I-f Interest（推断型）。
- **其他有效角色**：`foc-05` 的一段 · `prj-06` 的一节 · `cluster-01`（不属于任何课程的 8 条活动）
- **需要的关系**：从活动聚合出来的，没有单条证据 → **需要一个今天不存在的东西：推断的证据指针**
- **必须保留的信息**：**`confirmed_by_user: false` 必须一直跟着它。**
  数据集里 5 条推断型兴趣只有 0 条能点回具体证据（`int-04` 有活动列表，但没有一条 `evidence`）。
  这意味着用户问"你凭什么说我对因果感兴趣"时，系统只能拿一堆活动糊过去。
- **能否不新增类目**：能，**但不能新增"推断证据"这个类目**——它应该复用 Evidence，只是今天没写。

### ST-10 · 一条线索横跨两个兴趣、三个项目、两种来源

**场景**：`foc-02`（表征的跨域用法）：`related_interests: [int-02, int-03]`、
`related_projects: [prj-05, prj-06, prj-07]`、两段经历、6 份材料、19 条活动，从 2 月到 11 月。

- **主类**：I-e Focus。
- **其他有效角色**：多个对象的组织视角 · 不是任何一个项目的子集
- **需要的关系**：`engages_with`（活动 → 线索？）—— ⚠️ **这里是关系表的一个缺口**：
  活动挂线索应该用什么关系？`belongs_to` 太强（一条活动可以同时属于两条线索，且线索不是组织容器）。
  建议复用 `engages_with` 并注明"活动 engagements 的对象可以是 Object 或 Focus"。
- **必须保留的信息**：**线索不是容器的并集**。它的活动集合不等于它的兴趣的活动集合的并集——
  数据集里 `foc-02` 的 19 条活动中，有 4 条（`act-121`、`act-128`、`act-133`、`act-094`）同时属于别的线索。
- **能否不新增类目**：能。这正是 `trajectory.md` §3 要的那一列："同一个概念相关的节点落在同一列"。

### ST-11 · 一个被放弃的目标

**场景**：`goal-05`（把多视角一致性做出来，投一篇 workshop），3-20 立，8-31 截止，9-01 才正式关掉。
中间四个月它一直挂在清单上，项目 5 月就死了。

- **主类**：I-g Goal。
- **其他有效角色**：`prj-01` 的意图来源 · 一个从未发生的里程碑
- **需要的关系**：`transitions_to`（active → abandoned，9-01）
- **必须保留的信息**：**目标死亡的时间（9-01）与项目死亡的时间（5-26）不一样。**
  差 97 天。这 97 天里他一直有一个"还没做完的论文计划"——这是 UI 必须能表达的东西：
  一个已经没人动的项目，还挂着一个活着的目标。
- **能否不新增类目**：能，但要求 Goal 与 Project 各自有独立生命周期，**不能用一个 status 串起来**。

## D · 事件与时间

### ST-12 · 一件什么都没产出的活动

**场景**：`act-126`（6-06 20:40）："让 AI 改摘要，改了七版。" `focus: []`、`evidence: []`，最后用的还是第二版。

- **主类**：II-a Activity。
- **其他有效角色**：**没有**。它就是一件发生过的事。
- **需要的关系**：0 条。
- **必须保留的信息**：**它必须能存在。** 任何"活动必须有归属/必须有产出"的模型都会把它删掉或塞进某个项目，
  而它恰好是这五天里最有代表性的一条：他在用 AI，但没有学到东西，也没有做出来东西。
- **能否不新增类目**：能。**只要允许 0 关系。** 这也是 `focus: []` 与"没有 focus 字段"必须分开的原因。

### ST-13 · 一条日期本来就是错的记录

**场景**：`act-064`（中期答辩）记的是 `2026-05-15`。7-02 用户翻邮件发现是 5-14。
更正存在 `cor-05`（`event_time: 05-14`、`recorded_time: 05-15`、`revision_time: 07-02`），**原记录不改**。

- **主类**：II-a Activity（记录仍是一件事），但**它的时间字段不可信**。
- **其他有效角色**：**一个被更正的记录**（记录层角色，不是发展层角色）
- **需要的关系**：`supersedes`（cor-05 ⊃ act-064.ts）
- **必须保留的信息**：**原始值 + 正确值 + 谁在什么时候发现的。**
  把 `act-064.ts` 改成 5-14 会让历史看起来一直是对的——那就消灭了"他记错了"这件事。
- **能否不新增类目**：能，**但分类必须承认"记录层"的存在**。这是原提案完全没有的一层（spec §6-同理）。
  ⚠️ 一个只读 `ts` 的界面会永远显示 5-15，而且**看不出这里有更正**。

### ST-14 · 一次延迟录入

**场景**：`act-105`：3-13 在白板上给师兄画表征的两种用法，当天没记，4-22 整理笔记时补录，只记得"三月中某天"。

- **主类**：II-a Activity，`ts: 03-13`、`recorded_at: 04-22`、`precision: day_uncertain`。
- **其他有效角色**：`foc-02` 的早期活动 · `ins-01` 的前身
- **需要的关系**：无特殊关系，但**排序必须按 `ts` 而不是 `recorded_at`**
- **必须保留的信息**：**三个时间（发生 / 录入 / 精度）**。只留 `ts` 会丢掉"这是补记的"；
  只留 `recorded_at` 会把它放到四月，于是三月那条线上少了一个人。
- **能否不新增类目**：能。**但 Temporal 维度必须允许"只给需要的对象加字段"**——
  135 条活动里只有这一条有 `recorded_at`，这是对的，不是遗漏。

### ST-15 · 一条外部记录，事后改变了系统的判断

**场景**：`ext-01`（GitHub 87 次提交，1 月 41 次…5 月 12 次，最后 32 天 0 次），6-22 才同步进来。
系统据此在 6-22 判定 `prj-01` 已停止（`ins-09`），6-24 用户更正："我没停，我是在等毕设结束。"

- **主类**：**有争议**。它是 Behavioral Evidence 的**聚合**，不是一条事件。
- **其他有效角色**：`ins-09` 的依据 · `ins-13` 的依据（并且是被误用的）
- **需要的关系**：`supports`（ext-01 → ins-09）· `supersedes`（cor-01 更正 ins-09）
- **必须保留的信息**：**这是"摘要"不是"观察"**。把它画成一个点，等于把五个月的分布压成一个瞬间；
  而 `ins-13` 的错误正是从这里来的：**一条聚合观察被当成了完整证据**。
- **能否不新增类目**：**勉强能，但这是本规范最不舒服的一处**。
  它是 Evidence（Behavioral），粒度却是"87 件事的统计"。若拆成 135 条事件，一次同步会淹没一周；
  若不拆，证据的粒度就与事件不对等。⇒ 列为未决（spec §7-1）。

### ST-16 · 被吸收的线索，活动一条也没迁

**场景**：`foc-03`（意识一手文献，3-27 → 5-24）`absorbed_into: [foc-02]`。
它名下 10 条活动（`act-042`…`act-066`）**没有任何一条改了归属**。

- **主类**：I-e Focus + II-b Transition（absorbed）。
- **其他有效角色**：`foc-02` 的前身 · `lx-04` 的一段
- **需要的关系**：`merges_into`（这个关系原提案没有）
- **必须保留的信息**：**合并是"之后怎么看"，不是"当时的记录被改写"。**
  如果把 10 条活动批量迁到 `foc-02`，3–5 月的那条线就消失了，而它恰恰是"他曾经单独追过这个问题"的唯一证据。
- **能否不新增类目**：能，但**需要第 12 条关系 `merges_into`**。
  `supersedes` 不行——被吸收方没有被取代，两个都还在（`foc-03` 仍可被查看）。

## 汇总：这些案例逼出了什么

| 案例 | 逼出的东西 | 类型 |
|---|---|---|
| ST-02 | **零材料的 Learning Experience** | 数据集缺口 |
| ST-03 | Project 需要 `revisions[]` | 提案缺字段 |
| ST-06 | 需要 `weakens` 极性 | 关系表缺项 |
| ST-07 | 自述应从 Evidence 移到 Interpretation | 分类改动 |
| ST-09 | 推断型兴趣需要证据指针 | 数据缺口 |
| ST-10 | 活动挂线索用哪个关系没定 | 关系表歧义 |
| ST-13 | **需要一个"记录层"** | 提案缺一整层 |
| ST-15 | 聚合证据的粒度问题 | 未决 |
| ST-16 | 需要 `merges_into` | 关系表缺项 |

16 个案例里，**没有一个需要新增主类**。需要新增的是：1 个关系、1 个生命周期值、1 个维度取值、
1 个字段（revisions）、1 个层次（记录层），以及 2 处数据缺口。
这说明五类主范畴的划分是扛得住的——**烂的是边角和关系词汇**，不是骨架。
