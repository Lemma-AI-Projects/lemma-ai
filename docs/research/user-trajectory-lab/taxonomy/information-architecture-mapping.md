## 0 · 先否掉一个默认假设

四个视角不等于四个页面。**它们是四个问题**：

| 视角 | 它问的问题 | 对应四问 |
|---|---|---|
| Timeline | 发生了什么 | 第 1 问 |
| Explore | 我一直在绕着什么转 | 第 2 问（横切） |
| Development | 我现在在哪 | 第 4 问 |
| Insights | 系统凭什么这么想 | 第 3 问 |

`trajectory.md` §3 已经定了主视图是"纵向时间 × 横向 focus"，它同时承担 Timeline 与 Explore。
**把四问拆成四个 tab 的代价**：用户要在"我做了什么"和"我关心什么"之间反复横跳，
而这两件事在数据里本就是同一张图上的两个轴。

⇒ 本文按"**一张主图 + 三种叠加**"来写，而不是四页。如果最后必须分页，每个视角的取舍也在下面写清了。

## 1 · Timeline

### 1.1 第一眼看到什么

**最近 30 天，加一个"今天"的锚点。** 不是全量历史。

理由在数据里：135 条活动摊在 301 天里，最长空档 35 天，最密一天 8 条。
一上来给全量，等于给用户一封 300 天的账单；先给"你上次在哪"才可能继续往下拉。

### 1.2 哪些范畴在场

| 范畴 | 密度 | 显示形态 |
|---|---|---|
| II-a Activity | 最高（135） | 点/短条，按天聚合，可展开 |
| II-b Transition | 中（22） | **和活动不同的记号**（方向箭头、状态前缀） |
| II-c Milestone | 低（9） | 横杠，跨列 |
| I-d Artifact | 中（12） | 只挂在产生它的活动下，不单独成点 |
| I-e Focus | 7 | **横向的列**，不是点 |
| IV Interpretation | 低（14） | 只在"有话说"的位置出现，默认折叠 |
| III Evidence | 24 | **默认不在时间轴上**，只在节点展开后出现 |

### 1.3 怎么走到别的对象

- 点活动 → 展开 `engages_with` 的对象（材料 / 项目 / 线索）→ 跳进 Explore 的对应列
- 点里程碑 → 跳进 Development（"这条线现在到哪了"）
- 长按/更多 → 看这条活动产出的解释（如果有）

### 1.4 证据与出处怎么查

**两级，不多不少**（`trajectory.md` §4 已定）：

```
判断（他理解了困难问题）
  → 依据（ev-08：5-02 那两页复述）
    → 原始记录（act-059 那次活动，以及它引用的 mat-16）
```

第二级必须能点到**原始活动**，因为那是唯一"别人也能去看"的东西。
一条没有第二级的解释，`trajectory.md` §4 要求**显形为"没有记录支撑"**——不是藏起来，是标出来。

### 1.5 时间怎么表达

- 位置是唯一的时间编码，**不用长度表示时长**（数据里没有时长）
- 发生时间优先；`recorded_at` 只在它和 `ts` 差很远时以附注出现（`act-105`：补记于 4-22）
- **被更正的日期必须有痕迹**：`act-064` 显示 5-15，旁边一个小标记指向 `cor-05`（真实 5-14）。
  直接显示 5-14 是篡改，只显示 5-15 是撒谎，两个都得在。

### 1.6 藏起来直到被要

- 全部 104 条历史（默认只给 30 天）
- 证据全文与 `does_not_support`
- 解释的置信度与谁说的
- 未被审阅的系统解释（默认不打断主时间轴）

## 2 · Explore

### 2.1 第一眼看到什么

**7 条线索的横向分布，加它们各自的时间跨度。** 这是"我这些年绕着哪几件事转"的唯一可视图。

`trajectory.md` §3 的验收标准可以直接用了：*"TOEFL 那张要能一眼看出「口语」是竖着的一条线。"*
数据集上对应的断言：**`foc-02` 应该是一根从 2 月拉到今天的竖线，`foc-04` 应该是 1–3 月的一小段。**

### 2.2 哪些范畴在场

| 范畴 | 在场方式 |
|---|---|
| I-e Focus | 列（主结构） |
| I-f Interest | 列上方的一行状态灯：核心 / 活跃 / 变冷 / 休眠 / 退役 |
| I-c Project | 跨列的长条（一个项目常常横跨 2–3 条线索） |
| I-a Material | 只作为活动的附属，不单独成列（29 件平面铺开会淹没 7 条线） |
| I-g Goal | 顶部一行，不占列 |

### 2.3 怎么走到别的对象

- 点一列 → 只看这条线索（`trajectory.md` §4 第 3 步要的"聚焦过滤"）
- 点一条兴趣 → **不要跳到列，要跳到"这条兴趣和这条线索是什么关系"的说明**
  （`int-02` 与 `foc-02` 同时存在，点一下就合并会抹掉两者的区别）
- 点项目 → 看它的开发史（`prj-01` 的 9 个节点）

### 2.4 证据与出处

**Explore 是最不需要证据的视角**——它回答"我在干什么"，不回答"我做到了没有"。
证据只在一个地方出现：**推断型兴趣的旁边**（`int-04` 标"系统推断，未确认"，点开看那 8 条活动）。

### 2.5 时间怎么表达

只有跨度。**列的长短就是时间**，不需要刻度——这是唯一一个时间被"形状化"的视角。

### 2.6 藏起来直到被要

- 线索下的每一条活动（默认只给数量与分布）
- 线索被吸收/关闭之后的活动（`foc-01` 关了还有 2 条，默认折叠在"关后"）
- 没有线索的 39 条活动（37 条未评估 + 2 条显式为空）——**默认不显示，但必须有一个"没有线索的活动"的入口**，
  否则 `act-126`、`act-132` 这类永远看不到

## 3 · Development

### 3.1 第一眼看到什么

**三行字**：现在能做什么 / 正在形成什么 / 接下来可以做什么。

这不是设计选择，是 `learner-state.md` §2 已经定的：
```
✓ 已具备   → 接下来可学   ○ 还没轮到
```
**没有百分比，没有掌握度，没有曲线。**

### 3.2 哪些范畴在场

| 范畴 | 在场方式 |
|---|---|
| V State | **全部派生**，不显示来源记录，只显示结论 + "N 条记录" |
| I-g Goal | 顶部：哪些目标在推进、哪些停了 |
| II-b Transition | 近期变化（"这个月有 2 个目标被关掉"） |
| IV Interpretation | 只挑"关于能力"的那几条（`about: 知识/推理过程`） |
| III Evidence | **完全不在首屏**，只在点开某一条状态时出现 |

### 3.3 怎么走到别的对象

- 点"已具备"的一项 → 看支撑它的证据列表（不是"分数"，是"哪几次"）
- 点"正在形成"的一项 → 看最近一次相关的活动与解释
- 空态必须是一种**可读的状态**，不是"暂无数据"（见 3.6）

### 3.4 证据与出处

这里是**唯一必须默认展示出处的地方**：每一个状态结论旁边都要有"凭什么"。

原因是数据里的教训：`ins-13` 是 high confidence 且错的。Development 视角如果只显示结论，
它会把一个错误变成一个看起来最可靠的判断。

### 3.5 时间怎么表达

**"最近一次变化是什么时候"**，而不是"趋势"。
`evidence-flow.md`:326 说状态没有变更日志 ⇒ 任何折线图都是编的。
今天能给的最多是"这三个月的判断变过两次"，且每次都要能点回那条解释。

### 3.6 藏起来 / 必须显形

| 必须显形 | 为什么 |
|---|---|
| **"没有数据" 与 "不会" 的区别** | `ev-14` 是 `ungradable`，它既不是会也不是不会 |
| **判断的日期** | 状态是现算的，但"系统在某天这么判断过"是一条解释，有日期 |
| **未审阅** | 8 条系统解释里 4 条没人看过；有 1 条（`ins-13`）明确是错的 |

| 藏起来 | 为什么 |
|---|---|
| 证据原文 | 首屏放不下，且会诱导用户去读证据而不是读结论 |
| 置信度的数值化表达 | 不存在（红线） |
| 跨领域的能力对比 | 没有共同尺度，任何对比都是编的 |

## 4 · Insights

### 4.1 第一眼看到什么

**待审阅的解释**，不是全部解释。

数据支撑：13 条解释里 5 条是用户自己写的（不需要审），4 条未审、1 条被否、1 条部分更正、1 条更正、1 条撤回。
默认给全部，等于把"系统想了很多"当成价值；而 `adaptive-insight.md` §4.5 说的正好相反：
**"不生成"是一等结果。**

### 4.2 哪些范畴在场

| 范畴 | 在场方式 |
|---|---|
| IV Interpretation | 主体。每条带：谁说的 / 什么时候 / 关于什么 / 置信度 |
| III Evidence | **每条解释下必须能展开**（`adaptive-insight.md` §5 C-1：一条启示必须能展开看见它引用的那几行证据） |
| 关系 | supports / weakens / contradicts / qualifies 要**看得出方向**，不是一列"相关证据" |
| II-b Transition | 被否 / 被更正 / 被撤回的痕迹 |

### 4.3 怎么走到别的对象

- 从解释 → 证据 → 原始活动（两级，同 Timeline）
- 从解释 → 它讨论的那个对象（`ins-13` → `prj-07`）
- **从一条解释 → 与它冲突的另一条解释**（`ins-07` ↔ `ins-13`）
  这条路径今天在数据里存在（`conflicts_with`），但原提案的关系表里没有"解释↔解释"这个方向

### 4.4 证据与出处

这是唯一一个**证据比结论更重要**的视角。三条硬要求：

1. 一条解释下面，**支撑与削弱必须分开列**。`ins-12` 是 1 支撑 2 削弱，混在一起就等于在骗人。
2. **没有证据的解释必须显形**（`ev-18` 是对"我能读懂"的声明，一条证据都没有）。
3. **过期不删除**：`ins-12` 的 `effective_to = 10-29`，旧版本还能看，新范围写在 `reinterpretation` 里。

### 4.5 时间怎么表达

- 解释本身有日期（何时说的）
- 解释有**有效期**（`effective_from/to`）——这是唯一一种"有长度"的对象
- 用户的回应有日期（`ins-04` 5-24 被否、`ins-05` 11-01 部分更正）

### 4.6 藏起来直到被要

- 被撤回/过期的解释（默认折叠在"曾经这么以为"里）
- 低置信的推断（`int-05`：只有 9 天证据）
- 系统生成但从未被审的**超过 3 条**时，不要一次全推给用户

## 5 · 四个视角共用的一套规则

| 规则 | 出处 | 在四个视角里怎么落 |
|---|---|---|
| **每个节点答四问** | `evidence-flow.md` §10 | Timeline 给 1-2 问，Insights 给 3-4 问；任何视角都不许只给第 1 问 |
| **没依据要显形，不能隐藏** | `trajectory.md` §4 | 四个视角统一：无证据的解释带一个明确的标记，不是空着 |
| **证据两级追溯** | `trajectory.md` §4 | 任何出现解释的地方都能点到证据，再点到原始活动 |
| **不外流数值** | `learner-state.md` §1 | Development 与 Insights 都不出现百分比/分数/曲线 |
| **不生成是一等结果** | `adaptive-insight.md` §4.5 | Insights 空态是"这次没什么要说的" |
| **记录层不混入发展层** | 本规范 §2.2.2 | 更正（`cor-*`）只出现在"这条记录被改过"的附注里，不占时间轴节点 |

## 6 · 一张表看清"哪类范畴在哪个视角出现"

| | Timeline | Explore | Development | Insights |
|---|---|---|---|---|
| I-a Material | 附属于活动 | ✗ | ✗ | 作为证据落点 |
| I-b Learning Experience | 背景带 | ✓ | ✓（作为目标来源） | ✗ |
| I-c Project | 跨列长条 | ✓ | ✓ | 作为解释对象 |
| I-d Artifact | 附属 | ✗ | ✓（作为证据） | 作为证据 |
| I-e Focus | ✓（列） | ✓（主结构） | ✗ | 作为解释的"关于" |
| I-f Interest | ✗ | ✓ | ✓（状态灯） | 作为推断对象 |
| I-g Goal | 顶部 | 顶部 | ✓ | 作为解释对象 |
| II-a Activity | **主体** | 折叠 | ✗ | 作为证据来源 |
| II-b Transition | ✓ | ✓ | ✓ | ✓ |
| II-c Milestone | ✓ | ✓ | ✓ | ✗ |
| III Evidence | 折叠 | 极少 | 折叠 | **主体之一** |
| IV Interpretation | 折叠 | ✗ | 选中几条 | **主体** |
| V State | ✗ | ✗ | **主体** | ✗ |

三处刻意的空白：

1. **Explore 里没有 Interpretation**。这个视角回答"我在干什么"，不回答"系统怎么看我"。
2. **Development 里没有 Activity**。否则它会退化成第二个 Timeline，而且会诱导"活动多 = 状态好"。
3. **Timeline 里没有 State**。状态没有历史，画上去就是编的。

## 7 · 如果只能做一个视角

做 **Timeline + 横向 focus**。理由：它同时回答第 1 问和第 2 问，是唯一一个能把
"他做了 135 件事"与"他其实只在绕两三件事"放在同一张图上的形态；
另外三个视角都可以从它出发，而它不能从另外三个出发。
