## 0 · 三个前提（决定了后面所有取舍）

**① Trajectory 是投影，不是第二套语义库。**
`evidence-flow.md`:315 已定：轨迹不拥有独立的学习语义数据库，它是既有语义来源在时间轴上的投影。
⇒ 本文的五个类**不新增存储**，它们只是给已有记录命名、并规定什么样的记录才有资格被命名。

**② 状态是算出来的，不存历史。**
`learner-state.md` §1：状态纯函数派生、不落库、不外流任何数值。
`evidence-flow.md`:326 自己承认了后果：**没有「变化」这个事实可读**，所以 State Change 一项缺失。
⇒ 第五类（Development States）不能是实体。它不是本文能"加"的东西，只能被规定为投影（§2.5）。

**③ 一个节点要答四问，缺第三问是日志，缺第四问是编的故事。**
`evidence-flow.md` §10 / `trajectory-inputs.md` §1.4.2。
⇒ 分类的价值不在"分得细"，而在**每类能否稳定回答其中一问**。§2 每类末尾都标了它主要回答哪一问。

## 1 · 五个主范畴（一页看完）

| | 范畴 | 回答 | 一句话判据 | 数量（数据集） |
|---|---|---|---|---|
| **I** | **Development Object** 发展对象 | 什么东西在持续存在 | **能被指着一个具体东西说"就是这个"** | 82 |
| **II** | **Development Event** 发展事件 | 什么时候发生了什么 | **有一个时间点，且不能重复发生一次** | 166 |
| **III** | **Evidence** 证据 | 凭什么这么判断 | **一条具体的观察，能被别人复核** | 24 |
| **IV** | **Interpretation** 解释 | 这意味着什么 | **一个可以被反驳的句子** | 14 |
| **V** | **Development State** 发展状态 | 他现在处在什么位置 | **不存储；从 III 现算** | 0（派生） |

六条判据里最重要的是两条：

- **II 与 IV 的分界是"能不能被观察"**。同一句话，"他在 3 月 8 日写下一篇笔记"是事件；"他意识到表征是两件事"是解释。
  后者只有在前者存在时才成立，且**可以被推翻**。
- **III 与 IV 的分界是"能不能被复核"**。证据是一条别人能去看的观察（哪道题、哪段文本、哪次提交）；
  解释是一句判断。`evidence.verdict` 说的是**这条观察的结果**，不是它对某个解释的态度（见 §6 冲突 3）。

### 1.1 与原提案的差异（先说结论，理由在 §2）

| 原提案 | 本规范 | 为什么 |
|---|---|---|
| I 里 "Project & Creative Work" 合成一类 | **拆成 Project 与 Artifact** | 12 件产出里 3 件没有项目；6 条证据挂在产出上而不是项目上 |
| II 的 "Learning Event（理解/误解/迁移/突破）" | **删掉，并入 IV** | 没有任何人能"观察"到一次理解。`evidence-flow.md` §1.1 已写明「他不理解」是 Interpretation |
| II 的 "Reflection / Correction Event" | **拆成三样**：反思=Activity，更正=记录层操作，否决=用户控制维度 | 三者时间轴不同：一个是他的行为，一个是记录被改，一个是状态的翻转 |
| III 的六种证据 | **四种**（去掉 External 与 Self-reported） | External 是来源不是种类（`trajectory-inputs.md` §4.1）；自述是用户的解释不是证据（§2.3） |
| IV 的五种（Insight/Reflection/Claim/Trend/Hypothesis） | **一种 + 三个维度** | 它们差在 subject / confidence / 谁说的，不差在种类。Trend 不是实体（§2.4） |
| V 的六种状态 | **全部降为投影，Learner State 不是同级** | 状态不落库（前提②）；Learner State 是另外五个的合成 |

净结果：条目从 **29 个减到 15 个**（6+6+6+5+6 → 7+3+4+1，投影不计）。

## 2 · 逐类定义

每一类都给：定义 / 判据 / 收入什么 / 不收什么 / 正例 / 反例 / 它答四问里的哪一问。

### 2.1 对象（I）

对象的共同判据：**有身份、可以被反复引用、生命周期长于一次事件**。
反例：一次读书会不是对象；一本书是。

#### I-a Material 材料

- **定义**：用户**读/看/查**的东西，作者不是他。
- **判据**：能被"我读了它"这句话指向；它的存在不依赖用户。
- **收**：书、论文、视频系列、文档、文章、社区讨论串。
- **不收**：他自己写的东西（→ Artifact）；只存在于别人口中的观点（→ 没有对象，只是一句引述）。
- **正例**：`mat-19`（Bengio, The Consciousness Prior）——同时属于两段学习经历、两个项目、一条 pending 证据。
- **反例**：`out-04`（他的毕设论文）看起来也是"论文"，但作者是他，所以是 Artifact。**同一物理形态，不同关系。**
- **答**：四问里的第 3 问（凭什么）——材料是证据的落点，不是变化的载体。

#### I-b Learning Experience 学习经历

- **定义**：一段**有意图**的学习安排，用户可以给它起名字、说它"开始了/停了"。
- **判据**：存在一个目的（哪怕很虚）；能回答"这段有没有结束"。
- **收**：课程、自学计划、围绕一个问题的探究、以某个项目为载体的学习。
- **不收**：一串没有意图的活动（→ `loose_cluster`，见 §3 边界 4）。
- **正例**：`lx-04`（理解人的意识）——**没有结束日期**，9 月收敛成一篇长文，仍然没有正式关闭。
- **反例**：`cluster-01`（因果推断 8 条阅读）——他从未把它组织成一段经历，只是"顺着往下看"。
- **答**：第 1、4 问（发生了什么 / 这对接下来的意义）。

#### I-c Project 项目

- **定义**：一段**有产出的持续投入**，有开始、有开发史、可以归档。
- **判据**：能画出时间线；能说"它现在是什么状态"；它**不是**做出来的那个东西本身。
- **收**：软件项目、研究计划、长期写作。
- **不收**：一次交付（那是事件/产出）；没有投入史的想法（那是 Goal）。
- **正例**：`prj-01`（recon-lab）——9 个开发节点，最后一版 v0.3 只做代码整理，归档。
- **反例**：`out-10`（repr-view v1）是产物；`prj-07` 才是那段投入。两者不能互换。
- **答**：第 1 问与第 4 问。

#### I-d Artifact 产出物

- **定义**：他**做出来的、可以被指认的一个东西**。
- **判据**：有边界（一个仓库、一份 PDF、一封邮件），别人能打开它。
- **收**：代码仓、报告、论文、讲义、草稿、slides、笔记库、工具、**没发出去的邮件**。
- **不收**：他脑子里想通的道理（→ Interpretation）；他读的书（→ Material）。
- **正例**：`out-12`（给老师的邮件，写了 600 字，没发）——它存在，而且是他做的；**"没发出去"不改变它是产出物**。
- **反例**：`out-11`（分享 slides）是产出物；`act-065`（那 20 分钟的分享）是事件。两者同源不同物。
- **答**：第 3 问（凭什么）——产出物是 Artifact Evidence 的落点；**它本身不证明能力**（`trajectory-inputs.md` §4.4）。

#### I-e Focus 线索

- **定义**：**一段有起止的观察视角**，回答"这一段我在干什么"，不回答"我关心什么"。
- **判据**：有 `from`；可以没有 `to`；可以关闭、可以被吸收；**一条活动可以挂 0、1 或多条**。
- **收**：研究方向的探索期、持续的技术建设、跨学科追问、集中补课的时期、任务驱动的冲刺。
- **不收**：长期兴趣（→ Interest）；项目（→ Project，虽然常常重叠）。
- **正例**：`foc-04`（补到能看懂协方差传播的数学）——`related_interests: []`，**它不对应任何一条兴趣**。工具性时段本来就该是这个样子。
- **反例**：`int-02`（表征）是兴趣；`foc-02`（沿这个问题走了多远）是线索。前者在产品里可以永远存在，后者会结束。
- **答**：第 2 问（什么变了）——线索是"变化发生在哪条线上"的坐标系。

> ⚠️ Focus 的 `status` 需要第 6 个值：`absorbed`（被吸收）。原提案的 Lifecycle 五值里没有它，
> 而数据集里 `foc-03`、`foc-05` 都是被吸收而不是被完成或放弃。

#### I-f Interest 兴趣

- **定义**：一个**可能持续很久、也可能消失的注意方向**。
- **判据**：可以说"他关心这个"；不需要起止；**可以由系统推断，但推断值不等于事实**。
- **收**：声明过的、从行为推断的、变冷的、退役的、以及**推断错的**。
- **不收**：一段有起止的视角（→ Focus）。
- **正例**：`int-06`（数学基础）——系统当年的误判，`confirmed_by_user: false`。**假阳性必须能被表示**。
- **反例**：`foc-06`（学 Rust）在 4-20 关闭，`int-07` 到 9-02 才退役，差 135 天。一条线结束了，一段兴趣还挂着。
- **答**：第 2 问。

#### I-g Goal 目标

- **定义**：一个**意图达到的状态**，可以没有日期，可以有多个截止日。
- **判据**：它能被"完成/放弃/改口径"；它不发生在某一刻，它持续存在直到被改变。
- **收**：长期方向、短期目标、习惯型目标。
- **不收**：里程碑（→ II-c，那是一个时间点）；计划（那是 Milestone 的 `planned_date`）。
- **正例**：`goal-01`（"进入一个能做智能研究的地方"）→ 9 月被改写成 `goal-10`（"决定申请哪个方向"）。**改口径不是放弃。**
- **反例**：`ms-05`（答辩通过）是里程碑，`goal-03`（毕设按期完成）才是目标。一个目标下可以有多个里程碑。
- **答**：第 4 问（这对接下来的意义）。

### 2.2 事件（II）

事件的共同判据：**有一个时间点（或一段），且它是"发生过的"，不是"被判断的"**。

只有三类。原提案的六类砍到三类，理由逐条写在下面。

#### II-a Activity 活动

- **定义**：他**做了什么**。
- **子类型**（沿用数据集的十个值，不新增）：read / watch / discuss / note / problem / experiment / code / research / create / reflect。
- **判据**：能回答"几点、在哪、做了什么"。
- **不收**：他从中学到了什么（→ III/IV）。**活动不自动意味着学会**（`trajectory-inputs.md` §2.B）。
- **正例**：`act-112`（消融跑完，51%，只有 12 次试验）——它是一次活动，也是一个证据来源，但它本身不说明任何能力。
- **反例**：`act-126`（让 AI 改摘要七版）——活动成立，`focus: []`，零证据，零解释。**它存在，但它什么也不证明。**
- **答**：第 1 问。

#### II-b Transition 转变

- **定义**：某个对象**状态的翻转**（不是他做的一件事，是对象变了）。
- **子类型**：Goal 开始/完成/放弃/改口径 · Interest 出现/变冷/退役 · Focus 关闭/被吸收 · Project 归档/恢复 · 解释被否决/撤回。
- **判据**：有 `from` 与 `to`；**它是对象的属性变化，不是一次操作**。
- **收**：`goal-02` 在 4-20 被放弃；`foc-03` 在 5-24 被 `foc-02` 吸收；`ins-10` 在 4-28 被撤回。
- **不收**：他写下"我放弃了"这个动作（那是 `act-055`，一次 Activity）。
- **正例**：`act-055`（他写下"我其实不需要它"，4-20）与 `goal-02` 的 abandoned 是两个对象：**一个是行为，一个是状态**。
- **答**：第 2 问。**这是"什么变了"最直接的载体**，也是 `evidence-flow.md`:326 说缺失的那一项。

#### II-c Milestone 里程碑

- **定义**：一个**被标记的时间点**，用来指示"越过了某条线"。
- **判据**：有名字；通常有计划日期与实际日期；**它不承载内容，只承载"到了"**。
- **收**：答辩通过、第一次出图、PR 合并、v1 定版。
- **不收**：一段持续的状态（→ Goal）；一次普通活动（哪怕很重要）。
- **正例**：`ms-01`（第一次出可看的重建结果，计划 2-15，实际 1-30，提前）。
- **反例**：`ms-02`（线代复习做到第 5 章）——它是里程碑，但事后看是**仪式性的**：后四章从没做，也没用上。里程碑成立，意义不成立。
- **答**：第 2 问。

#### 2.2.1 为什么删掉 "Learning Event"

原提案把「理解 / 误解 / 迁移 / 突破」列为事件。三条反对：

1. **没有人能观察到一次理解。** 能观察到的是：他答对了、他解释了、他把方法用到了新情境。
   观察结果是 Evidence，判断"他理解了"是 Interpretation。`evidence-flow.md` §1.1 原话：
   「答错是 Evidence；这个知识点待确认困难是 State；而**他不理解是 Interpretation** —— 三者必须分开表述」。
2. **它会把第四问变成编故事。** 一个"突破"节点如果不带证据，就是 `evidence-flow.md` §10 说的"AI 编的故事"。
3. **它和 IV 重复。** "9 月 26 日那次突破"在数据里就是一条带日期的解释（`ins-08` 是 10-25，`ins-12` 是 6-08），
   不需要第二种对象来装它。

**代价**：时间轴上少了一种节点。**补偿**：解释自带 `at`，仍然落在轴上，只是它显示为"被断言"而不是"被观察"（见 §5 Epistemic）。这比造一个假的观察类更诚实。

#### 2.2.2 为什么拆开 "Reflection / Correction Event"

原提案把三件事放进一格，它们的时间轴完全不同：

| 原提案里的东西 | 实际是什么 | 落在哪 | 数据集实例 |
|---|---|---|---|
| Reflection（反思） | 他做的一件事 | II-a Activity（type=reflect） | `act-058`、`act-081`、`act-101` |
| Confirmation / Rejection（确认/否决） | 他对一条解释的状态翻转 | 维度 User Control + II-b Transition | `ins-04` 被否（5-24） |
| Correction（更正） | **记录被改了**，不是他做了什么 | **记录层**（Provenance），不在发展时间轴上 | `cor-05`（`act-064` 日期 5-15→5-14） |

`cor-05` 是最好的证据：那天他什么也没做，是系统在 7-02 发现 5-15 是错的。
把它画在发展时间轴上，会让"7 月 2 日"变成一个他根本没有的节点。

### 2.3 证据（III）

#### 2.3.1 定义与判据

- **定义**：一条**关于他实际表现的具体观察**，能被第二个人复核。
- **判据**：三件事都要有——① 观察到了什么；② 它挂在哪个活动上；③ **它不能证明什么**。
- **一个必须保留的字段**：`does_not_support`。数据集 25 条证据 100% 都有这一栏，
  因为一条不写"不能证明什么"的证据，最后一定会被当成"能证明一切"。

#### 2.3.2 四种，不是六种

| 种类 | 是什么 | 数据集实例 |
|---|---|---|
| **Performance** 表现 | 对错、完成度、指标 | `ev-01` 五题全对 · `ev-07` 贝叶斯错 · `ev-19` 复测 78% |
| **Reasoning** 推理 | 解释、独立推导、迁移 | `ev-03` 自推体渲染 · `ev-08` 复述困难问题 · `ev-13` backdoor 迁移 |
| **Artifact** 产出 | 做出来的东西本身 | `ev-04` 出图 · `ev-16` 只完成 dry-run · `ev-17` repr-view v1 |
| **Behavioral** 行为 | 过程、节奏、模式 | `ev-11` 三次同类错 · `ev-22` 计划三组只跑一组 |

**去掉 External**：`trajectory-inputs.md` §4.1 已定「来源 ≠ 类型」。`ev-20`（朋友指出第二处混用）
是**关于他解释的第三方判断**，种类是 Reasoning，`by: third_party` 是来源。若把 External 当种类，
下一次"从 GitHub 导入的一次作答"就无处可放——它是 Performance，只是来源是 F。

**去掉 Self-reported**：这一条改动最大，单独说。

#### 2.3.3 自述不是证据，是解释

`trajectory-inputs.md` §2.A 已定：**明示信息对"他说了什么"是权威的，对"是不是真的"不是。**
数据集的 `ev-18` 就是这个规则的落地：他说"我现在能读懂 NeRF 类论文了"，`verdict: not_evidence`。

那么它到底是什么对象？**它是用户写的一条解释**：`subject: self`、`about: 知识`、`asserted_by: user`。
它的价值是"他想让自己相信什么"，不是"他会什么"。

⇒ 自述进 IV，不进 III。**"用户说他会" 与 "证据显示他会" 在这套分类里长得完全不一样**，
这正是 `trajectory-inputs.md` §4.3 要求的"每一条记录都要能说出是谁断言的"。

> ⚠️ 这一条与提案不同，属**强建议**而非定论。若产品坚持要有"自述"这个种类，
> 唯一可接受的形态是：`kind: self_report` + `admission: not_admitted`，且**永不计入任何状态计算**。

#### 2.3.4 两个必须分开的值

数据集把两种东西塞进了同一个 `verdict` 字段，这是可以修的：

| | 回答 | 值 |
|---|---|---|
| **outcome** 结果 | 这条观察本身成不成立 | `supported / unsupported / partial / inconclusive` |
| **admission** 准入 | 它有没有资格进入判断 | `admitted / ungradable / pending / not_evidence` |

`ev-14`（答"我不知道"，没有可挂的知识点）是 `admission: ungradable`，`outcome: —`。
它既不表示会，也不表示不会。**今天这两件事被压在一个枚举里，导致"没测出来"只能被显示成"部分掌握"。**

### 2.4 解释（IV）

#### 2.4.1 定义

- **定义**：一句**关于他、关于他的东西、或关于世界的判断**，有作者、有日期、**可以被反驳**。
- **判据**：能说出"如果 X 出现，这句话就不成立"。
- **收**：他的顿悟、系统的观察、他对自己能力的声明、朋友的一句评价（若被记录成解释）。
- **不收**：观察（→ III）；状态（→ V）；原文（→ Material/Artifact）。

#### 2.4.2 一种，三个维度

原提案分 Insight / Reflection / Development Claim / Trend / Hypothesis。它们差在这三处，不差在种类：

| 维度 | 值 | 数据集实例 |
|---|---|---|
| `asserted_by` | user / system / third_party | `ins-01`（user）· `ins-12`（system）· `ev-20` 里的第三方评价（third_party） |
| `subject` | self / work / world | `ins-11`（self，"我什么都没做成"）· `ins-08`（work，关于长文）· `ins-01`（world，关于"表征"这个词） |
| `about` | 沿用 `adaptive-insight.md` §3 已定的六轴：知识 / 推理过程 / 表达 / 策略 / 元认知 / 情绪与坚持 | `ins-04`（策略）· `ins-05`（情绪与坚持）· `ins-07`（策略） |

`confidence` 不是种类（低置信的"突破"还是突破）。`status` 不是种类（被否的观察还是观察）。
**Hypothesis 只是 `confidence: low` + `user_status: unreviewed`**，不需要第 5 个类。

#### 2.4.3 为什么 Trend 不是实体

一条趋势需要多个可比的数据点。数据集里 18 个月只有 25 条证据、4 次零散测验 ——
**在这个密度下任何"趋势"都是把两个点连成一条线**。`adaptive-insight.md` §3 已明确不采用
「用概率/评分表达确定性」，Trend 只是换了个名字的评分。

⇒ Trend 是**视图**（对同一 `about` 下的解释按时间排），不是对象。

### 2.5 状态（V）

#### 2.5.1 它不在这套分类的对象里

`learner-state.md` §1 三条红线：状态派生、不缓存、不外流数值。
所以本文对第五类的规定只有一句：**状态没有实例，只有投影。**

| 投影 | 从什么算 | 能不能存 |
|---|---|---|
| Knowledge State | 证据 + 知识结构 | 否（每次现算） |
| Competency State | 证据（Reasoning/Artifact 类） | 否；且**产品今天算不出来**（见下） |
| Interest State | 兴趣记录 + 行为 | 否 |
| Goal State | 目标 + 里程碑 | 否 |
| Project State | 项目开发史 | 否 |
| Learner State | 上面五个的合成 | 否；**不是同级，是视图的视图** |

#### 2.5.2 Competency State 今天不存在，别假装它在

`evidence-flow.md` §7 已写清：短期答对 / 理解与解释 / 迁移 / 长期保持是四种不同性质的结果，
**仓库今天只能测第一种**。数据集里 25 条证据里 Reasoning 只有 4 条、迁移 1 条。

⇒ 把 Competency State 画成一张"能力地图"，在今天的证据密度下是编的。
它能以什么形态存在：**一组带日期的解释**（"10-05 那次迁移做到了 backdoor"），而不是一个状态面板。

#### 2.5.3 状态怎么"随时间变化"

`evidence-flow.md`:326 说 State Change 缺失，原因是状态不存历史。
本规范的答案：**变化不是对象，是比较**。要让它出现在时间轴上，只有一条路——
把某次判断写成一条带日期的解释（`ins-12` 就是这么来的），而不是给状态加一张历史表。

## 4 · 关系

### 4.1 最小集（11 条）

方向约定：`A --rel--> B` 一律读作"A 通过 rel 指向 B"，**每条关系只定义一次**，反向由视图算，不存两遍。

| 关系 | 从 → 到 | 语义 | 数据集实例 | 提案里有吗 |
|---|---|---|---|---|
| `engages_with` | Event → Object | 这次活动碰了哪个对象 | `act-004` → `mat-12` | ✅ |
| `belongs_to` | Event → Experience/Project | 这次活动属于哪段安排 | `act-112` → `prj-02` | ✅ |
| `produces` | Event/Project → Artifact | 做出了什么 | `act-102` → `out-10` | ✅ |
| `evidenced_by` | Interpretation → Evidence | 这条解释的依据 | `ins-12` → `ev-22` | ✅ |
| `supports` | Evidence → Interpretation | 支持 | `rel-06` | ✅ |
| `weakens` | Evidence → Interpretation | 削弱（不否定） | `rel-04`、`rel-07`、`rel-08` | ❌ **缺** |
| `contradicts` | Evidence → Interpretation（也允许 Interpretation → Interpretation） | 逻辑上不相容 | `rel-09`、`rel-10`；`ins-07` ↔ `ins-13` | ✅（需允许解释↔解释） |
| `qualifies` | Evidence → Interpretation | 加条件，不推翻 | `rel-05` | ✅ |
| `derived_from` | Interpretation → Evidence/Event | 由什么推出来的 | `ins-08` ← `act-091` | ✅ |
| `supersedes` | 任意 → 同类型 | 新版取代旧版（旧的仍在） | `cor-05` ⊃ `act-064.ts`；`ins-12` 的 `reinterpretation` | ✅ |
| `transitions_to` | Object → Object state | 生命周期翻转到哪 | `goal-02` → abandoned | ✅ |
| `merges_into` | Focus → Focus | 被吸收（两个都还在） | `foc-03` → `foc-02` | ❌ **缺** |

### 4.2 提案里被否掉的三条

| 关系 | 为什么不要 |
|---|---|
| `associated_with` | 它什么都能表示，所以什么也没表示。数据集里凡是需要它的地方，都能落到具体一条（`engages_with` / `belongs_to` / `derived_from`） |
| `evidenced_by` 与 `supports` 并存 | 同一个事实的两个方向。留 `supports`（带极性的那个），`evidenced_by` 由查询算 |
| `advances` | "推进了"没有可验证的语义。目标是 `transitions_to`，线索是时间重叠，项目是 `belongs_to` |

### 4.3 数据集的第五条极性：inconclusive

`rel-11`（`ev-21` 对 `ins-13`：不确定）在数据里存在。本规范**不把它做成关系**，
因为它回答的是"这次检验没测出来"，属于 `evidence.admission = ungradable`，不属于"证据对解释的态度"。

⇒ 数据集的 5 种极性收敛为 **4 种**：supports / weakens / contradicts / qualifies。
这是一处**对已写数据的建议性修正**，未落地。

## 5 · 正交维度

七个维度逐条对照数据集与既有决策。**没有一个是必填的**——`trajectory-inputs.md` §4 的纪律是"每类只用得上一种"。

### 5.1 Origin 来源

| 提案 | 问题 | 建议 |
|---|---|---|
| User / Lemma / External（三值） | 混了两个问题：**谁产生的** 与 **从哪个面看到的** | 拆两字段 |

- `produced_by`：user / lemma / third_party / external_system
- `observed_via`：A–F 六源（沿用 `trajectory-inputs.md` §2，不改）

数据集实证：`ev-20`（朋友的批评）`produced_by: third_party`，`observed_via: B`（他在 Lemma 里记下来的）。
用三值会把它归成 "User"（因为是用户录入的），那就把"朋友说的"变成了"他说的"。

### 5.2 Temporal 时间

| 值 | 用在哪 | 数据集实例 |
|---|---|---|
| Event Time | 全部事件 | `act-105.ts = 03-13`（事情发生时） |
| Recorded Time | 只有需要区分时 | `act-105.recorded_at = 04-22` |
| Revision Time | 对象被改过时 | `cor-05.revision_time = 07-02`；`prj-02.description_revisions[0].at = 06-02` |
| Effective Time | 只用于解释 | `ins-12.effective_from/to = 06-08 → 10-29` |

**加一个 `precision`**：`act-105.recorded_precision: day_uncertain`。
"三月中某天"和"3 月 13 日 16:20"不是同一种事实，缺了精度就只能二选一（要么假装精确，要么丢掉）。

### 5.3 Epistemic 认知状态（四值）

提案：observed / self-reported / inferred / hypothesized。建议改为：

| 建议值 | 含义 | 数据集实例 |
|---|---|---|
| `observed` | 系统看见了 | `ev-01` |
| `stated` | 有人说了（不等于真） | `ins-01`、`ev-18` |
| `inferred` | 系统推出来的 | `int-04`、`ins-12` |
| `imported` | 从外部系统搬来的 | `ext-01` |

理由：`self-reported` 与 `stated` 重复，而 `hypothesized` 是**置信度**不是认知状态——
一个"假设"如果是系统推的，`epistemic` 仍然是 `inferred`，只是 `confidence: low`。
`imported` 是提案里没有但数据集必需的值（6 条外部记录）。

### 5.4 Confidence 置信度

只允许 `high / moderate / low / unknown`，**不允许数字**（`learner-state.md` §1）。
必须带 `basis`：凭什么给这个置信度（数据集 100% 有 `confidence_basis`）。
`ins-13` 是反例教材：`confidence: high` + `basis: 提交历史与活动计数一致` —— 它仍然错了。

### 5.5 Lifecycle 生命周期

| 提案 | 建议补充 | 为什么 |
|---|---|---|
| Active / Paused / Completed / Abandoned / Resumed | **+ Absorbed** | `foc-03`、`foc-05` 是被吸收，不是完成也不是放弃 |
| | **+ Retired** | `int-07`（兴趣退役）、`ins-10`（解释撤回）与"放弃"不是一回事：放弃是他决定的，撤回是条件不成立了 |

另外，生命周期**必须允许"关了还能收到活动"**：`foc-01` 在 5-26 关闭，`act-131`（6-07）、`act-135`（10-24）仍在它名下。
`to` 是描述性的，不是闸门。

### 5.6 Provenance 出处

必须能回答三件事：① 这条从哪来（`observed_via`）；② 它由什么推出（`derived_from`）；
③ 它被改过几次（`revisions[]`）。**第四条：推断用了哪条规则**——`adaptive-insight.md` §4.2 是纯函数三步，
所以一条系统解释必须能说出它走的是 S1/S2/S3 哪一步。数据集缺这个字段，是**已知缺口**。

### 5.7 User Control 用户控制

| 提案 | 建议补充 | 数据集里的数量 |
|---|---|---|
| Confirmed / Corrected / Rejected / Withdrawn | **+ Unreviewed** | 8 条系统解释里 4 条从未被看过 |
| | **+ Partially corrected** | `ins-05`：他只改了周数，没回应结论 |

`unreviewed` 是最重要的一值。没有它，"系统没被否"会被读成"系统是对的"——
而数据集里 4 条未审的解释中，有 1 条（`ins-13`）明确是错的。

## 7 · 未决问题

1. **`ext-*` 要不要拆成逐条事件？** 不拆，轨迹永远看不到"哪天提交了什么"；拆了，一次导入会淹没一周。
2. **自述到底进 III 还是 IV？** 本文选 IV（§2.3.3），但与提案相反，且会影响已有的 `ev-18`。
3. **Competency State 在没有迁移测量的情况下，能不能以任何形态出现？** 本文的答案是"只能以带日期的解释出现"。
4. **一条解释能不能被"部分撤回"？** `ins-05` 的 `partially_corrected` 是用户控制值，不是解释的语义状态。
5. **同一件事被两个来源描述时怎么合并？**（`trajectory-inputs.md` §5 问题 6 至今没有规则）
6. **Focus 允许完全没有兴趣对应吗？** 数据集说"允许"（`foc-04`），产品词表未必接受一个"没有主题的线索"。
7. **`loose_cluster` 算不算一个对象？** 本文说它是视图；但如果没有它，8 条因果活动就无处安放。
