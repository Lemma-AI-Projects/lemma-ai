## 4 · 结构冲突清单（本研究最重要的产物）

不是"文档不一致"，是**两条战略同时成立但互相排斥**。每条都标了"必须由谁拍板"。

### C1 · 公共基础设施 vs 消费级平台

- **A 侧**：「为人类的新纪元搭建学习基础设施」（B2）、「为人类的 AI 教育发展做贡献」（`官网计划.md:16`）。
- **B 侧**：「面向终生学习者的学习平台」（B1），Slogan 是「驰骋千里，世界尽在脚下」。
- **冲突**：基础设施的客户是**机构**，评价者是**同行与标准**；消费平台的客户是**个人**，评价者是**留存与付费**。两者的护城河完全不同（制度合法性 vs 使用习惯）。
- **必须拍板**：谁是你的"评价者"。这决定了 `04` 里所有案例里哪些可迁移。

### C2 · 任何人都能学 vs 认同需要边界

- **A 侧**：「任何学科，从西班牙语到分析哲学」（`产品战略.md:26`）、「受众广泛的平台」。
- **B 侧**：身份认同的社会学前提是**内外之分**（`03` §2）。对所有人说话的产品产生偏好，不产生认同。
- **冲突**：**广度与身份在结构上互斥。** 这不是执行问题，是定义问题。
- **⚠️ 但创始人自己试过一个解法**：`2026.8.27关于Lemma AI设计的新想法.md` 写「入口很小，但是受众广泛的切入口」。这是**唯一一处**正面处理这个张力的材料 —— 它把"广"放在用户数上，把"窄"放在入口上。问题是：入口窄不构成**边界**（谁都能进来），所以它解决的是获客，不是认同。
- **必须拍板**：是否接受"核心用户是一小撮人，其余是使用者"。

### C3 · Agent 主导 vs 社区共创

- **A 侧**：「用户永远不'选择 Method'」（`method-system-design.md:198`）、Agent 主导判断（`agent-principles.md:16`）。
- **B 侧**：社区的定义性特征是成员**自己决定做什么**（`03` §3）。
- **冲突**：一个用户不能选择学习方式的产品，其用户没有可共创的对象。**共创需要一个用户能改的东西。**
- **必须拍板**：允许用户改什么？（现在什么都不可改。）

### C4 · 产品层排除社区 vs 组织层押注社区

- **A 侧**：B18–B21，四条排除条款。
- **B 侧**：`跃迁战略.canvas` 里 Lemma X / Hippy / Base / Discord 四个 group，占整张图的大半。
- **冲突**：**社区在组织层是核心，在产品层是禁止项。** 两者之间没有任何接口。
- **【事实】补充**：`.workbuddy/research/` 34 份设计文档里，**没有任何社区/共创/UGC 的正向主张**，只有排除条款（见 `02` §7 索引复核）。
- **必须拍板**：社区长在产品**外面**（Discord/线下/黑客松），还是长在**里面**？现在选了外面，但没人写下这个选择。

### C5 · 社区是"分派下来的任务"，不是"想清楚的东西"

- **【事实】** `8.26任务分配.md:3`：Ceaser 的任务列表第一项就是「**社区建设**」。这不是后来倒推的。
- **【事实】** 两个月后，可查到的社区产物是：一个 Discord 邀请链接（`官网计划.md:97`）、canvas 上四个 group、一句「Seed User Group」（`Deck:94`）、一个只有标题的「Lemma Hippy 的申请条件」（`Deck:98`）。
- **【事实】**「私人研究材料」：47 篇日记里**没有任何一篇**讨论用户共同体、社区运营、外部社群。唯一近似的一处是把"张力/贡献/协同"当作**产品内反馈机制**来设计，并自问会不会变成"教育版 IG"。
- **【推断】** 所以真正的问题不是"社区被忽略了"，而是：**它被认领了，但没人把它想过一遍。** 一个被分派但没有定义的任务，会稳定地停在一个链接上。
- **为什么重要**：这类任务最容易在融资材料里变成一句空话，因为它**看起来有人负责**。

### C6 · 艺术家 vs 基础设施

- **A 侧**：「我们更愿意称自己为艺术家」（B9）。
- **B 侧**：「基础设施」（B2）。
- **冲突**：艺术家的价值来自**稀缺与品味**（少数人懂）；基础设施的价值来自**普遍与可靠**（所有人用）。**两种自我叙事要求两种完全不同的组织。**
- **【推断】** B9 是真的（日记里反复出现"希望人们把它当艺术品"「私人研究材料」），B2 是后来的（官网）。**后写的那个不一定更真。**

### C7 · 互补 vs 逃逸

- **A 侧**：「和 altman 成为互补产品」（B7）。
- **B 侧**：「保持逃逸速度」（B6）。
- **冲突**：**互补品的身份由主品定义。** 被定义为"OpenAI 生态里的教育应用"，就等于把分类权交给对方 —— 这在定义上就是没逃逸。
- **【推断】** B6 与 B7 不能同时为真。这不是措辞问题，是两个战略方向。这一条在 `03` §5 与 `05` 里会被反复用到。

### C8 · 内部评估说"没有护城河"，融资叙事需要护城河

- **【事实】**`.workbuddy/research/learn-space-design-assessment.html:937`：「产品在早期几乎没有护城河……**不能拿'机制不可复制'去融资**」；`:942`：「**不能防复制，只能靠先开始**」。
- **对比**：`For A16Z Pitch Desk Outline.md:78` 把 `Defensibility` 列为四大模块之一。
- **冲突**：**内部最清醒的那句话，正好否掉了对外的必要模块。**
- **这不是矛盾，是缺口。** 本系列 `05`/`07` 的全部工作就是填这个缺口——或者诚实地宣布填不上。
- **注意**：那份评估是 Agent 写的（标了 `INFERENCE`），**不是创始人原话**。它的价值在于它是仓库里唯一一处把这件事说穿的地方。
