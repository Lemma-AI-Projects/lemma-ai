# Eval Taxonomy V1：技术调研报告评估（对标式）

> 2026-10-26 · v1 取代 v0。
> **v0 的问题**：20 个指标打分加权，是一套**合规性检查**——它能查出"没写什么"，
> 查不出"写了但不可信"。用户判定：形式主义。v1 改为**内容导向的四步评估**：
> 每一步产出的都是**具体的技术事实或设计问题**，不是分数。

---

## 四步法

### Step 1 · 技术对标（Claim-by-Claim Benchmark）

把报告的**关键技术断言**逐条拎出来，对标到三种可信度等级的证据：
官方文档 / 仓库代码实测 / 第三方转述。不允许"我记得是这样"。

输出：断言 → 证据 → 判定（✓ 成立 / ⚠️ 成立但未实测 / ✗ 不成立）。

### Step 2 · 体验审查（UX Walk-through）

**按报告推荐的交互模型，把自己放进学习者位置走三个场景**，回答三类问题：
- 学习者此刻的心智模型是什么？（他知不知道自己在文档里还是在活动里？）
- 每个界面元素出现时，学习者被要求做什么？（打断成本实测推演）
- 被忽略的元素后来怎么样了？（生命周期）

### Step 3 · 可行性推演（Feasibility Walk）

从**当前代码**出发，沿推荐路线逐站走，问"这一步真正的工作量与卡点是什么"。
专打"简洁接口掩盖真实成本"的表述——原语越少，越要数清每种实例的成本。

### Step 4 · 盲点扫描（Blind-spot Scan）

列报告**没写、但一旦为真会迫使架构更改**的主题。按"咬人程度"排序。
盲点比错误更危险：错误会被审出来，盲点会活到实现阶段。

## 首例应用 ·《Focus Mode 技术调研报告》评估（2026-10-26）

### Step 1 · 技术对标

| 报告断言 | 对标证据 | 判定 |
|---|---|---|
| ProseMirror/Tiptap 支持"锚随编辑变换"（position mapping） | PM 官方文档：`Transform`/`Mapping`/step 模型是核心机制 | ✓ 成立（报告应补 API 级引用） |
| tldraw 有 Chat starter kit / make real | tldraw 官方站点 | ✓ 成立 |
| NotebookLM closed-corpus + 逐条源引用 | Google 公开特性 | ✓ 成立 |
| 三段复核锚（position+quote+occurrence）仓库已有原型 | `focus/blockOps.ts` | ✓ 成立（实测过） |
| 整页删重插与锚定结构性冲突 | `doc_service.py:216` 实测 | ✓ 成立 |
| **Tiptap 是"最快验证"路径** | **未实测**——这正是 E1 要回答的问题 | ⚠️ 报告把它写成推荐理由，措辞过强；应写为"假设，E1 验证" |
| GenUI 三模式 / 五级自主权 / 七种共存 | 厂商博客与顾问文章（Zooz/Zylos），非学术 | ⚠️ 成立但来源等级低，报告未标注 |
| SWITH 零命中 / episodes 零调用 | `VISION_GAPS` A3/A5 实测 | ✓ 成立 |

### Step 2 · 体验审查（三个报告没回答的问题）

1. **双层模型的心智问题**：引入块层 + 活动层后，学习者如何知道"我在改文档"还是
   "在活动里"？Proposal B 的答案干净（活动即一切）；块层引入后**文档感会回流**，
   两个原型的心智模型不一致——这是合流时最大的体验风险，报告没讨论。
2. **L2 提示的生命周期**：就地提示被忽略后——堆叠？过期？随滚动消失？
   报告只说"不自动升档"，没说收敛。三个堆叠的 L2 就是视觉噪音。
3. **干预的降档路径**：报告只写了"不升档"，没写"什么时候降档"（Agent 发现自己
   判断错了，已发出的 L3 怎么收？）——U6 说撤回一步就够，但跨"建议→采纳"的
   撤回语义没定义。

### Step 3 · 可行性推演（三处"简洁掩盖成本"）

1. **`propose(move, anchor, payload)` 的真实成本是 O(块类型 × move)**：
   原语只有 4 个，但每个 move × 每种块类型的建议卡都是一个独立组件
   （反例卡/练习卡/可视化卡/高亮卡……）。报告说"声明成本一个 dataclass"——
   **那只是 moves 字段的成本，不是 propose 的成本**。
2. **Tiptap 迁移没有迁移清单**：现有五类块（heading/quote/练习/公式/分割线）
   映射到 Tiptap nodes，其中**公式与练习是自定义节点**——工作量集中在它们身上，
   报告的"中"没有拆到这个粒度。
3. **R4（Agent Integration）的进入条件漏了 C2 埋点**：Agent Initiative 的最小前提
   是"读到哪"信号（VISION_GAPS C2，零命中）——报告在 §2.3 指出了缺口，
   却没有把它列为 R4 的进入条件。**不改，R4 的主动干预全是伪触发。**

### Step 4 · 盲点扫描（按咬人程度排序，全部为报告零提及）

| # | 盲点 | 为什么会咬人 |
|---|---|---|
| **1** | **数学公式渲染**：KaTeX/MathJax 与块编辑器的集成、公式内部锚定 | Lemma 的主场景是数学（特征向量原型全是要点）；公式渲染方案不定，编辑器选型**不完整**，且公式内的锚定（锚到"等号右边那一项"）比文本锚更难 |
| **2** | **LLM 成本与调用策略**：Agent Initiative 意味着模型调用**不再由用户发起**——触发频率、批量策略、预算上限全部未讨论 | 主动性的商业模式与产品节奏都卡在这里 |
| **3** | **性能**：长文档（50+ 块）+ N 个交互组件（SVG 实验可视化）同屏渲染 | 画布原型只有 3 个元素，没有任何性能证据 |
| **4** | **建议卡生命周期**：L2/L3 卡片何时过期、更新、堆叠 | 与 Step 2-2 同源，但这里指实现层（内存/重渲染策略） |
| **5** | 多语言锚定（中文学习英文材料、全角/RTL 边角） | quote 复核在跨语言粘贴时的假阴性 |

### 评估结论

报告的**主干判断依然成立**（Hybrid 两步走、四原语、E1 优先、AIRIS 控制分配）——
对标没有推翻任何核心架构选择。但：

1. **三处措辞强于证据**（Tiptap 推荐先于验证、GenUI 来源、引用等级）；
2. **三个体验问题未回答**（双层心智、L2 生命周期、降档路径）；
3. **三处可行性成本被掩**（propose 卡片矩阵、迁移清单、R4 前置条件）；
4. **五个盲点**（公式渲染最重）。

**处置建议**：报告作为**方向性讨论稿**成立；进入 R1 实验排期前，必须补
§盲点 1（公式渲染入选型矩阵）+ R4 进入条件修正 + 三场景成章（沿 v0 红线 X1）。
图（v0 的 D2 红线）维持待补。
