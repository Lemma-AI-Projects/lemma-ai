## 0 · 一句话

把"当前学习活动"变成主界面对象，让 Agent 的内容**长在工作区里**，而不是长在聊天里 ——
用一条 `/preview` 路由把这件事做出来给人点，然后才谈要不要动真页面。

用全局 store 反而让"删掉这个原型"变难。

## 5 · 交互式可视化（唯一必须真做的东西）

**数学**：固定矩阵 `A = [[2,1],[0,1]]`，用户拖 `φ` 决定 `v = (cos φ, sin φ)`，
实时算 `Av`，画两条箭头 + 夹角。

**为什么这个矩阵好**：它有两个特征方向（λ=2 的 x 轴、λ=1 的 (1,−1)），
用户拖着转一圈会**遇到两次"对齐"** —— 那一下就明白"特征方向是少数几个方向"。

**判定**：`|sin(θ_Av − θ_v)| < 0.02` 视为同向，箭头变赭色 + 出现一句「对上了」。
反向（夹角 ≈180°）也算对齐（λ 为负），文案写"反向拉长"。

**实现**：一个 `<svg viewBox="0 0 480 360">`，画网格线 + 两条带 `marker-end` 的线。
坐标变换：数学坐标（y 向上）→ SVG（y 向下），`sy = cy - y * scale`。约 80 行。

**不做**：动画过渡、矩阵格子输入、3D、可拖拽箭头。一个滑杆 + 实时重画足够回答"这个概念能不能被摸到"。

## 6 · 模拟 Agent Move（Stage 3）

**触发**：工作区底部一个按钮 `模拟 Agent 提议`（明确带"模拟"二字）。

**插入什么**：一张卡片，内容是**基于当前活动主题**的一个换角度提示 ——
「如果 A 把整个平面压扁成一条线（det A = 0），还剩几个特征方向？」+ 一个可展开的小图。

**三条硬约束**：
1. **不声称它观察了用户**。文案里不出现"你刚才…"（现有 `ADAPTIVE_INSIGHT_V0` 的同类风险）。
2. **卡片带徽章**：`模拟 · 不是真实 Agent 判断`，且说明"这条内容和你的操作无关"。
3. **只插一次**：插入后按钮变灰；撤销后可以再插（`insertedVisible` 复位）。

**撤销**：卡片右上 `撤销这条` → 卡片消失，**工作区其它内容与可视化状态（φ、选项）全部不动**。
这本身就是一条验收：撤销不该重置别的。

## 7 · Chat 模拟（Stage 1 就到位）

- 输入框回车 → 追加一条 `role: 'user'` 消息 → **700ms 后**追加一条预置回复。
- 回复选择：关键词命中（`特征|eigen`）→ 讲特征向量的那条；否则 → 通用那条。
- **每条 Agent 气泡上方有 `模拟` 小字**，且回复文案不自称理解用户。
- 不做流式、不做真实调用、不做"正在思考"的假进度。

## 11 · 风险与没定的事

| 风险 | 我的处理 |
|---|---|
| 原生 range 跨浏览器样子不一 | 用 `appearance-none` 自绘；只在 Chrome 验（本机只有 Chrome），并在报告里写明"未验 Firefox/Safari" |
| 新页面和 `/preview/focus` 混 | 路由名 + 页面角标 `Proposal B · 原型`；报告里也说清"这是另一条路，不是替代" |
| 可视化太重会变成"做数学工具" | 只做一条滑杆、一个矩阵、两条箭头。矩阵可调 = 不做 |
| 模拟插卡容易被误读成"Agent 真在判断" | 徽章 + 明确文案 + 按钮名带"模拟" |
| 两栏折叠在窄屏挤坏 | 1120 宽截图验收；两栏都收时主区仍 ≥ 640 |

**没定、需要你拍的**：
1. 两栏**默认开还是默认收**？我选默认开（评审一次看到全貌）；真产品里可能默认收。
2. 插入的卡片**能不能再点展开**（我打算给一个小折叠看 det=0 的图）—— 加这一层会让 Stage 3 多半天。
3. 检查题**答错要不要给反馈**？我倾向：只在选对时淡淡标一下，选错不纠正（避免假装教学）。

### 验收结果（`.workbuddy/localdb/verify_focus_activity.mjs`，22 条断言）

Stage 1 九条（版面/折叠/对话）· Stage 2 六条（SVG 存在、30° 未对齐、0° 与 315° 各自对齐
且 |Av| 分别为 2 与 1、90° 回到未对齐、检查题判分）· Stage 3 七条（徽章写全、无"你刚才"、
撤销后 φ=45 与选项不动、可重插）。

### 过程中抓到的两个真 bug（都是断言抓的，不是眼睛）

1. **撤销后按钮永久变灰**。第一版撤销只藏卡片、不重置 `moveInserted`，
   "撤销后可再插一次"成了一句空话。修法：撤销 = 整个循环重置。
2. **截图滚错容器**。页面本身不滚，滚的是中栏的 `main`；`window.scrollTo` 无效。
   （这条是验证脚本的问题，不是产品问题，但同样只有真驱动才暴露。）

### 数学上改过的一处

断言初版把 φ=315° 写成"对上了（反着）"—— **错了**：λ=1 是正的，(1,−1) 方向上 Av 与 v
**同向**且 |Av|=1。修正后的断言反而更有区分度：0° 与 315° 分别钉住 λ=2 与 λ=1。

### 已知限制

- 插入的内容是**写死的卡片**：这一轮验的是**落点、撤销、不打断**，不是"Agent 能不能决定插什么"。
  那个问题在研究决策日志里仍是 Open（Q2），本原型不回答也不假装回答。
- 滑杆只在 Chrome 验过（本机没有其它浏览器）。
- 不验学习效果（L5）—— 一屏原型连 L4 都只是"看着顺眼"。
- `AgentMoveCard` 的展开答案是**写死的正确结论**，不是按用户状态生成的。

### 下一轮交互设计的建议（按价值排）

1. 把 Stage 3 的按钮从"模拟"换成**由真实信号触发**（哪怕是最笨的规则）—— 那才会第一次
   产生"该不该插"的真实数据（对应研究决策日志 Q3）。
2. 卡片加"有用 / 没用"两个小按钮 —— 第一个能被学习者评价的 Learning Move。
3. 左栏的"上一个活动"从展示变成可切 —— 验"活动之间怎么走"。
