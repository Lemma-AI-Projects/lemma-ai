## 0. 什么时候该读这篇

当你要让**另一个** Experience 会说话或会听话时——
Learn Space Voice、Focus Voice、Global Voice、题库朗读……

今天的现实是：**语音层只服务 Free Course 一个 Experience**，
而且实现内联在播放 Hook 里（`useTeachingPlayback.ts:128-153`）。
所以你接第二个 Experience 时，**第一件事不是写代码，是先做下面的四问。**

---

## 1. 适配器四问（先回答，再动手）

### 问 1：这个 Experience 有"句"的概念吗？

语音的时序建立在**切句 + `cue` 绑定**上（[02-contract.md](02-contract.md) §6）。
- **有**（像 Free Course 的 `narration` + 白板动作）→ 可以直接复用现有时序契约。
- **没有**（比如一段连续朗读的文档）→ 你需要**先定义"什么是一个可读单元"**，
  否则时长基准、打断粒度、恢复位置全都无处附着。

### 问 2：它的内容从哪来，谁决定下一段？

**Voice 不决定内容**（[01-overview.md](01-overview.md) §2 边界 1）。
- 如果这个 Experience 的内容是**已经定好的**（读一段文本、念一道题）→ 天然合规，直接用。
- 如果它需要"边说边决定说什么"→ **那不是语音层的事**，是 Agent 的事。
  语音层只负责把已经定好的东西读出来。

### 问 3：它需要"听"吗，还是只需要"说"？

**这是最省事的一刀。** 今天 ASR 完全不存在，**只做"说"的接入成本远低于做"听"**。
- 只需要说 → 接 TTS 通道即可，不碰麦克风权限、录音、上传。
- 需要听 → 额外承担：权限拒绝率、浏览器兼容（`MediaRecorder` 编码差异）、
  转写准确率、上传延迟。**先问清楚这一条，能省掉一半工作。**

### 问 4：它有自己的停点吗？

Free Course 的停点来自 `step.question` 和 `awaitClick`（[02-contract.md](02-contract.md) §6.4）。
- 有停点 → 必须同时回答：**停多久算没回应？**（否则重复今天"永远等"的问题）
- 无停点（一路读完）→ 不需要 `no_response`，但也就没有交互。

## 2. tier 选择：这个 Experience 该用哪种实现

| 场景 | 该用 | 理由 |
|---|---|---|
| 内容短、要求快、可以接受机器音 | `browser` | 零成本、零延迟 |
| 要求音色统一 / 要记账 / 要限流 | `remote` | 唯一能统一音色的路 |
| 用户静音、或环境不支持 | `silent` | 保底，保证时间线不崩 |

**约定**：Experience **不自己选**实现，只声明"我需要语音"，
由 Runtime 按降级链决定（[02-contract.md](02-contract.md) §2）。这样换实现不用改每个 Experience。

## 3. 检查清单

- [ ] `speak` 的 `onEnd` 在所有路径下必达，且只有一次（[02-contract.md](02-contract.md) §8 不变量 1）
- [ ] `available === false` 时 UI **可见地**告知，不静默降级（不变量 3）
- [ ] 打断会**取消在途请求**，不只是停播已下载部分（不变量 4）
- [ ] 语音层**不产生** signal，只转发（不变量 2）
- [ ] 没有把语音的计数渲染成任何掌握度 / 百分比（不变量 5）
- [ ] 时长基准写清楚了：估算还是真实时长（[02-contract.md](02-contract.md) §6.3）
- [ ] 有停点的话，定义了超时策略
- [ ] 切句规则与后端一致（今天两侧各有一份：`sentences.ts:18-44` / `planner.py:47-81`）
- [ ] 新增可朗读字段已登记进 [02-contract.md](02-contract.md) §5

## 4. 反模式（今天已经存在或极易踩）

| 反模式 | 为什么错 |
|---|---|
| **在 Experience 里直接 `new` 一个 voice** | 今天就是这样（`useTeachingPlayback.ts:128-153`）。第二个 Experience 只能复制这段 |
| **让语音决定下一段讲什么** | 越界。Voice 是 delivery 层，不是决策者 |
| **`available === false` 时隐藏控件** | 今天就是这样（`SessionRail.tsx:119-133`）。用户听到一片寂静、界面毫无提示 |
| **删掉 `createBrowserVoice`** | 等于删掉降级路径，违反"语音失败 ≠ 课程失败" |
| **把 `PlaybackPhase` 和传输状态合并** | 二者正交，合并会立刻产生"在听但没在等"的歧义 |
| **只做"听"不做降级** | 权限被拒 / 不支持时用户会以为产品坏了 |
| **语音偏好写进 `UserHomeItem`** | 那是列表形态（自由文本短语），单值枚举放进去会污染语义 |
| **把语音用量记进新表** | 已有 `ai_usage_logs` ledger，复用即可 |

## 5. 一句话

**接一个新 Experience = 回答四问 + 走一遍检查清单。**
如果发现要改 `Voice` 接口才能接进去，先停下来——
**接口是为多个 Experience 共用的，不该为某一个让步**。
