1. 项目概览

结论先行

LemmaKnowledgeBase = Trilium Notes（TriliumNext 社区版）——一个功能极其完整、成熟的开源层级知识库应用。它不是"画板/笔记玩具"，而是一个可支撑 10 万+ 笔记 的生产级系统。

定位判断：这不是"借一个模块"，而是"搬一整个成熟产品内核"。它的价值在于：把 10 年积累的知识库能力（层级树/克隆/属性/脚本/图表/加密）一次性带来；成本在于：它自带一套完整的前后端与同步体系，必须做大规模裁剪才能融入 Lemma 的架构。

当前 Lemma 知识库：`frontend/src/features/knowledge/` 是纯 mock（74 行假数据文件列表），无后端、无层级、无搜索。差距 = 从"展示型文件列表"到"可承载 10 万笔记的引擎"。

3. 核心架构

三层缓存 · 实体 · 同步 · widget

3.1 三层缓存系统（数据访问铁律）

层位置作用
Becca服务端实体缓存becca.notes[noteId]；缓存方法自动产生 EntityChange 供同步
Froca客户端镜像WebSocket 同步；froca.getNote()
Shaca分享/发布缓存公开笔记优化

3.2 实体系统（6 类核心实体）

  • BNote — 笔记（title/type/mime/isProtected/blobId）
  • BBranch — 树形关系（多父克隆：一条笔记可挂多个位置）
  • BAttribute — 属性（label 标签 + relation 关系，可继承）
  • BRevision — 版本历史
  • BBlob — 二进制内容存储（内容与元数据分离）
  • BOption — 应用配置（同步选项系统）

3.3 同步协议

HMAC 认证 + EntityChange 增量推拉 + 内容 hash 校验——这套同步体系与 Lemma 的 Supabase Auth 冲突，集成时应整体剥离（Lemma 数据天然多端在线，不需要自建同步服务器）。

3.4 Widget 系统（前端 UI 范式）

  • BasicWidget / NoteContextAwareWidget / RightPanelWidget — jQuery 基类
  • type_widgets/ — 每种笔记类型的渲染器
  • 可复用 Preact 组件：Table(Tabulator) / Calendar(FullCalendar) / Dropdown / Badge / Form 系列
  • 命令注册表 + 快捷键 + 全局菜单

6. 功能全景

编辑器 · 搜索 · 脚本 · 图表 · 同步 · 加密

6.1 编辑与内容

  • 富文本 WYSIWYG + markdown autoformat + 表格 + 图片 + KaTeX 数学公式
  • 代码编辑器（CodeMirror）+ 语法高亮
  • Excalidraw 画布 / Mind Elixir 思维导图 / Mermaid / 关系图 / 笔记图 / 地理图
  • Univer 电子表格（Excel 级）
  • 版本历史（revisions）+ 差异对比
  • 笔记加密（per-note protected）

6.2 搜索（37 种表达式）

全文搜索 + 结构化查询：#标签 / ~关系 / ancestor: / descendantOf: / property: / noteContentFulltext: / orderBy:…… 这是知识库"可查询性"的核心资产。

6.3 脚本系统

  • 后端脚本 API（backend_script_api）+ 前端脚本 + 服务端脚本
  • 脚本笔记可创建/修改/查询任意笔记——知识库的自动化能力
  • Render 笔记类型 = 脚本渲染动态输出

6.4 协作与发布（裁剪项）

  • 自托管同步服务器（HMAC + EntityChange）— 剥离
  • 公开分享发布（Shaca）— 剥离（或按需保留只读分享）
  • Web Clipper 浏览器插件 — 剥离
  • OCR 识别 — 可延后

7. API 与接口

ETAPI · 内部 REST · WebSocket

7.1 ETAPI（外部 API，basic auth）

/etapi/notes / /etapi/create-note / /etapi/attributes / /etapi/branches / /etapi/revisions / /etapi/search…… 基于 token 的自动化接口——可整体复用为 Lemma 的"知识库写读 API"蓝本，只需把认证从 etapi_token 换成 Lemma 的 Supabase JWT。

7.2 内部 REST（apps/server/src/routes/api，29 文件）

clipper / database / files / llm_chat / login / metrics / ocr / options / totp / etapi_tokens…… 内部 API 信任前端，集成时按 Lemma 路由体系重挂。

7.3 WebSocket（ws.ts）

实时同步 + Froca 客户端缓存——Lemma 若走 REST + React Query 即可不引入 WS。

11. 怎么魔改（Lemma 化）

四大改造面

11.1 存储层：SQLite → Supabase PG

  • notes/branches/attributes 三表映射到 PG，加 user_id + RLS 行级安全
  • blobs 内容 → Supabase Storage 或 PG bytea；附件同理
  • revisions 保留；entity_changes 删除

11.2 认证：etapi_token → Supabase JWT

  • ETAPI 的 CRUD 蓝本保留，认证中间件换成 Lemma 的 get_current_user
  • 所有查询强制 user_id 过滤（沿用 Lemma IDOR 红线）

11.3 UI：Trilium 皮肤 → Lemma zinc 风格 + React 接管

  • Widget jQuery 系统 → 可在 Lemma React 应用中按"知识库 tab"嵌入
  • 复用 Lemma 现有组件体系（ui/button、card、i18n）
  • i18n：Trilium 自带中文翻译 → 并入 Lemma 的 en/zh.json

11.4 与 Lemma 独有能力融合（差异化价值）

  • Board 融合：canvas 类型 ↔ 现有 tldraw Board + 语义画板（S1/S2 已完成）
  • 伴学联动：llmChat 类型 ↔ C1 agent 人格；讲解落成知识笔记
  • learner 集成：知识笔记 ↔ learner L2 knowledge_nodes 双向投影（评估框架 L4/L5 后续）
  • 课程/空间：book 类型 ↔ 课程 & learn space 容器

13. 风险与决策

诚实评估

风险登记

风险影响缓解
