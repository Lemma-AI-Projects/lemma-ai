L4 实时双向语音层 — 调研与实施计划

Lemma AI · 最低耦合方案 · 2026-09-13 · 仅调研与规划，未开工
人话结论：L4（学生随时插话、agent 随时接、像打电话一样的口语家教）不是把 L2+L3 拼起来，而是整条链路要压到实时全双工。 2026 年业界有两条路线：端到端语音模型（GPT-4o Realtime / Gemini Live，模型自己听自己说）和 级联流水线（STT→LLM→TTS，各段可换）。对咱们最划算、耦合最低的选择是级联 + 复用现有大脑—— 语音只是包在现有 AIClient 外面的一层 I/O 壳，现有文本管线一行都不用改。

1. 调研：2026 年 L4 两条技术路线

维度端到端语音模型级联流水线（推荐）
代表 GPT-4o Realtime、Gemini Live、Moshi、Hume EVI、NVIDIA PersonaPlex、字节 Seeduplex LiveKit / Vapi / Pipecat +（Deepgram/Speechmatics 做 STT）+（Cartesia/ElevenLabs/Azure/Gemini 做 TTS）+ 任意 LLM
怎么工作 单一语音模型音频进、音频出；转写/思考/发声都在模型内部，原生处理打断(barge-in) 麦克风音频→STT 转文字→咱们现有 LLM 生成→TTS 合成语音→播放；三段串行可并行流水
延迟 首包 200–500ms（GPT-4o 实测 232–320ms 均值；Gemini 2.5 Flash Native 0.63s） 最佳组合（Cartesia+TTS+Groq Whisper+Cerebras）≈300ms；平均生产栈 600–1000ms；压到 <600ms 才自然
成本 / 分钟 GPT-4o Realtime ≈ $2–4；Gemini Live ≈ $0.5–2 ≈ $0.10–0.30（自选组件，远低于端到端）
能否复用咱们的大脑 不能 LLM 被厂商锁死，课程上下文/掌握度注入只能靠 system prompt / 转写，工具调用不成熟 能 LLM 段就是现有 AIClient.stream_chat(COURSE_COMPANION)，路由/回退/计费/上下文全复用
可审计 / 可调试 弱 无中间文本，日志只能看音频；合规与排错困难 强 三段各自有文本边界（转写/回复/合成输入），天然留痕
打断(barge-in) 模型原生处理，质量好 需自建 VAD + TTS 急停 + LLM 取消（<150ms 总预算），工程量大但可控
对语言学习的关键影响 发音/口音评测(L3)无法介入；换音色/换语言受限 STT 可选多语种抗口音（Whisper/Speechmatics）；TTS 可精调目标语言发音；L3 发音评测以后能直接挂在同一链路
为什么推荐级联而不是端到端？ 三个理由叠在同一选择上：①耦合最低——大脑（现有 LLM 网关、课程上下文、掌握度注入）原封不动复用，语音只是边缘 I/O； ②最便宜——端到端是级联的 10–40 倍单价，对创业团队不友好；③课程接地——agent 必须始终基于课程材料说话，端到端模型会把它变成"通用聊天嗓"，丢掉咱们的研究内核。 端到端适合"纯陪伴/客服"，不适合" grounded tutor"。

2. 耦合分析：复用 vs 隔离矩阵

这是本计划的核心。绿色=直接复用、零改动；蓝色=新增但共享；红色=新增且隔离。

ai/routing.py · 路由与优先级回退复用·零改 LLM 段沿用现有 AiHubMix/OpenRouter/DeepSeek 回退铁律

一句话耦合目标： 现有 backend/api/v1/{overview,companion,chat}.py 与 ai/client.py 零改动；voice 作为平行模块，只通过 AIClient 的公开文本接口和 persist_turn 两个"门"接入。把"大脑"当黑盒，把"嗓子和耳朵"当可插拔外设。

3. 推荐架构：级联 + 大脑复用

关键决策修正：区域感知路由（2026-09-13 更新）

用户面向全球，故不再"默认国内栈"。正确架构 = 区域感知语音 I/O + 中国可控大脑（region-aware voice I/O, China-controlled brain）：

  • 大脑永远在中国主体：LLM 推理（基于课程上下文 + 掌握度）走现有 AiHubMix→Gemini / OpenRouter / DeepSeek 网关，战略 IP 零改动、永不出境。
  • 语音 I/O 按用户区域路由：中国用户 → 火山 / 阿里（数据留境内）；美 / 欧 / 全球用户 → Deepgram + Cartesia（外语口音最强、就近延迟最低）。VAD = 本地 Silero 全局通用。
  • 红线仍满足：掌握度 / 学习者档案 / 课程 = 战略数据留中国主体 PG / Supabase；语音音频为临时 I/O，海外 API 属"阳光出海"（合法商用），非"泡澡式出海"（设壳公司规避监管）。
  • 出海合规作业：若音频跨境持久化 → 数据出境评估；技术进出口申报；与海外厂签 DPA。尽量 ephemeral 不落盘以降低负担。
  • 开发现实：本机 OpenRouter 曾 403，美国 API 开发期或不可达 → P0 先用国内栈验证管线，生产按 region 配置翻转（适配器已隔离，切换 = 配置）。

6. 待你拍板的开放决策

  • 路线确认：级联（推荐，复用大脑/省钱）还是端到端（GPT-4o Realtime/Gemini Live，体验上限高但锁厂商、贵 10–40×）？
  • STT 首选型：Deepgram Nova-3（快、抗噪）vs Whisper（自建、隐私）vs Speechmatics（抗口音最强）——语言学习者口音多，建议 Speechmatics/Whisper 保底。
  • TTS 首选型：Cartesia Sonic 2（40ms TTFB，最快）vs ElevenLabs（最自然）vs Azure/Gemini（多语种发音准、便宜）。
  • 是否把 P3 的 build_agent_context 一并返哺文本伴学：建议做，但属于对现有 companion 的小幅重构，需你点头再动。
  • 语言范围：先支持哪门目标语言？影响 STT/TTS 厂商与音色库。
  • 区域路由策略：全球用户 → 按用户所在区域切 STT/TTS 厂商（中国 = 火山 / 阿里，海外 = Deepgram / Cartesia），由 VOICE_REGION 配置驱动；大脑恒定中国主体。
  • 是否持久化语音录音：供跟读回放 / 发音复盘则须走数据出境评估；若 ephemeral 不落盘则合规负担最低。需你定。
