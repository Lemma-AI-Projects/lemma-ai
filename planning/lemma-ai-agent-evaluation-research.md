# Lemma AI — Agent 诚实评估升级·调研计划

> 启动：2026-08-08 · 阶段：**调研期（M1）** · 目标产物：内部盘点 + 外部文献 + 最小升级方案
> 触发：用户提供"自我改进的诚实评级"截图作为评估框架参照 → 把同样的诚实镜头对准我们自己的 agent

## 1. 背景与动机

用户给出一张截图，展示一个 agent 系统的**自我改进诚实评级**——用五个维度去丈量"它真的在学习吗？"：

| 维度 | 截图评级 | 截图备注 |
|---|---|---|
| 自动产出新记忆/技能 | ✅ 有 | background review，无需人工触发 |
| 遗忘/收敛 | ✅ 有 | curator 归档 + 字节预算硬上限 |
| 反馈信号 | ⚠️ 弱 | 只有使用频次/最近使用时间；没有成功率/自评分/reward/错误驱动修正 |
| 闭环性 | ⚠️ 半闭环 | 产出 → 使用计数 → 生命周期流转；技能质量从不被动评估 |
| 本质 | — | LLM 自我总结写文件 + 基于使用频次的垃圾回收 |

截图结论：**介乎 (a)(b) 之间，更偏 (b)**——不是真正的闭环学习（无效果反馈），但确实会自主写文件；唯一"适应性"来自使用频次这一个非常弱的信号。

> 这张图的核心价值不是某个具体框架的名字，而是**评估维度本身**：我们要把同样的诚实镜头对准 Lemma 的 agent，看看到底学到了什么。

### Lemma 当前的 agent 是什么？
- **伴学老师**（C1 人格注入，已实现，提交 16a71dc）：learn space 对话里 AI 以 TA 的名字/性格/教法开口
- 引擎底座：Hermes learner 五层（identity / knowledge / patterns / episodes / meta_rules）+ AIClient 5 mixin + 遥测通道
- 已有：遥测（TTFT / fallback / degraded）+ 对话历史落库 + usage log + provider_usage_log

### 这次升级的意图
把 Lemma 的 agent 从"能开口、有记忆框架"升级到"**真的在学、并且能被衡量学到了什么**"——但必须诚实，不能演变成 LLM 自评打分那种表演。

## 2. 调研总目标

回答三个核心问题：

1. **现状**：Lemma 的 agent 今天的"记忆/技能/反馈/闭环/本质"分别对应截图的哪个评级？为什么？
2. **缺口**：从"半闭环/偏 (b)"到"真闭环"缺哪一环？优先补什么？
3. **最小方案**：先选哪一个维度做第一次升级？升级后用户视角能看到什么变化？

## 3. 调研范围（基于截图五维度）

### 维度 A：自动产出新记忆/技能
- 内部：现在有没有 background review / 自动总结 / 自动归纳"可复用的教法"？
- 对照：截图 ✅（background review）；我们 ❓

### 维度 B：遗忘/收敛
- 内部：Hermes 五层里有 episodes / meta_rules；有没有 curator / 字节预算硬上限？
- 对照：截图 ✅（curator + 字节预算）；我们 ❓

### 维度 C：反馈信号（最关键）
- 内部：现有信号只有 usage（use_count / last_used）+ 遥测（TTFT / fallback / degraded）；有没有成功率/用户反馈/教学效果？
- 候选信号源：
  - **显式反馈**：用户在对话里给 👍/👎 或"这讲得不对"（产品功能）
  - **隐式信号**：用户重问 / 跳过 / 退出对话 / 切到课程（行为）
  - **教学进展**：learner 知识状态变化（BKT/IRT 概率提升）
  - **模型自检**：另一 LLM 对本轮对话质量评分（Constitutional AI 思路）
- 对照：截图 ⚠️（只有使用频次）；我们需要：至少 2 个独立信号源 + 不全靠 LLM 自评

### 维度 D：闭环性
- 内部：从对话 → 落库 → usage → 生命周期流转 有链路吗？信号有没有回写到 agent 的下次行为？
- 对照：截图 ⚠️（半闭环，质量不被评估）；我们 ❓

### 维度 E：本质
- 内部：我们到底是 LLM 自我总结 + 频次回收？还是基于教学效果证据的真正闭环？
- 这是定性判断——调研产出里要给出诚实答案，不能粉饰。

## 6. 红线（约束）

- **诚实 > 体面**：调研产出必须敢写"偏 (b)"，不能粉饰；MVP 上线后若发现仍是半闭环，必须再迭代，不能用"已经努力了"自欺。
- **不自评打分**：不能拿另一个 LLM 给对话质量打 5 星当主信号——这是截图的本质问题，我们不能重复。
- **不绑架用户**：任何"显式反馈"机制必须是可选、轻量、可关闭；不能给每条消息加弹窗要评分。
- **不破坏体验**：信号采集必须 fail-open、不增加 latency、不降低对话质量。
- **门控 + 可回滚**：MVP 必带 `evaluation_v2_enabled` 之类门控，关闭即降级到旧链路。
- **隐私与合规**：反思 / 评分使用的对话内容必须遵守现有 Supabase Auth + 不向境内公众提供的合规底线（参见 `lemma-ai-commercialization-legal-engineering-plan.md`）。

## 7. 与已有方向的衔接

- **C1 注入**（已落地）：评估反馈应该能回写到 agent 人格——但**只在用户主动表达同意之后**（不能默默改 TA 的性格）。
- **Onboarding 画像**（已落地）：onboarding_interests 可作为评估"是否真的因材施教"的初始基线。
- **Hermes learner 五层**（已合并）：评估信号应能写回 identity / knowledge / patterns / episodes 哪一层？还是另起一层？这是 M1 要回答的。
- **遥测通道**（已落地）：evaluator 信号能复用同一通道，但要避免混淆 usage 指标与教学效果指标。
