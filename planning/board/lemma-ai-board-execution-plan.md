## 阶段 0 · 底座验证（⚪ 内部工程，理由：铺路 + 消最大技术风险）

| 任务 | 内容 | 验收 |
|---|---|---|
| E0.1 ✅ 装依赖 + 最小画布 | 前端装 tldraw v5.3；`/board-demo` 路由渲染最小无限画布 | 08-06 完成：类型 + 全量 build 通过 |
| E0.2 ✅ 自定义 shape 原型 | tldraw v5 API 实现 KnowledgeCard（文本+KaTeX）与 ConceptNode（掌握度三态） | 08-06 完成：类型 + build 通过 |
| E0.3 ✅ 快照存取 | getSnapshot/loadSnapshot → localStorage，刷新自动恢复 | 08-06 完成：类型 + build 通过 |
| E0.4 binding 原型 | tldraw binding 系统实现 SemanticLink 语义连线：节点移动连线跟随 | 待做（差异化核心） |

> v5 API 关键结论（08-06 踩坑记录）：自定义 shape 类型 = `TLBaseShape<'type', Props>`；必须 `declare module '@tldraw/tlschema'` augment `TLGlobalShapePropsMap` 才能满足 BaseBoxShapeUtil 泛型约束；props 为普通对象映射（含 w/h）；指示线用 `getIndicatorPath` 返回 Path2D（无 indicator JSX）；快照用 `getSnapshot/loadSnapshot`。文件必须 .tsx（含 JSX）。

> 理由（⚪ 必须写明）：Board 差异化核心 = 知识卡片 + 语义连线 + AI 沉淀，三者依赖 tldraw 的 shape/binding/createShape 能力——E0.2/E0.4 是**全项目最大技术风险的验证点**，不过闸一切免谈。

## 依赖与顺序

```
E0（底座验证）→ E1（容器）→ E2（沉淀闭环）→ E3（开放架构）→ E4（增强）
```

- E0.2 是全局闸门：Excalidraw 自定义元素能力不过关 → 停下回到研发计划重选底座
- E1 与 E2 可部分并行（E2.1 可在 E1.3 表建好后先行开发）

## 风险表

| 风险 | 等级 | 对策 |
|---|---|---|
| tldraw shape/binding API 能力不达预期 | 高（E0.2/E0.4 闸） | 先跑原型验证；不达预期停下重选（自研 subset） |
| tldraw 学习曲线拖慢进度 | 中 | 官方文档 + starter kits 先行；E0.1 先跑通 |
| 前端 node_modules 缺失 | 中 | E0.1 先 npm install，装不上先解决环境 |
| 后端 deps 未装（迁移/测试跑不了） | 中 | E1.3 前先装 deps 或本地验证 |
| 快照 JSONB 膨胀 | 低（v1 单用户） | 卡片结构化 + 定期瘦身，P2 再优化 |

## 开工顺序建议

1. **E0.1 + E0.2**（今天就能动：npm install → 最小画布 → KnowledgeCard 原型）——不依赖任何后端
2. E0.4 binding 验证（差异化核心）→ E0.3 快照存取 → 阶段 1 后端模型
