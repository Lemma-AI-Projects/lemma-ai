Free Course
作为一次学习，
而不只是一门课

这不是一份产品需求文档。它是一次对现有代码的审计，加上一次受约束的发散， 目标是回答一个问题：当 AI 不只是回答问题、 而是真的参与一个人的学习过程时，人和 AI 之间最基本的那个东西是什么。

02 — What Free Course Actually Is

Free Course 现在到底是什么

从代码与真实流程推导，不预设。它比"课程"少，比"聊天"多。

不是

不是"课程 + 聊天"

聊天与课程是两个并列的界面，不是同一个东西的两种表现。 点"切到教学会话"是从一棵树上跳到另一棵树上， 课程进度与会话进度互不读写。

不是

不是"AI 生成课程 + 对话式导师"

它更接近"一次性生成一份大纲 + 一次预录的讲解"。 会话不是对话：模型一次返回整段时间线，之后按句播放。 形状必须符合硬校验，缺一抛 409。

更接近

一份被编译过的学习路径

编译期产物。像一份 build 好的东西： 输入一句话，经过若干次模型调用，产出一个固定形状的树 + 若干固定形状的脚本。 学习者在这个产物上按顺序消费， 他的行为不参与这个产物的形状，只被记在旁边。

由 :283-344 / :347-476 / planner.py:117 三处共同支持
最接近的隐含结构

它在结构上已经暗示了 adaptation，
但把它关在了门外

learner_state 进了 prompt；observed_attempts 进了 prompt；confused 能改变讲解。 所有零件都在，没有一个能改变下一步该走哪。

✓ 一句话结论

Free Course 是一个学习内容的编译器，它缺一个运行时。 编译产物（大纲、讲解脚本）是真实的、可用的；缺的是"根据学习者此刻的状态 重新决定下一条指令"的那一层 —— 而那一层在代码里只有一个 5 字段的数据类和一个 COUNT(*)。

前三项（内容、组织、路径）是 AI 做得多好的问题 —— 它们随模型能力增长。

Free Course 今天把全部工程投入放在前 3 项，而后 5 项是空的。 这不是优先级排错了，是因为前 3 项看起来像产品，后 5 项看起来像抽象。

05 — Design Space

十一个视角的发散

每个视角都推到底，不是提三个点子就收。右侧是它对今天这个产品的判决。

01Course as Content 存疑

主张：如果它本质是内容组织系统，那它应该像 Wikipedia 或 Khan 那样强：一条路径、清晰层级、可以跳读、内容质量高、随时回来接着看。

推到底：内容层的完备度其实不低 —— 6 次模型调用产出带 objective / blueprint / 四类对象的树，还带难度标签。缺的是可跳读 （只能顺序）与内容复用（不能「从某一节开始」）。

但是：这条路的天花板是「更好的内容」，而内容质量这件事 完全被模型能力绑定 —— 我们做不出比模型更好的内容， 它不会产生 Lemma 独有的东西。

判决：内容是入场券不是护城河。值得做，但不值得作为主方向。

02Course as Interaction 值得

主张：课程不是内容，而是一组持续发生的交互。 若如此，unit/chapter 这棵树应该消失，课程 = 一条交互的轨迹。

推到底：这其实最接近白板课现在的形态 —— 它是唯一真的「在发生」的部分（按步、按句、随回答延伸）， 而课内练习部分是静态内容带一个提交框。 系统里已经有一个 Course as Interaction 了，只是它没有名字、没有入口、也不被记录。

关键代价：轨迹没有树，就没有「你走到哪了」的天然表示。 今天的 cursor 解决的是「播到哪」，不是「走到哪」—— 而这正是缺口 3。

判决：这是最可能成为 Lemma 独有 interaction pattern 的方向。 理由：它是唯一一个「模型必须在过程中决策，而不是一次生成」的形态， 而今天的模型调用预算已经允许（每轮 1 次追加）。

03Course as Experiment 值得

主张：每节课是一个 learning experiment —— 有假设、有干预、有观测。 AI 设计的不是「内容」，是「这次要验证他会不会 X」。

推到底：这与「观察用户」「调整难度」两个缺口是同一件事的三种说法。 而今天有一个现成的实验记录：transcript （代码自认「学习者真实经历的忠实记录，包括他后来要求重讲的部分」）。 它现在只被写、不被读。把 transcript 当作「这次实验的观测记录」来读， 是改动最小而认知收益最大的一步。

我自己的反对意见：如果「实验」没有明确的假设与判定， 它就只是「教学」的漂亮说法。所以这个视角必须落到一个具体 primitive 上 —— 而它落在 Attempt 上（见 §7）。

判决：值得，但它是 Attempt 的论证方式，不是独立方向。

04Course as Game 今天别做

主张：课程不是章节，是 challenge → attempt → feedback → next challenge。

推到底：结构上这是对的，也是 §8 的 Pipeline B。 但「游戏」的实现里有 80% 是反馈延迟、连胜、失败可视化 —— 那些是动机工程，需要几十次真实用户调试，而 它不产生任何关于「AI 怎么教」的知识。

关键判断：我们现在的核心问题不是「用户不想回来」， 是「系统不知道他会不会」。给一个不知道状态的系统加连胜动画，是给诊断做化妆。

判决：结构在 Pipeline B 里吸收，游戏化今天别做。 把有限的注意力放在「读 transcript」上更值。

05Course as Dialogue 存疑

主张：课程本质是长期苏格拉底式对话。Course Structure 还需要存在吗？ 答案：不需要。

推到底：那产品就变成「一个知道很多的人」， 和 /chat 的区别只是它有板书和语音。这有价值 —— 但它让 Free Course 失去了「来学一个东西」的入口感， 而这恰恰是浅用户的心理门槛：「我要学 X」比「我要聊聊」更容易点进去。

更硬的反对：纯对话没有「完成」的自然表示。 Learn Space 那边有 method_episodes，因为「一段」有起点有判据； 纯对话里没有。所以这条路最后会退化成「有声音的 chat」， 而 Lemma 已经有一个更好的 chat。

判决：取其局部（苏格拉底式提问），弃其整体（取消课程结构）。

06Course as Simulation 存疑

主张：学习不是读知识，而是在环境中 act → observe → reason → adapt。

推到底：这是最强的理论主张，也是最难的一个。 今天最接近的资产是白板 —— 它是可操作的画布， awaitClick 已经在等学习者点它。这已是模拟的雏形， 但只走了「act」的一半：点对/点错的后果没有被建模， 白板不会因为他的操作而改变。

关键冲突（值得记住）：模拟需要「环境状态」， 而今天的白板是一次生成、只增不改 （steps 只 extend 不 splice，因为 transcript 必须是「忠实记录」）。 这两条要求在数据结构上直接冲突 —— 而这个冲突本身就是一个发现： 它说明「忠实记录」和「可交互环境」是两种不同的历史。

判决：与 02 是同一方向，难度更高。 先做 Interaction，模拟是它的自然延伸。

07Course as Assessment 值得

主张：AI 首先不是教，而是不断寻找「这个人到底会不会」。 课程是评估的载体，不是内容的载体。

推到底：这是缺口 1（观察）最锐利的表述， 而且它有一个现实优势：它不需要新的表。 course_lesson_observations 已经有 verdict， 只是从来没有人把多次 verdict 连起来读。

最硬的约束：现有动作几乎全是回忆型（§C）， 而回忆题无法区分「会」「猜」「刚看过」。 所以这个视角逼出一个具体要求：题目必须能区分「记住了」与「懂了」 —— 而那正需要 §C 里缺的那几类动作。

判决：值得，且与 03 是同一件事的两种说法。 真正缺的不是「评估」，是「评估的题目能区分『对』与『会』」。

08Course as Cognitive Intervention 值得

主张：Course 不是传递知识，而是在不同时间对用户施加不同的 cognitive interventions。

推到底：这是 Learn Space 的 Method 已经建成的东西 —— 四要素（适用条件 / 要他做的 / 我不做的 / 观察什么）+ 一条完成判据。 Free Course 缺的不是这个概念，是这个结构的一个具体实现。

但有一个重要区别：Learn Space 的 Method 作用于知识结构。 Free Course 面对的是一个还没建立的知识点， 学习者对它连名字都没有。所以同一个四要素在这里会退化成两格 —— 「适用条件」是「他刚学会了什么」，「完成判据」是「他能不能不靠提示做出来」。

判决：值得，但不要把 Learn Space 的 Method 直接搬过来 —— 那会让 Free Course 依赖 Learn Space，而它必须能独立。

09Course as Creation 值得

主张：学习最终不是「完成课程」，而是创造某个东西。 学习 → 创作 → 遇到问题 → 学习 → 修改 → 再创作。

推到底：这是唯一一个天然产出「转移」证据的形态， 而转移（§C 缺的那一列）是唯一能说明「他真的会了」的动作。 它还有一个别的方向没有的性质：创作会暴露他自己的知识缺口， 而那个缺口是他自己发现的，不是系统猜的 —— 所以它是 07（Assessment）最诚实的形式。

最硬的约束：浅用户没有东西想做。 一个只想花 3 分钟试试的人，不会想「我要做一个东西」。 所以这条不能作为主入口，只能作为有耐心用户的深处。

判决：值得，但它的入口门槛决定了它救不了浅用户。 它是「30 分钟以上」那一档的答案。

10Course as Exploration 值得

主张：用户根本不知道自己想学什么。 Free Course 应该从「我要学 X」变成「让我探索 X」。

推到底：这与 Free Course 的产品定位最吻合 —— 它是第一次接触 Lemma 的地方，而「随便试一个课程」正是真实用户行为。 今天的入口要求用户先描述想学什么， 而首页那 4 个「随便试试」chip 是没有 onClick 的装饰。

实现上的关键：探索不需要新的数据结构 —— 它需要的是「不要求先有目标」也能开始， 而这正好是 §8 Pipeline D 要解决的事。 这是一个被装饰品承诺过、但从未实现的能力。

判决：最可能立刻见效的一个方向， 因为它不需要新表、不需要迁移，只需要一个入口。

11Course as Agentic Environment 今天别做

主张：AI 不只是 Tutor，而是 Designer + Tutor + Examiner + Critic + Coach。 先研究角色，而不是设计 Multi-Agent。

角色今天对应什么缺什么
Designer✓ map / blueprint 阶段不知道学习者，设计不出「为他」的东西
Tutor✓ 白板讲解只有一种教法，重讲是唯一变化
Examiner△ 只判这一次不出题，只判已给出的题
Critic✗ 不存在没有任何东西反驳学习者
Coach✗ 不存在没有任何东西主动改变策略

关键判断：Examiner 与 Critic 值得作为角色存在， 而 Designer / Tutor / Coach 今天就够 —— 不需要拆成多个 Agent。 拆成多 Agent 会把「谁决定下一步」变成 Agent 间通信问题， 而它现在是一个数据结构问题（缺口 3）。 用架构掩盖数据结构缺口，是最贵的一种修法。

判决：今天别做 Multi-Agent。 把 Examiner 补成「出题 + 判 + 记」的完整角色，用现在的单 Agent 形态就够 —— 而且那正是 §7 的 Attempt。

06 — Cross-domain Inspirations

跨领域：不是竞品清单，是 interaction loop

每个系统只问两个问题：它的 loop 是什么 · 它靠什么让人继续。然后问：那个 loop 的哪一段我们缺。

系统它的 interaction loop它靠什么持续我们缺的那一段
Duolingo 题 → 答 → 即时反馈 → 下一题 连胜与进度条（动机） 我们缺的不是连胜，是「答完之后系统该干什么」
ALEKS 诊断 → 定弱点 → 出针对性题 → 掌握 「它知道我在哪」 最接近我们要的 loop。而它的核心资产是那张知识点掌握表 —— 正是缺口 1
Brilliant 概念 → 交互式演示 → 你动手 → 概念成立 「我刚才亲手看到它动了」 我们有白板，但点对错没有后果（§06 的冲突）
Wikipedia 搜索 → 跳转 → 跳转 → 停在某处 可跳读（不需要按顺序） 我们只能顺序 —— 而这让「只学 3 分钟」变成不可能
GitHub 读 → 改 → 跑 → 失败 → 读 diff 反馈是即时的、具体的、不可争辩的 我们的反馈是「一句话评价」；反馈的粒度决定了学习能不能发生
Interactive fiction 选择 → 世界改变 → 新状态 → 新选择 选择的后果被记住了 我们的 transcript 记了选择，但不读它
Socratic dialogue 提问 → 回答 → 指出回答里的漏洞 → 追问 对话本身的张力 我们缺 Critic —— 没有任何东西反驳他
Scientific experiment 假设 → 实验 → 观测 → 假设错了 → 改假设 失败的实验也是有信息量的 这是 §03 的原型。我们连「这次假设是什么」都没记
Apprenticeship 看师傅做 → 模仿做 → 做砸了 → 师傅纠正 → 再做 「做砸」是学习的关键一步，且被允许 我们的练习答错后永久 disabled，没有重试
Coaching 目标 → 现状 → 差距 → 下一步 → 再评估 承诺 + 反馈回路 Learn Space 的 method_episodes 已建，Free Course 没有
Language learning 输入 → 强制输出 → 即时纠错 → 重复 「用出来才算」 我们有强制输出，但重复的是回忆不是使用
Reddit / 评论 发帖 → 陌生人回帖 → 楼主再回 被真实的人看见 与学习无关，但它提醒我们一件事：反馈若来自模型，就不是反馈

三个反复出现的模式

跨了 12 个系统，有三件事每次都在同一个位置出现：

  1. 系统必须先知道「他会不会」，才谈得上教什么。 ALEKS 的掌握表、scientific experiment 的假设、coaching 的现状评估、 apprenticeship 的「做砸了」—— 全部要求一个关于学习者的事实， 而不是一个 COUNT。
  2. 「做砸」必须被允许且有信息量。 Apprenticeship 明确说「做砸是学习的关键一步」， 交互小说的 loop 建立在「选择有后果」上。 我们的练习答错即永久 disabled —— 那不是防作弊， 那是把「做砸」这个步骤从产品里删掉了。
  3. 反馈的粒度决定学习能不能发生。 GitHub 的反馈是「这个 diff 跑挂了，栈在这里」—— 具体、即时、不可争辩。我们的反馈是「一句话评价」， 而它产自一个不知道他会不会的模型。

三条都指向同一处：缺的不是内容，也不是交互丰富度， 是「系统对他有一个事实」。

为什么 Attempt 而不是 Evidence。 Evidence 是 Learn Space 的核心概念，Free Course 不该复制它 —— 那会让它依赖 Learn Space，而它必须能独立。 两者形态其实不同：Evidence 问「他会不会」， Attempt 问「他做了什么」。 在 Free Course 里，只有 Attempt 是有现成数据源的 （observation + transcript 已经在那儿）， 而 Evidence 需要一个我们今天没有的知识结构。

为什么 transcript 的「读法」算一个 primitive。 因为它不需要任何新数据。今天 transcript 是死的， 不是因为缺字段，是因为没有人把它当观测记录来读。 这是改动最小、认知收益最大的一步 —— 它也是唯一一个当天就能做、且不需要定任何 schema 的实验。

为什么 Stall 是派生的。 它不是新记录，而是「Attempt 序列上的一个性质」： 同一处连续未达成 N 次。 把它单列成一个 primitive 是错的 —— 那会让它看起来需要一个表，而它只需要一个查询。

他第二次来，同一主题 ✗ 系统无感知 最可靠的信号，但系统今天不知道他来过。要它就得先有 Attempt

他点了「我没懂」 ✓ 存在且有效 唯一一个已经工作的转化信号。它证明系统有能力响应 —— 只是只有这一个信号
他做对了带提示的题 ✗ 不记帮助 免费课程没有 hint_used，所以带提示的成功与独立成功不可区分 —— 而 Learn Space 那边已经把这件事解决了
他中途离开又回来 △ 会话有，课程不感 cursor 恢复是真的，但它恢复的是播放位置。
他改了目标 △ 问卷在建课前 问卷存在且有 4 个维度，但它只用了 1 次 —— 建课之后没有任何机制再听到「我想换个方向」
⟡ 我的判断

真正的转化点不是「他回来了」，是「他做了第二件事」 —— 任何一件系统能记录、他不会自动重复的事：再答一题、换一个分支、 说一句自己的话、点一次「我没懂」。

而这四条今天只有一条有响应（点「我没懂」）。 其余三条都被记录了但没人读。 所以「浅 → 深」今天不是一条转化路径的缺失 —— 是四个信号里三个接错了线。

10 — Free Course ↔ Learn Space

哪些能力留在 Free Course，哪些未来可能被抽走，哪些现在绝对不要抽象

前提不重复：Free Course 作为一个相对独立的 AI Learning Experience， 被允许保持独立，而且目前是有价值的。 下面讲的不是「怎么合并」，是哪些东西的形态会碰巧一样。

应该留在 Free Course 内部

课程的生成与树

unit / chapter / lesson object 这套结构， 以及 6 次模型调用的生成管线。 它的节奏是「一次投入、长期消费」， 而 Learn Space 的知识结构是「长期演化、每次一点」—— 两种节奏不该共用一个结构。

白板

它是「一次讲解」的工具：画布、动作、按句播放、语音。 Learn Space 的 Focus 模式有自己的呈现（文档块 + 三面状态栏）， 两者不是同一种东西，不该被统一。

会话的连续性

cursor 落库、刷新恢复、只增不改的 transcript。 这是整套代码里做得最扎实的一块， 而且它服务的是「一次讲解的连贯性」， Learn Space 有完全不同的连续性需求（跨课、跨天、跨空间）。

生成期的一次性参数

问卷 / tuning 是一次生成的参数，不是长期状态。 它们的价值恰恰在于「过期」—— 生成完就该被忘掉。 把它抽成长期偏好会毁掉它。

未来可能值得抽象到 Learn Space（候选，不是承诺）

Attempt 的记录格式

Free Course 记的是「选了一个 option」， Learn Space 记的是「独立且未受帮助地做对」。 两者是同一个东西的两种精度， 格式统一之后 Free Course 才能说「他已经在别处学过了」。

Commitment 与判据

Learn Space 已经有 method_episodes： 一段承诺 + 一条可核对的判据 + 五个出口。 Free Course 缺的是同构物。但顺序必须是 Free Course 先有， 再考虑是否收敛 —— 现在反过来做会是错的。

Stall 的判定

「同一处连续顶不破 N 次」在两个场景里是同一个计算。 但 N 的默认值应该各自不同 （Learn Space 有跨课的连续性，Free Course 往往只有一次课）—— 所以抽象的应该是机制，不是数值。

⚠️ 三个绝对不要抽象的东西（现在）

① 课程树与知识结构。unit/chapter 是「教学顺序」， 知识结构是「依赖关系」。它们形状相似、用途相反 —— 强行统一会让 Learn Space 的结构退化成一条链。

② 白板 / 教具。它是讲解的工具，不是学习状态的载体。 Learn Space 的 Focus 有自己的形式，且那是有意的。

③ 判分与掌握度。Free Course 的「对」是回忆型判定， Learn Space 的「会」是独立判定。 在 Free Course 有了 hint_used 与非回忆题之前， 抽象这一层等于把「猜对了」污染进「掌握了」。

关于「Free Course → Learn Space 是漏斗」这个说法

我核了一遍代码，找不到支持它的机制，也找不到反对它的机制 —— 因为 Free Course 与 Learn Space 之间今天没有任何数据通路。 判分不互通、知识结构不互通、掌握状态不互通。

所以这不是一条浅→深的漏斗，而是两个各自完整的产品， 共享同一个品牌与同一个模型。这本身没问题。

而我认为唯一真实的连接点是： 如果 Free Course 里某个学习者反复在同一个概念上卡住， 而 Learn Space 恰好有那个概念的知识结构 —— 那时才谈得上「他需要更长的路」。 而这个连接点今天连不上，因为没有 Attempt 记录。

11 — Convergence

收敛：八个问题

Q1

当前最核心的问题是什么？

系统对他没有一个事实。 不是内容不够、不是交互不够，而是：他做过什么、会不会、卡在哪 —— 全部落在一个 COUNT(*) 上。 而整条链路的 5 个决策职责（观察 / 调难度 / 何时继续 / 何时换法 / 何时结束）全部为空。

Q2

最大的结构性缺陷是什么？

学习是一个「读取」过程，只是被读的那份数据从来没有被写。 learner_state 有完整接口、 transcript 有忠实记录、 observation 有 verdict —— 三个容器都在，零个读它们的地方。

Q3

哪些东西不应该改？

① 课程树与生成管线——它对「学完一个东西」仍然合理， 该做的是加一条短路而不是重写它。
② 白板与它的形状硬校验——出头的约束是有价值的， 该改的是从配额变判断，不是取消。
③ 会话的 cursor 与只增不改——那是对的， 而且它是 §06（模拟）唯一还站得住的那条数据结构原则。

Q4

哪些东西值得实验？

按「改动小 / 认知收益大」排序： 读 transcript（0 新表）· hint_used 接到 Free Course（1 列，Learn Space 已解决）· 非回忆题（能让"对"与"会"分开）· 3 分钟入口（一个装饰品已经承诺过的能力）· Stall 计数（先记不判）。

Q5

哪些 primitive 最值得验证？

Attempt（承重）· transcript 的读法（即时）· Stall（派生，不单列）。
明确不推荐 Mastery —— 在 Attempt 之前做它是 在没刻度的尺子上画刻度。

Q6

哪些方向漂亮但没价值？

① 游戏化——给一个不知道状态的系统加连胜动画。
② Multi-Agent——用架构掩盖数据结构缺口。
③ 掌握度 / KST——前置条件还没满足。
④ 「更好的内容」——天花板是模型能力，不是我们。

Q7

哪些可能成为 Lemma 独有的 pattern？

「白板 + 强制输出 + 逐步撤除帮助」这个组合。 它需要三样同时成立：可操作的教具、可判定的动作、有帮助程度的事实。 前两样今天有，第三样是 Free Course 唯一完全缺的那一样 —— 而 Learn Space 已经把它建好了。
跨两个产品拼出一个 interaction pattern，这可能是最值得投的一件事。

Q8

Free Course 与 Learn Space 什么关系？

今天：两个各自完整、零数据通路的产品，共享品牌与模型。 这没问题。
唯一真实的连接点是「他反复在同一个概念上卡住， 而别处有那个概念的结构」 —— 而它今天连不上，因为没有 Attempt。
留：课程树 · 白板 · 会话连续性 · 生成期参数。 可能抽：Attempt 格式 · Commitment · Stall 机制。 绝不现在抽：课程树 · 白板 · 判分与掌握度。

✓ 一句话收束

Free Course 已经把「把知识变成结构」这件事做得比大多数人好； 它欠的不是结构，是「读回自己做过什么」的那一读。

而那一读需要的不是新表、不是新架构、不是新 Agent —— 它需要 hint_used、非回忆题，以及 把 transcript 从一份存档变成一次观测。

12 — Experiments

三个实验：它们能告诉我们什么

不是「实现这个功能」。每个实验都写清它能回答什么问题， 以及什么结果会推翻它。

EXPERIMENT 01

让 transcript 被读一次

在教学会话的下一轮开始时，把已发生的 transcript 读成一段「他在这段里表现如何」， 并据此决定这次先讲什么。 不写任何新表、不加任何字段 —— 只加一个 reader。

HYPOTHESIS会话 transcript 里已经含有足够的信号 （点了哪次、答了什么、什么时候说不懂），只是没人读。
WHAT CHANGES会话第二轮的讲解起点。 以及「先讲什么」从固定变成被 transcript 影响。
WHAT STAYS课表、树、白板、形状硬校验、 cursor 与恢复逻辑，全部不动。
EXPECTED USER BEHAVIOR不明显。 用户可能根本注意不到变化 —— 这是这个实验的特色，不是缺陷。
WHAT WE LEARNtranscript 里的信号够不够。 这是唯一能回答「数据已在那儿，只是没被读」这句话的真伪的实验。
WHAT WOULD FALSIFY 加上 reader 之后，讲解的差异在 transcript 只有 1–2 轮时不可观察 （数据太少，读不出差别）⇒ 说明 transcript 不是「没被读」，而是「里面东西不够」， 那么 primitive 02 就不是最有价值的那一个，下一步要换。
EXPERIMENT 02

把「我帮过忙」记进 Free Course

Free Course 的练习与白板课增加 hint_used， 并且允许带提示的答对被记为「还不算」。 Learn Space 那边已经建好了整条链路 （knowledge_evidence.hint_used 列 + 契约 + 领域对象 + 核心规则 state.py:291），Free Course 这边是零。

HYPOTHESIS今天的「答对」里混着大量「被扶着走完」， 而 Free Course 完全没有办法区分它们。
WHAT CHANGES「这一题算不算他学会了」的判定。 这是首次让「对」与「会」在 Free Course 里成为两件事。
WHAT STAYS树、白板、生成管线、进度算法全部不动。
EXPECTED USER BEHAVIOR提示会撤得更快 —— 因为系统第一次知道哪些成功是被帮助出来的。
WHAT WE LEARN带提示的答对到底占多少。 这个比例是一个我们今天完全不知道、且无法估算的数字。
WHAT WOULD FALSIFY 实测带提示比例低于 5% ⇒ 这条线索在 Free Course 里不成立， 那「撤除帮助」的设计要另找依据（而 5% 这个阈值是我拍的，可以调）。
EXPERIMENT 03

3 分钟 playable：一个不需要描述的入口

首页那 4 个「随便试试」chip 现在没有 onClick —— 它们承诺过一个从未实现的能力。给它接上一个不需要先描述、 30 秒内给出第一次尝试的入口。

HYPOTHESIS「先描述想学什么」是浅用户的最大流失点， 而它今天是强制的（默认分段是 chat，且表单要求描述）。
WHAT CHANGES只有入口。 不生成完整课程 —— 一次尝试 + 一次诊断 + 一次针对性干预（Pipeline D 的第一段）。
WHAT STAYS全部生成管线、树、白板、Learn Space。 这是加法不是改法。
EXPECTED USER BEHAVIOR首页→第一次尝试的转化上升。 而「有多少人走完第一次尝试后要第二次」比「多少人点了」更重要。
WHAT WE LEARN浅用户是被门槛挡住的， 还是被结果挡住的（点进来了但不好玩）。 这两种原因要分开测量，而后者的解法完全不同。
WHAT WOULD FALSIFY 接上入口之后，第二次尝试的转化率没有变化（只是多了些点一次就走的人） ⇒ 门槛不是瓶颈，第一次体验的质量才是， 那么这个实验的价值变成了「一个干净的测量基线」， 而主攻方向要转向 Experiment 01/02。
⟡ 为什么是这三个，顺序也是刻意的

01 最便宜（零新表，最快能出结论）· 02 最尖锐（它回答一个我们完全不知道的数字）· 03 最重要（它决定用户会不会进门）。

01 和 02 是认知实验 —— 它们回答"我们知不知道自己在做什么"。 03 是产品实验 —— 它回答"别人知不知道"。

而 03 最可能第一个做，因为它最便宜、且今天已经有一个承诺过它的死 chip。 但它也是三个里最可能证伪我们自己的 —— 那正是它值得做的原因。

研究方法： 代码审计（后端 3,088 行 Free Course 代码 + 前端全链路）· 11 个视角的发散 · 12 个跨领域系统的 loop 对照 · 6 个 pipeline 的七维比较 · 三条断头链的亲自核实。

本报告不做什么： 不改 Free Course · 不设计新架构 · 不提 Multi-Agent · 不接 Learn Space · 不假设任何理论是正确答案。
